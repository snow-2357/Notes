# Interfaces vs. Abstract Classes

In Java, both abstract classes and interfaces are used to achieve abstraction. However, they serve different purposes and have different capabilities.

---

## 1. Abstract Classes

An abstract class is a class that is declared with the `abstract` keyword. It cannot be instantiated.

- **Purpose**: To provide a common base for subclasses to extend.
- **Features**:
  - Can have both abstract methods (no body) and concrete methods (with body).
  - Can have member variables (instance fields).
  - Can have constructors.
  - A class can extend only **one** abstract class.

```java
abstract class Vehicle {
    int speed;
    Vehicle() { System.out.println("Vehicle created"); }
    
    abstract void move(); // Abstract method
    
    void stop() { System.out.println("Stopping..."); } // Concrete method
}
```

---

## 2. Interfaces

An interface is a blueprint of a class. It contains only constants and abstract methods (prior to Java 8).

- **Purpose**: To define a contract that implementing classes must follow.
- **Features**:
  - All methods are implicitly `public` and `abstract` (before Java 8).
  - All variables are implicitly `public`, `static`, and `final`.
  - A class can implement **multiple** interfaces.
  - Since Java 8, interfaces can have `default` and `static` methods.

```java
interface Flyable {
    void fly(); // Abstract by default
    
    default void log() { // Java 8 default method
        System.out.println("Logging flight...");
    }
}
```

---

## 3. Key Differences

| Feature | Abstract Class | Interface |
| :--- | :--- | :--- |
| **Inheritance** | Use `extends`. Single inheritance only. | Use `implements`. Multiple inheritance allowed. |
| **Methods** | Can have abstract and concrete methods. | Mostly abstract (until Java 8). |
| **Variables** | Can have final, non-final, static, and non-static. | Only constants (`public static final`). |
| **Constructor** | Can have constructors. | Cannot have constructors. |
| **Access Modifiers** | Can have any access modifier. | Everything is `public` by default. |

---

## 4. When to Use Which?

- **Use an Abstract Class when**:
  - You want to share code among several closely related classes.
  - You need to declare non-static or non-final fields.
  - You want to define common state or behavior (with constructors).

- **Use an Interface when**:
  - You want to define a contract for what a class should do, but not how it should do it.
  - You need multiple inheritance of type.
  - You want to provide common functionality to unrelated classes (e.g., `Comparable`, `Serializable`).

---

## 5. Modern Java (Java 8+)

Java 8 introduced **default methods** to interfaces, allowing developers to add new functionality to interfaces without breaking existing implementations.

```java
interface Payment {
    void process();
    default void refund() {
        System.out.println("Processing refund...");
    }
}
```
This narrowed the gap between abstract classes and interfaces, but the fundamental difference remains: interfaces define "behavioral contracts", while abstract classes define "identity and state".
