# CompletableFuture for Async Programming in Java

`CompletableFuture`, introduced in Java 8, is a powerful tool for asynchronous programming. It implements the `Future` and `CompletionStage` interfaces, providing a flexible and expressive way to write non-blocking code.

---

## 1. Why `CompletableFuture`?

While `Future` provides a basic way to represent an asynchronous computation, it has several limitations:
- **Blocking `get()`**: To retrieve the result, you often have to block the current thread.
- **No Callbacks**: You cannot attach a callback function to a `Future` to be executed when the task finishes.
- **No Chaining**: You cannot easily chain multiple asynchronous tasks together.
- **No Error Handling**: It doesn't provide built-in mechanisms for handling exceptions within the asynchronous task.

`CompletableFuture` addresses all these limitations.

---

## 2. Creating a `CompletableFuture`

- **`runAsync(Runnable)`**: Executes a task asynchronously and doesn't return a value.
- **`supplyAsync(Supplier)`**: Executes a task asynchronously and returns a value.

Both methods optionally accept an `Executor` to run the task in a specific thread pool. By default, they use the `ForkJoinPool.commonPool()`.

```java
import java.util.concurrent.*;

CompletableFuture<String> future = CompletableFuture.supplyAsync(() -> {
    // some heavy logic
    return "Result from Async task";
});
```

---

## 3. Transformation and Chaining (Callbacks)

These methods allow you to define what should happen when a `CompletableFuture` finishes.

- **`thenApply(Function)`**: Transforms the result of the previous stage and returns a new `CompletableFuture`. (Synchronous)
- **`thenAccept(Consumer)`**: Consumes the result of the previous stage and returns `CompletableFuture<Void>`.
- **`thenRun(Runnable)`**: Runs a piece of code after the previous stage finishes, but doesn't have access to its result.

```java
CompletableFuture<String> resultFuture = future.thenApply(s -> s + " - Transformed")
                                             .thenApply(String::toUpperCase);

resultFuture.thenAccept(System.out::println); // Output: RESULT FROM ASYNC TASK - TRANSFORMED
```

---

## 4. Chaining Multiple CompletableFutures

- **`thenCompose(Function)`**: Similar to `flatMap`. Use it when the transformation function itself returns a `CompletableFuture`.
- **`thenCombine(CompletableFuture, BiFunction)`**: Used when you want to combine the results of two independent `CompletableFutures`.

```java
CompletableFuture<String> userFuture = getUserAsync(userId);
CompletableFuture<String> addressFuture = getAddressAsync(userFuture.get()); // BAD: Blocking

// BETTER: Use thenCompose for sequential dependencies
CompletableFuture<String> addressFutureCompose = userFuture.thenCompose(user -> getAddressAsync(user));

// BETTER: Use thenCombine for independent tasks
CompletableFuture<String> combinedFuture = userFuture.thenCombine(addressFuture, (user, address) -> {
    return user + " lives at " + address;
});
```

---

## 5. Waiting for Multiple Tasks

- **`allOf(CompletableFuture...)`**: Returns a new `CompletableFuture` that is completed when all of the given `CompletableFutures` complete.
- **`anyOf(CompletableFuture...)`**: Returns a new `CompletableFuture` that is completed when any of the given `CompletableFutures` complete.

```java
CompletableFuture<Void> allFutures = CompletableFuture.allOf(f1, f2, f3);
allFutures.join(); // Wait for all tasks to finish
```

---

## 6. Exception Handling

`CompletableFuture` provides several ways to handle exceptions within the asynchronous pipeline.

- **`exceptionally(Function)`**: Handles an exception and returns a default value.
- **`handle(BiFunction)`**: Handles both the result and the exception, regardless of whether the task succeeded or failed.

```java
CompletableFuture<String> safeFuture = future.exceptionally(ex -> {
    System.err.println("Task failed: " + ex.getMessage());
    return "Default Value";
});

CompletableFuture<String> handledFuture = future.handle((res, ex) -> {
    if (ex != null) {
        return "Error: " + ex.getMessage();
    }
    return res;
});
```

---

## 7. Async methods vs Sync methods

Most methods in `CompletableFuture` have an `Async` variant (e.g., `thenApplyAsync`).
- **Sync methods**: Usually run in the same thread as the previous stage or the thread that completed the future.
- **Async methods**: Run in a separate thread (either the default common pool or a provided `Executor`).

Use `Async` variants if the callback itself is a heavy operation to avoid blocking the thread pool's workers.
