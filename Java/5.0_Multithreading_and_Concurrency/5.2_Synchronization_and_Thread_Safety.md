# Synchronization and Thread Safety in Java

When multiple threads access shared resources (like a global variable or a shared data structure) simultaneously, there is a possibility of data inconsistency and race conditions. Synchronization is the process of controlling the access of multiple threads to any shared resource.

---

## 1. Race Conditions

A **race condition** occurs when two or more threads can access shared data and try to change it at the same time. The final result depends on the order of execution, which is unpredictable.

```java
class Counter {
    int count = 0;
    // Without synchronization, this can lead to incorrect counts
    public void increment() {
        count++; // This is NOT atomic! It's actually: read, increment, write
    }
}
```

---

## 2. The `synchronized` Keyword

The `synchronized` keyword ensures that only one thread can execute a block of code at a time. It uses a **monitor lock** (also known as an intrinsic lock).

### Synchronized Method
The entire method is locked for the object instance (`this`).

```java
public synchronized void increment() {
    count++;
}
```

### Synchronized Block
You can lock only a specific part of a method for better performance.

```java
public void increment() {
    synchronized(this) {
        count++;
    }
}
```

### Static Synchronization
When a static method is synchronized, the lock is on the `Class` object, not an instance.

```java
public static synchronized void staticIncrement() {
    staticCount++;
}
```

---

## 3. Atomic Variables (`java.util.concurrent.atomic`)

For simple operations like incrementing a counter, `AtomicInteger`, `AtomicLong`, etc., are more efficient than using `synchronized`. They use **Compare-And-Swap (CAS)**, a low-level CPU instruction that is much faster than locks.

```java
import java.util.concurrent.atomic.AtomicInteger;

class Counter {
    AtomicInteger count = new AtomicInteger(0);
    public void increment() {
        count.incrementAndGet(); // Atomic operation
    }
}
```

---

## 4. Volatile Keyword

The `volatile` keyword ensures that a variable is always read from and written to the **main memory**, not from the thread's local cache. This guarantees visibility across threads but **not atomicity**.

```java
class SharedFlag {
    private volatile boolean flag = true; // Visibility is guaranteed

    public void stop() { flag = false; }
    public void work() {
        while(flag) { /* ... */ }
    }
}
```

---

## 5. Thread-Safe Collections

Java provides several thread-safe versions of common collections:
- **`Vector` / `Hashtable`**: Older, legacy collections (don't use for new projects).
- **`Collections.synchronizedList()`**: Wraps a list with synchronized methods.
- **`ConcurrentHashMap`**: Highly efficient, allows concurrent reads and limited concurrent writes. Preferred over `synchronizedMap`.
- **`CopyOnWriteArrayList`**: Good for lists that are frequently read but rarely modified.

---

## 6. Deadlocks

A **Deadlock** is a situation where two or more threads are blocked forever, waiting for each other to release a resource.

### Prevention Strategies:
1.  **Lock Ordering**: Always acquire locks in a consistent order.
2.  **Lock Timeout**: Use `tryLock()` with a timeout instead of waiting indefinitely.
3.  **Minimize Lock Scope**: Keep synchronized blocks as small as possible.

---

## 7. Wait and Notify

Used for inter-thread communication. They must be called inside a `synchronized` block.

- **`wait()`**: Causes the current thread to wait until another thread invokes `notify()` or `notifyAll()` for this object.
- **`notify()`**: Wakes up a single thread that is waiting on this object's monitor.
- **`notifyAll()`**: Wakes up all threads that are waiting on this object's monitor.

```java
// Producer-Consumer pattern example
synchronized(queue) {
    while(queue.isEmpty()) {
        queue.wait(); // Release lock and wait
    }
    // consume item...
    queue.notifyAll(); // Wake up producers
}
```
