# Generics and Type Safety

Generics were introduced in Java 5 to provide compile-time type safety and to eliminate the need for casting.

---

## 1. Why Generics?

Before generics, collections stored `Object` types, which meant you had to manually cast objects when retrieving them, leading to potential `ClassCastException` at runtime.

```java
// Without Generics
List list = new ArrayList();
list.add("Hello");
String s = (String) list.get(0); // Explicit cast required

// With Generics
List<String> listGen = new ArrayList<>();
listGen.add("Hello");
String sGen = listGen.get(0); // No cast needed!
```

---

## 2. Generic Classes and Methods

You can define your own generic types using angle brackets `<T>`.

### Generic Class
```java
public class Box<T> {
    private T value;
    public void set(T value) { this.value = value; }
    public T get() { return value; }
}

Box<Integer> intBox = new Box<>();
intBox.set(10);
```

### Generic Method
```java
public static <E> void printArray(E[] elements) {
    for (E element : elements) {
        System.out.println(element);
    }
}
```

---

## 3. Wildcards in Generics

Wildcards are used when you want a generic to represent an unknown type.

1.  **Unbounded Wildcard (`<?>`)**: Can represent any type.
2.  **Upper Bounded Wildcard (`<? extends T>`)**: Can represent any type that is a subclass of `T`. Useful for reading.
3.  **Lower Bounded Wildcard (`<? super T>`)**: Can represent any type that is a superclass of `T`. Useful for writing.

```java
// Accepts List of Integer, Double, etc.
public static void sum(List<? extends Number> list) {
    double total = 0;
    for (Number n : list) total += n.doubleValue();
    System.out.println(total);
}
```

---

## 4. Type Erasure

To ensure backward compatibility with older Java versions, the compiler uses **Type Erasure**. It replaces all generic type parameters with their bounds (or `Object` if unbounded) during compilation. This means generic type information is not available at runtime.

```java
// Compiled as List<Object>
List<String> list = new ArrayList<>(); 
```

---

## 5. Key Rules

- You cannot use primitive types as generic parameters (e.g., `List<int>` is invalid; use `List<Integer>`).
- You cannot create an instance of a type parameter (`T obj = new T()`).
- You cannot create arrays of generic types.
- Static fields cannot be of a generic type parameter.
