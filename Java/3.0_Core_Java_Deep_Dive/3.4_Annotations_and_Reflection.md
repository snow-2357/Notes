# Annotations and Reflection

Annotations and Reflection are advanced Java features that allow for meta-programming—writing code that inspects or modifies other code at runtime.

---

## 1. Annotations

Annotations provide metadata about the code and have no direct effect on the operation of the code they annotate.

### Built-in Annotations
- `@Override`: Ensures a method is overriding a superclass method.
- `@Deprecated`: Marks a method/class as no longer recommended for use.
- `@SuppressWarnings`: Instructs the compiler to ignore specific warnings.

### Custom Annotations
Created using `@interface`. You can specify retention policy and target.

```java
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
public @interface MyAnnotation {
    String value() default "Default Value";
}
```

---

## 2. Reflection

Reflection is a feature that allows a program to inspect or manipulate its own structure (classes, methods, fields) at runtime.

### Common Uses of Reflection:
- Inspecting a class's methods and fields.
- Instantiating objects dynamically.
- Invoking methods by name.
- Accessing private fields (even if they are `private`).

```java
// Example: Getting class info at runtime
Class<?> clazz = Class.forName("com.example.User");
System.out.println("Class Name: " + clazz.getName());

Method[] methods = clazz.getDeclaredMethods();
for (Method m : methods) {
    System.out.println("Method: " + m.getName());
}
```

---

## 3. Accessing Private Members

Reflection allows you to bypass access modifiers, which is powerful but should be used with caution.

```java
Field privateField = User.class.getDeclaredField("password");
privateField.setAccessible(true); // Bypass 'private'
privateField.set(userObject, "newPassword");
```

---

## 4. Pros and Cons

### Pros
- **Flexibility**: Allows for highly dynamic code (used extensively in frameworks like Spring and Hibernate).
- **Tooling**: Enables IDEs to perform auto-completion and refactoring.

### Cons
- **Performance Overhead**: Reflection is slower than direct calls.
- **Security Risks**: Can break encapsulation.
- **Maintainability**: Code using reflection is often harder to read and debug.

---

## 5. Summary

- **Annotations** are "tags" that provide metadata.
- **Reflection** is the "engine" that reads those tags or inspects the code structure at runtime to perform dynamic actions.
- Together, they form the basis of most modern Java frameworks.
