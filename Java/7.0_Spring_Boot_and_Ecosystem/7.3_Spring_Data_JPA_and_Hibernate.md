# Spring Data JPA and Hibernate

**Spring Data JPA** is a part of the larger Spring Data family that makes it easy to implement JPA-based repositories. It uses **Hibernate** as the default JPA implementation.

---

## 1. What is JPA?

**Java Persistence API (JPA)** is a standard specification for object-relational mapping (ORM) in Java. It defines how to map Java objects (Entities) to relational database tables.

### What is Hibernate?
Hibernate is a popular ORM framework that implements the JPA specification. It handles the heavy lifting of generating SQL queries, managing transactions, and mapping database results back to Java objects.

---

## 2. Key Components of Spring Data JPA

### Entities
An **Entity** is a Java class that represents a table in your database. It's annotated with `@Entity`.

```java
@Entity
@Table(name = "users")
public class User {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(nullable = false, unique = true)
    private String username;

    private String email;

    // Getters and Setters
}
```

### Repositories
A **Repository** is an interface that provides a set of methods for interacting with your entities. You can extend `JpaRepository` or `CrudRepository`.

```java
@Repository
public interface UserRepository extends JpaRepository<User, Long> {
    // Custom query method derived from name
    Optional<User> findByUsername(String username);

    // Using @Query annotation for custom JPQL or native SQL
    @Query("SELECT u FROM User u WHERE u.email LIKE %:domain")
    List<User> findByEmailDomain(@Param("domain") String domain);
}
```

### Services
The **Service Layer** is where your application's business logic resides. It often uses one or more repositories to interact with the database.

```java
@Service
public class UserService {
    private final UserRepository userRepository;

    public UserService(UserRepository userRepository) {
        this.userRepository = userRepository;
    }

    public User createUser(User user) {
        return userRepository.save(user);
    }
}
```

## 3. Querying with Spring Data JPA

Spring Data JPA provides several ways to query your database:

1.  **Derived Query Methods**: Spring Data JPA automatically generates the query based on the method name (e.g., `findByUsername`).
2.  **JPQL (Java Persistence Query Language)**: An object-oriented query language that looks like SQL but works with entities and fields instead of tables and columns.
3.  **Native SQL Queries**: You can write raw SQL if needed using the `nativeQuery = true` attribute of `@Query`.
4.  **Criteria API**: A programmatic way to build dynamic queries (rarely used for simple cases).
5.  **Querydsl**: Another programmatic way to build type-safe queries.

## 4. Entity Relationships

JPA supports several types of relationships between entities:

- **`@OneToOne`**: One entity is related to exactly one other entity.
- **`@OneToMany`** / **`@ManyToOne`**: One entity is related to multiple other entities. This is the most common relationship.
- **`@ManyToMany`**: Multiple entities are related to multiple other entities. This requires a join table.

```java
@Entity
public class Post {
    @Id @GeneratedValue private Long id;
    
    @OneToMany(mappedBy = "post", cascade = CascadeType.ALL)
    private List<Comment> comments;
}

@Entity
public class Comment {
    @Id @GeneratedValue private Long id;

    @ManyToOne
    @JoinColumn(name = "post_id")
    private Post post;
}
```

## 5. Transactions and Dirty Checking

Spring Data JPA manages transactions automatically using the `@Transactional` annotation.

- **Dirty Checking**: Hibernate automatically detects changes to your entities and updates the database when the transaction commits. You don't need to manually call `.save()` for updates.

```java
@Service
@Transactional
public class UserService {
    public void updateEmail(Long id, String newEmail) {
        User user = userRepository.findById(id).orElseThrow();
        user.setEmail(newEmail); // Automatically saved when the method finishes!
    }
}
```

---

## 6. Best Practices

1.  **Use `JpaRepository`** for your common CRUD operations.
2.  **Prefer constructor injection** for your services and repositories.
3.  **Leverage derived query methods** for simple lookups.
4.  **Use `@Query`** for more complex queries to keep your repository interfaces clean.
5.  **Be careful with `FetchType.EAGER`**: It can lead to the "N+1 select" problem. Use `FetchType.LAZY` (the default for many-to-one and many-to-many) whenever possible.
6.  **Use `CascadeType`** judiciously to manage related entities' lifecycles.
