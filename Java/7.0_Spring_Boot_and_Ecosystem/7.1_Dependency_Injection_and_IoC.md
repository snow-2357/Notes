# Dependency Injection and IoC in Spring

**Inversion of Control (IoC)** and **Dependency Injection (DI)** are the core concepts of the Spring Framework. They allow you to build loosely coupled and highly testable applications.

---

## 1. Inversion of Control (IoC)

In traditional programming, you (the developer) are in control of creating objects and managing their lifecycle. In **IoC**, the control is inverted: the **Spring IoC Container** takes over the responsibility of creating, configuring, and managing the lifecycle of objects (known as **Beans**).

- Instead of calling `new MyService()`, you ask the container for an instance of `MyService`.
- The container handles the instantiation and injects any required dependencies.

---

## 2. Dependency Injection (DI)

**Dependency Injection** is a specific form of IoC where the container "injects" the required dependencies into a class at runtime. This makes your code more modular and easier to test.

### Types of Dependency Injection in Spring:

#### Constructor Injection (Recommended)
Dependencies are provided through the class constructor. This is the best practice as it ensures the object is always in a valid state and allows for `final` dependencies.

```java
@Service
public class UserService {
    private final UserRepository userRepository;

    // Autowired by Spring automatically
    public UserService(UserRepository userRepository) {
        this.userRepository = userRepository;
    }
}
```

#### Setter Injection
Dependencies are provided through setter methods. This is useful for optional dependencies.

```java
@Service
public class EmailService {
    private SmtpClient smtpClient;

    @Autowired
    public void setSmtpClient(SmtpClient smtpClient) {
        this.smtpClient = smtpClient;
    }
}
```

#### Field Injection (Discouraged)
Dependencies are injected directly into the fields using the `@Autowired` annotation. While concise, it makes unit testing harder and hides dependencies.

```java
@Service
public class OrderService {
    @Autowired
    private ProductRepository productRepository; // Avoid this in production
}
```

## 3. Spring Beans

A **Bean** is simply an object that is managed by the Spring IoC Container. You can define beans in several ways:

- **Component Scanning**: Annotate your classes with `@Component`, `@Service`, `@Repository`, or `@Controller`. Spring will automatically find and register them.
- **Java Configuration**: Use a `@Configuration` class and define beans with the `@Bean` annotation.

```java
@Configuration
public class AppConfig {
    @Bean
    public MyService myService() {
        return new MyServiceImpl();
    }
}
```

---

## 4. Bean Scopes

The scope of a bean defines its lifecycle and how many instances are created.
1.  **Singleton (Default)**: Only one instance of the bean is created for the entire application.
2.  **Prototype**: A new instance of the bean is created every time it's requested.
3.  **Request**: (Web apps only) A new instance is created for each HTTP request.
4.  **Session**: (Web apps only) A new instance is created for each HTTP session.

```java
@Component
@Scope("prototype")
public class UserSession { ... }
```

---

## 5. Qualifiers and Primary

If you have multiple implementations of the same interface, you can use these annotations to tell Spring which one to inject:

- **`@Primary`**: Tells Spring to use this implementation by default.
- **`@Qualifier`**: Allows you to specify the name of the bean you want to inject.

```java
@Service
@Qualifier("fastService")
public class FastService implements MyService { ... }

@Service
public class MyConsumer {
    public MyConsumer(@Qualifier("fastService") MyService service) { ... }
}
```

---

## 6. Autowiring Modes

Spring provides several modes for autowiring:
- **`no`**: (Default) No autowiring.
- **`byName`**: Autowiring by property name.
- **`byType`**: Autowiring by property type.
- **`constructor`**: Similar to `byType` but for constructor arguments.

**Note**: In modern Spring, explicit autowiring modes are rarely used; Spring's default behavior (automatically choosing the best method) is usually sufficient.
