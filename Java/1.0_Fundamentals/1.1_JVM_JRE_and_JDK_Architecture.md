# JVM, JRE, and JDK Architecture

Understanding the Java platform requires a clear distinction between the JDK, JRE, and JVM. These three components form the backbone of Java's "Write Once, Run Anywhere" (WORA) philosophy.

---

## 1. The Big Picture: JDK vs. JRE vs. JVM

- **JDK (Java Development Kit)**: The full SDK for Java. It contains everything needed to **develop** and **run** Java applications.
  - Includes JRE + Development Tools (compiler `javac`, debugger `jdb`, archiver `jar`, etc.).
- **JRE (Java Runtime Environment)**: The environment needed to **run** Java applications.
  - Includes JVM + Runtime Libraries (standard Java classes) + Other files.
- **JVM (Java Virtual Machine)**: The engine that actually **executes** the Java bytecode.
  - It is platform-dependent (different JVMs for Windows, Mac, Linux).
  - It provides the runtime environment in which Java bytecode can be executed.

**Relationship:** `JDK = JRE + Development Tools` | `JRE = JVM + Library Classes`

---

## 2. JVM Architecture

The JVM is divided into three main subsystems:

### A. Class Loader Subsystem
Responsible for loading, linking, and initializing the class files (`.class`).
1.  **Loading**: Loads classes from various sources (Bootstrap, Extension, Application class loaders).
2.  **Linking**: Verifies bytecode, allocates memory for static variables (Preparation), and resolves symbolic references.
3.  **Initialization**: Executes static blocks and assigns initial values to static variables.

### B. Runtime Data Areas (Memory Management)
- **Method Area**: Stores class-level data (static variables, method code). Shared among all threads.
- **Heap Area**: Stores all objects and their corresponding instance variables. Shared among all threads.
- **Stack Area**: Stores local variables and partial results for each thread. Each thread has its own private stack.
- **PC Registers**: Contains the address of the currently executing instruction for each thread.
- **Native Method Stack**: Stores native method information (methods written in C/C++).

### C. Execution Engine
The component that executes the bytecode.
1.  **Interpreter**: Reads bytecode and executes instructions one by one. Faster to start but slower to execute overall.
2.  **JIT (Just-In-Time) Compiler**: Compiles frequently executed bytecode (hotspots) into native machine code to improve performance.
3.  **Garbage Collector (GC)**: Automatically manages memory by identifying and deleting unreachable objects.

---

## 3. The Java Execution Process

1.  **Writing Code**: You write Java source code in a `.java` file.
2.  **Compilation**: The `javac` compiler converts `.java` into `.class` (Bytecode). Bytecode is intermediate code, not machine code.
3.  **Loading**: The JVM's Class Loader loads the `.class` file into memory.
4.  **Verification**: The JVM verifies the bytecode for security and integrity.
5.  **Execution**: The Execution Engine (Interpreter + JIT) converts bytecode into machine-specific instructions for the OS.

---

## 4. Key Takeaways

- **Bytecode** is platform-independent.
- **JVM** is platform-dependent.
- **JIT Compiler** is what makes modern Java performance comparable to C++.
- **Garbage Collection** simplifies development by handling memory deallocation automatically.
