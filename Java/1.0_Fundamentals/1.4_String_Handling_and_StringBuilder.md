# String Handling and StringBuilder

In Java, Strings are objects that represent a sequence of characters. Understanding how they work in memory is crucial for writing efficient code.

---

## 1. String Immutability

Strings in Java are **immutable**, meaning once a `String` object is created, its value cannot be changed. Any operation that appears to modify a string actually creates a new `String` object.

```java
String s1 = "Hello";
s1.concat(" World"); 
System.out.println(s1); // Output: "Hello" (s1 remains unchanged)

s1 = s1.concat(" World");
System.out.println(s1); // Output: "Hello World" (s1 now points to a new object)
```

### The String Constant Pool (SCP)
To save memory, JVM uses a special memory area called the String Constant Pool. When you create a string literal, the JVM checks the pool first. If the string already exists, it returns a reference to the existing one.

```java
String a = "Java";
String b = "Java";
System.out.println(a == b); // true (Both point to the same object in SCP)

String c = new String("Java");
System.out.println(a == c); // false (c is created in the Heap memory, not SCP)
```

## 2. Common String Methods

| Method | Description |
| :--- | :--- |
| `length()` | Returns the number of characters |
| `charAt(index)` | Returns the character at a specific index |
| `substring(start, end)` | Returns a part of the string |
| `contains(str)` | Checks if string contains a sequence |
| `equals(str)` | Compares content (Case-sensitive) |
| `equalsIgnoreCase(str)` | Compares content (Case-insensitive) |
| `indexOf(char)` | Returns the index of the first occurrence |
| `replace(old, new)` | Replaces characters/sequences |
| `split(regex)` | Splits string into an array |

## 3. StringBuilder and StringBuffer

When you need to modify strings frequently (e.g., in a loop), using `String` is inefficient because it creates many temporary objects. Instead, use `StringBuilder` or `StringBuffer`.

### StringBuilder
- **Mutable**: Modifications happen in the same memory location.
- **Not Thread-Safe**: Faster than `StringBuffer`.
- Use case: Single-threaded environments where performance is key.

```java
StringBuilder sb = new StringBuilder("Hello");
sb.append(" World");
sb.insert(5, ",");
sb.reverse();
System.out.println(sb.toString());
```

### StringBuffer
- **Mutable**: Same as `StringBuilder`.
- **Thread-Safe**: Methods are synchronized, making it safe for use across multiple threads.
- **Slower** than `StringBuilder` due to synchronization overhead.

---

## 4. Best Practices

1.  Use **String Literals** (`"abc"`) instead of `new String("abc")` to take advantage of the String Constant Pool.
2.  Use **`.equals()`** to compare the content of strings, not `==`. `==` compares memory addresses.
3.  Use **`StringBuilder`** for complex string manipulations or when building strings inside loops.
4.  Avoid string concatenation in loops:
    ```java
    // BAD
    String result = "";
    for (int i = 0; i < 100; i++) result += i;

    // GOOD
    StringBuilder sb = new StringBuilder();
    for (int i = 0; i < 100; i++) sb.append(i);
    ```
