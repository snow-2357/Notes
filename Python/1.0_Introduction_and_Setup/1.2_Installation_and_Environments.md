# Installation and Environments

Setting up a proper Python environment is the first step to effective development. This involves installing Python and learning to use virtual environments to manage project dependencies.

## 1. Installing Python

Most non-Windows systems come with Python pre-installed. You can check your version by opening a terminal and running:
```bash
python --version
# or
python3 --version
```
If you don't have it, or if you need a specific version, you should install it.

### Recommended Method: `pyenv`
For macOS and Linux, `pyenv` is a popular tool that lets you easily install and manage multiple Python versions on the same machine. This is highly recommended as it prevents you from interfering with your system's default Python installation.

**Basic `pyenv` usage:**
```bash
# Install a specific version of Python
pyenv install 3.11.5

# Set the global Python version
pyenv global 3.11.5

# Set a local (per-project) Python version
pyenv local 3.10.7
```

For Windows, you can download the official installer from [python.org](https://www.python.org/downloads/). Be sure to check the box that says **"Add Python to PATH"** during installation.

## 2. `pip`: The Package Installer

Python uses `pip` to install and manage third-party packages (libraries and frameworks) from the Python Package Index (PyPI).

```bash
# Check pip version
pip --version
# or
pip3 --version

# Install a package
pip install requests

# Install a specific version of a package
pip install requests==2.28.1

# List installed packages
pip list

# Uninstall a package
pip uninstall requests
```

## 3. Virtual Environments

It is a best practice to create a **virtual environment** for each Python project you work on. A virtual environment is an isolated directory that contains its own Python interpreter and its own set of installed packages.

**Why use them?**
- **Dependency Isolation**: Project A can depend on version 1.0 of a library, while Project B can depend on version 2.0 of the same library, without any conflicts.
- **Cleanliness**: It keeps your global package directory clean and free of clutter.
- **Reproducibility**: It makes it easy to replicate your project's environment on another machine.

### Using `venv`
Python 3 comes with a built-in module called `venv` for creating virtual environments.

**Workflow:**
1.  **Navigate to your project folder:**
    ```bash
    cd my-python-project
    ```
2.  **Create a virtual environment:**
    The command below creates a directory named `venv` (a common convention) which will contain the environment.
    ```bash
    python -m venv venv
    ```
3.  **Activate the environment:**
    - **On macOS/Linux:**
      ```bash
      source venv/bin/activate
      ```
    - **On Windows (Git Bash):**
      ```bash
      source venv/Scripts/activate
      ```
    - **On Windows (Command Prompt/PowerShell):**
      ```bash
      .\venv\Scripts\activate
      ```
    Your terminal prompt will usually change to show the name of the activated environment (e.g., `(venv) $`).

4.  **Work in your environment:**
    Now, when you use `pip install`, packages will be installed inside the `venv` directory, not globally.

5.  **Deactivate the environment:**
    When you are done working, you can deactivate it.
    ```bash
    deactivate
    ```

## 4. `requirements.txt`

To share your project with others or to set it up on another machine, you need a way to list its dependencies. The standard way to do this is with a `requirements.txt` file.

```bash
# While your virtual environment is active, generate the file
pip freeze > requirements.txt

# On another machine, create and activate a new virtual environment, then run:
pip install -r requirements.txt
```
This command tells `pip` to install all the packages listed in the `requirements.txt` file.
