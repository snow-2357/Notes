# The Four Pillars of OOP

Object-Oriented Programming is based on four fundamental principles, often referred to as the four pillars.

## 1. Encapsulation

Encapsulation is the bundling of data (attributes) and the methods that operate on that data into a single unit (a class). It also restricts direct access to some of an object's components, which is a key part of data hiding.

In Python, we don't have true `private` variables like in Java or C++. Instead, we use a convention:
- **Protected attributes**: Prefixed with a single underscore (e.g., `_name`). This is a hint to other programmers that the attribute is intended for internal use.
- **Private attributes**: Prefixed with two underscores (e.g., `__balance`). This triggers "name mangling," which makes it harder to access from outside the class.

```python
class Account:
    def __init__(self, owner, balance):
        self.owner = owner
        self._account_number = "12345" # Protected
        self.__balance = balance       # Private

    def deposit(self, amount):
        if amount > 0:
            self.__balance += amount
            print("Deposit successful.")

    def get_balance(self):
        # We provide a public method to access the private attribute
        return self.__balance

# The __balance attribute is "mangled" and not directly accessible
acc = Account("Alice", 1000)
# print(acc.__balance) # This would raise an AttributeError

# We should use the public method to get the balance
print(f"Current balance: {acc.get_balance()}")
```

## 2. Inheritance

Inheritance is a mechanism where a new class (child/subclass) inherits attributes and methods from an existing class (parent/superclass). This promotes code reuse.

```python
# Parent class
class Animal:
    def __init__(self, name):
        self.name = name

    def speak(self):
        raise NotImplementedError("Subclass must implement abstract method")

# Child class inheriting from Animal
class Dog(Animal):
    def speak(self):
        return "Woof!"

# Another child class
class Cat(Animal):
    def speak(self):
        return "Meow!"

my_dog = Dog("Buddy")
print(my_dog.speak()) # Output: Woof!

my_cat = Cat("Whiskers")
print(my_cat.speak()) # Output: Meow!
```

## 3. Polymorphism

Polymorphism, which means "many forms," allows objects of different classes to be treated as objects of a common superclass. It's the ability to use a common interface for different underlying forms (data types).

A common demonstration of polymorphism is using a loop that iterates through a list of objects from different classes and calls the same method on each.

```python
animals = [Dog("Buddy"), Cat("Whiskers")]

for animal in animals:
    # The same `speak` method call works for different objects
    print(f"{animal.name} says: {animal.speak()}")
```
This works because both `Dog` and `Cat` have their own implementation of the `speak` method.

## 4. Abstraction

Abstraction means hiding complex implementation details and showing only the essential features of the object. In the inheritance example above, the `Animal` class is abstract.

We don't expect to create an `Animal` object directly. Instead, we use it as a base to build more specific classes like `Dog` and `Cat`. The `speak` method in `Animal` is an abstract method because it doesn't do anything itself; it just defines an interface that its subclasses must implement. Python's `abc` module can be used to formally define Abstract Base Classes (ABCs).
