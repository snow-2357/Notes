# Decorators in Python

A decorator is a design pattern in Python that allows a user to add new functionality to an existing object (like a function) without modifying its structure. Decorators are usually called before the definition of a function you want to decorate.

## 1. Functions are First-Class Objects

In Python, functions are "first-class objects." This means that functions can be:
- Assigned to a variable.
- Passed as an argument to another function.
- Returned from another function.

This property is what makes decorators possible.

```python
def greet(name):
    return f"Hello, {name}"

# Assigning a function to a variable
say_hello = greet
print(say_hello("Alice")) # Output: Hello, Alice

# Passing a function as an argument
def process_greeting(greeter_func, name):
    return greeter_func(name).upper()

print(process_greeting(greet, "Bob")) # Output: HELLO, BOB
```

## 2. A Simple Decorator

A decorator is essentially a function that takes another function as an argument, adds some functionality, and then returns another function.

Here's a simple decorator that logs when a function is called.

```python
def my_logger(original_function):
    def wrapper_function():
        print(f"Running function: {original_function.__name__}")
        original_function()
        print(f"Finished function: {original_function.__name__}")
    return wrapper_function

# This is how you would use it without the '@' syntax
def display_info():
    print("This is some important information.")

decorated_display = my_logger(display_info)
decorated_display()
```

## 3. The `@` Syntactic Sugar

The `@` symbol is "syntactic sugar" that makes using decorators cleaner and more readable.

```python
def my_logger(original_function):
    def wrapper_function():
        print(f"Running function: {original_function.__name__}")
        original_function()
        print(f"Finished function: {original_function.__name__}")
    return wrapper_function

@my_logger
def display_info():
    print("This is some important information.")

display_info()
```
This code is equivalent to `display_info = my_logger(display_info)`.

## 4. Decorating Functions with Arguments

What if our function takes arguments? We need to pass those arguments to the original function inside our wrapper. We use `*args` and `**kwargs` to handle any number of positional and keyword arguments.

```python
def logger_with_args(original_function):
    def wrapper(*args, **kwargs):
        print(f"Running {original_function.__name__} with args: {args}, kwargs: {kwargs}")
        result = original_function(*args, **kwargs)
        print(f"Result: {result}")
        return result
    return wrapper

@logger_with_args
def add(x, y):
    return x + y

add(5, 3)
```

## 5. Preserving Function Metadata

When you use a decorator, you're technically replacing your original function with the wrapper function. This can cause issues with debugging and introspection because the metadata of the original function (like its name `__name__` and docstring `__doc__`) is lost.

The `functools` module provides a decorator called `@wraps` that you can use inside your decorator to copy this metadata over to the wrapper function.

```python
import functools

def my_logger(original_function):
    @functools.wraps(original_function) # This is the important part
    def wrapper(*args, **kwargs):
        """This is the wrapper function's docstring."""
        print(f"Logging: Calling {original_function.__name__}")
        return original_function(*args, **kwargs)
    return wrapper

@my_logger
def my_function():
    """This is my_function's docstring."""
    print("Executing my_function.")

print(my_function.__name__) # Output: my_function (without @wraps, it would be 'wrapper')
print(my_function.__doc__)  # Output: This is my_function's docstring.
```
