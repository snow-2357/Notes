# 1.3 Functions Deep Dive

Functions are fundamental building blocks in JavaScript. They are reusable blocks of code that can be executed by name. In JavaScript, functions are "first-class citizens," meaning they can be treated like any other variable: stored in variables, passed as arguments to other functions, and returned from functions.

## Basic: Declaration vs. Expression

### Function Declaration
This is the classic way to define a function. Declarations are **hoisted**, meaning they are available in their entire scope even before the line they are declared.

```javascript
// You can call it before it's defined
sayHello(); // "Hello!"

function sayHello() {
  console.log("Hello!");
}
```

### Function Expression
Here, a function is assigned to a variable. The function itself is anonymous (it has no name), but the variable holds a reference to it. Expressions are **not hoisted**.

```javascript
// sayHi(); // TypeError: sayHi is not a function

const sayHi = function() {
  console.log("Hi!");
};

sayHi(); // "Hi!"
```

### Arrow Functions (ES6)
A more concise syntax for function expressions. Arrow functions also have a key difference in how they handle the `this` keyword.

```javascript
const add = (a, b) => {
  return a + b;
};

// Implicit return for single expressions
const subtract = (a, b) => a - b;
```

## Advanced: The `this` Keyword

The `this` keyword is a reference to the context in which the current function is being executed. Its value is determined by **how the function is called**.

1.  **Global Context**: Outside of any function, `this` refers to the global object (`window` in browsers, `global` in Node.js).
    ```javascript
    console.log(this); // window (in a browser)
    ```

2.  **Function Context (Default Binding)**: Inside a regular function (not an arrow function), if it's called without a specific context, `this` also defaults to the global object. In strict mode (`'use strict'`), it is `undefined`.
    ```javascript
    function showThis() {
      console.log(this);
    }
    showThis(); // window (or undefined in strict mode)
    ```

3.  **Method Context (Implicit Binding)**: When a function is called as a method of an object, `this` refers to the object itself.
    ```javascript
    const user = {
      name: 'Gemini',
      greet: function() {
        console.log(`Hello, ${this.name}`); // `this` is the user object
      }
    };
    user.greet(); // "Hello, Gemini"
    ```

4.  **Arrow Function Context (Lexical Binding)**: Arrow functions do not have their own `this` binding. Instead, they "inherit" the `this` value from their surrounding (lexical) scope. This is extremely useful for callbacks and event handlers.
    ```javascript
    const counter = {
      count: 0,
      start: function() {
        // `this` here is the counter object
        setInterval(() => {
          // `this` inside the arrow function is also the counter object
          this.count++;
          console.log(this.count);
        }, 1000);
      }
    };
    counter.start();
    ```

## Advanced: Higher-Order Functions

A function that either:
1.  Takes one or more functions as arguments.
2.  Returns a function as its result.

This is a core concept of functional programming.

```javascript
// Example 1: Taking a function as an argument (like .map)
const numbers = [1, 2, 3];
const double = n => n * 2;
const doubledNumbers = numbers.map(double); // .map is a higher-order function
console.log(doubledNumbers); // [2, 4, 6]

// Example 2: Returning a function
function createGreeter(greeting) {
  return function(name) {
    console.log(`${greeting}, ${name}!`);
  };
}

const greetInSpanish = createGreeter("Hola");
greetInSpanish("Mundo"); // "Hola, Mundo!"
```

## Advanced: Closures

A closure is the combination of a function and the lexical environment within which that function was declared. In simpler terms, a closure gives you access to an outer function's scope from an inner function, even after the outer function has finished executing.

The `createGreeter` function above is a perfect example of a closure. The inner function "remembers" the `greeting` variable from its parent's scope.

**Classic Example: The Loop Problem**
Without closures (and using `var`), this code doesn't behave as expected.

```javascript
for (var i = 1; i <= 3; i++) {
  setTimeout(function() {
    console.log(i); // Prints 4, 4, 4
  }, 10);
}
```
This is because the `setTimeout` callbacks all share the *same* `i` from the global scope, and by the time they run, the loop has finished and `i` is 4.

**Solution with a Closure:**
```javascript
for (var i = 1; i <= 3; i++) {
  (function(j) { // Create a new scope with a closure
    setTimeout(function() {
      console.log(j); // Prints 1, 2, 3
    }, 10);
  })(i); // Immediately invoke the function, passing in the current `i`
}
```
**Modern Solution with `let`**: `let` is block-scoped, so it creates a new binding for `i` in each loop iteration, effectively solving the problem without an explicit closure.
```javascript
for (let i = 1; i <= 3; i++) {
  setTimeout(function() {
    console.log(i); // Prints 1, 2, 3
  }, 10);
}
```
