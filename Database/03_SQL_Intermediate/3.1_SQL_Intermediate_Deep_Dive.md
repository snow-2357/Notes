# Phase 3: SQL Intermediate

This phase bridges the gap between simple queries and professional-grade data manipulation.

## 1. The Power of Joins
Joins allow you to normalize data and then reconstruct it for the user.

- **INNER JOIN:** The most common. Returns records with matching values in both tables.
- **LEFT JOIN:** Returns all records from the left table and matched records from the right. Unmatched right rows are `NULL`.
- **RIGHT JOIN:** Inverse of Left Join. Use sparingly; usually, a Left Join is more readable.
- **SELF JOIN:** A table joined with itself.
    - *Use Case:* Finding an employee's manager in a single `employees` table.
- **CROSS JOIN:** Returns the Cartesian product (every row from A paired with every row from B).
    - *Use Case:* Generating all possible combinations of products and sizes.

## 2. Set Operations
- **UNION:** Combines result sets and removes duplicates.
- **UNION ALL:** Combines result sets but keeps duplicates (Faster than UNION).
- **INTERSECT:** Returns only rows present in both result sets.
- **EXCEPT / MINUS:** Returns rows in the first set but not the second.

## 3. Advanced Subqueries
- **Non-Correlated:** The inner query can run independently (e.g., `WHERE price > (SELECT AVG(price) FROM products)`).
- **Correlated:** The inner query depends on values from the outer query.
    - *Caution:* These can be slow if not optimized.
- **EXISTS:** Returns true if the subquery returns at least one row. Often faster than `IN` for large datasets.

## 4. Common Table Expressions (CTE)
CTEs improve readability and can be recursive.
```sql
WITH top_customers AS (
    SELECT user_id, SUM(total) as spend
    FROM orders
    GROUP BY user_id
    HAVING SUM(total) > 5000
)
SELECT u.name, tc.spend
FROM users u
JOIN top_customers tc ON u.id = tc.user_id;
```

## 5. Window Functions
Calculations across a set of rows related to the current row.
- `ROW_NUMBER()`: Assigns a unique rank (1, 2, 3...).
- `RANK()` / `DENSE_RANK()`: Handles ties (1, 2, 2, 4 vs 1, 2, 2, 3).
- `LEAD()` / `LAG()`: Peeking at the next or previous row.
    - *Use Case:* Calculating month-over-month growth.

## 6. Schema Objects
- **Views:** Virtual tables based on a SELECT statement. Great for security and simplifying complex joins.
- **Stored Procedures:** Pre-compiled SQL code stored on the server. Used for complex logic that needs to be close to the data.
