# Phase 11: Distributed Systems Concepts

When data is spread across multiple machines, the rules of physics and networking introduce new complexities.

## 1. Consensus Algorithms
How do independent servers agree on a single truth (e.g., "Who is the leader?")?
- **Raft:** A popular consensus algorithm designed for understandability. Used by etcd (Kubernetes) and CockroachDB.
- **Paxos:** The "original" consensus algorithm. Mathematically rigorous but notoriously difficult to implement.

## 2. The CAP Theorem (Review)
In a network partition (P), you must choose between:
- **Consistency (C):** Atomic consistency; every node sees the same data at the same time.
- **Availability (A):** Every node can respond to reads/writes, even if it's not the latest data.
- **PACELC Theorem:** Extends CAP by saying: In case of **P**artition, choose between **A**vailability and **C**onsistency; **E**lse (no partition), choose between **L**atency and **C**onsistency.

## 3. Consistency Models
- **Strong Consistency:** Linearizability. Reads always return the most recent write.
- **Eventual Consistency:** If no new updates are made, all reads will eventually return the same value. (Standard for high-scale NoSQL).
- **Causal Consistency:** Operations that are causally related are seen by all nodes in the same order.

## 4. Quorum Reads and Writes
A mechanism to ensure consistency without requiring all nodes to be online.
- `N`: Number of replicas.
- `W`: Number of nodes that must confirm a write.
- `R`: Number of nodes that must respond to a read.
- **Rule:** If `W + R > N`, you are guaranteed to read the latest value.

## 5. Distributed Locks
Ensuring only one process across the whole network can access a resource.
- Usually implemented using a strongly consistent store like Redis (Redlock) or ZooKeeper.

## 6. Leader Election
The process of choosing a "Leader" node to handle writes while "Follower" nodes handle reads or stay in standby.
- If the leader fails, a new election is triggered using a consensus algorithm.
