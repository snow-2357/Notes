# Phase 10 & 11: NoSQL & Distributed Concepts

Understanding the world beyond the relational model.

## 1. NoSQL Databases (Phase 10)
- **Document (MongoDB):** Schema-less, JSON-like. Best for evolving data models.
- **Key-Value (Redis):** Ultra-fast. Best for caching and sessions.
- **Wide-column (Cassandra):** Designed for massive writes and high availability.
- **Graph (Neo4j):** Best for complex relationships (Social graphs, fraud detection).

## 2. Distributed Database Concepts (Phase 11)

### 2.1 Consistency Models
- **Strong Consistency:** All nodes see the same data at the same time. (Slow).
- **Eventual Consistency:** Data will eventually be the same across nodes. (Fast, NoSQL).

### 2.2 Consensus Algorithms
- **Raft / Paxos:** Algorithms used by distributed systems to agree on a value (e.g., who is the leader?).
- **Quorum R/W:** `R + W > N`. If you write to a majority and read from a majority, you are guaranteed to see the latest data.

### 2.3 The Theorems
- **CAP Theorem:** Consistency, Availability, Partition Tolerance.
- **PACELC Theorem:** If there is a Partition (P), choose between Availability (A) and Consistency (C); Else (E), choose between Latency (L) and Consistency (C).
