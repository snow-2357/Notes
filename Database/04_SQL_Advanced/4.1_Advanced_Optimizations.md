# SQL Advanced: Query Optimization & Concurrency

Mastering the execution and safety of complex operations.

## 1. Query Optimization & Execution Plans
Understanding how the database sees your query.
- **Index Scan:** Fast lookup via B-Tree.
- **Table Scan:** Slow sequential read of the whole table.
- **Recursive CTEs:** Useful for traversing graph-like or hierarchical data (e.g., an org chart).
    ```sql
    WITH RECURSIVE subordinates AS (
        SELECT id, name, manager_id FROM employees WHERE name = 'Alice'
        UNION ALL
        SELECT e.id, e.name, e.manager_id FROM employees e
        INNER JOIN subordinates s ON s.id = e.manager_id
    )
    SELECT * FROM subordinates;
    ```

## 2. Transactions & Locks
- **Atomicity:** `BEGIN`, `COMMIT`, `ROLLBACK`.
- **Row-level Locks:** `SELECT ... FOR UPDATE` prevents other transactions from modifying a row until you're done.
- **Deadlocks:** When Transaction A waits for B, and B waits for A.
    - *Solution:* Always acquire locks in the same order.

## 3. Isolation Levels Deep Dive
- **Dirty Reads:** Seeing uncommitted data.
- **Non-Repeatable Reads:** Data changes between two reads in the same transaction.
- **Phantom Reads:** New rows appear between two reads in the same transaction.
- **Postgres Default:** `Read Committed`.
- **Highest Safety:** `Serializable`.
    - *Note:* Serializable can cause "Serialization Failures", meaning the application must be prepared to retry the transaction.
