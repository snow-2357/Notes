# Phase 14: Database Security

Data is a company's most valuable asset; securing it is mandatory.

## 1. Core Security Threats
- **SQL Injection:** Malicious SQL code injected into queries.
    - *Defense:* **ALWAYS** use **Prepared Statements** or Parameterized Queries. Never concatenate strings.

## 2. PostgreSQL Security Features
- **Row-Level Security (RLS):** Policies that restrict which rows a user can see (e.g., a user can only see their own orders).
- **Prepared Statements:** Prevents injection by separating query logic from data.
- **RBAC (Role-Based Access Control):** Granting specific permissions (SELECT, INSERT) to specific users/roles.

## 3. Data Protection
- **Encryption at Rest:** Encrypting the data files on disk.
- **Encryption in Transit:** Using TLS/SSL for all connections.
- **Secrets Management:** Never hardcode credentials. Use environment variables or secret managers (AWS Secrets Manager, HashiCorp Vault).

## 4. Operational Security
- **Backup & Recovery:** 
    - **Logical Backup:** `pg_dump`.
    - **Physical Backup:** Disk snapshots.
    - **Point-in-Time Recovery (PITR):** Using WAL logs to restore a database to any specific microsecond in the past.
