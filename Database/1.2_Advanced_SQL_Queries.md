# Advanced SQL & Query Optimization

Effective SQL isn't just about getting the data—it's about getting it with minimal resource consumption.

## 1. Complex Joins & Set Operations

### 1.1 Self Joins
Useful for hierarchical data (e.g., employees and their managers).
```sql
SELECT e.name AS employee, m.name AS manager
FROM employees e
LEFT JOIN employees m ON e.manager_id = m.id;
```

### 1.2 LATERAL Joins (The "For-Each" Join)
Allows you to run a subquery for every row returned by the outer query.
```sql
SELECT p.name, top_reviews.content
FROM products p
LEFT JOIN LATERAL (
    SELECT content FROM reviews 
    WHERE product_id = p.id 
    ORDER BY rating DESC LIMIT 3
) top_reviews ON true;
```

## 2. Window Functions (Analytical SQL)
Window functions perform calculations across a set of rows related to the current row without grouping them into a single output row.

### 2.1 Common Functions
- `RANK()` / `DENSE_RANK()`: Rankings.
- `LAG()` / `LEAD()`: Accessing data from the previous or next row (great for trend analysis).
- `SUM(...) OVER(...)`: Running totals.

```sql
SELECT 
    order_date,
    amount,
    SUM(amount) OVER (ORDER BY order_date) as running_total
FROM sales;
```

## 3. Query Optimization Patterns

### 3.1 Avoiding N+1 in SQL
Instead of looping in code, use `IN` or `JOIN`.
- **Bad:** `SELECT * FROM comments WHERE post_id = ?` (called 100 times).
- **Good:** `SELECT * FROM comments WHERE post_id IN (1, 2, 3...)`.

### 3.2 SARGability (Search ARgumentable)
Queries must allow the DB to use an index.
- **Non-SARGable:** `SELECT * FROM users WHERE YEAR(created_at) = 2023;` (Functions on columns prevent index usage).
- **SARGable:** `SELECT * FROM users WHERE created_at >= '2023-01-01' AND created_at < '2024-01-01';`

### 3.3 CTEs vs Subqueries
- **CTEs:** Better readability, can be recursive.
- **Subqueries:** Sometimes faster in older versions of MySQL/Postgres, but CTEs are generally preferred for maintainability.
