# 2.6 Advanced Bundling: Module Federation

Module Federation is a technology, pioneered by Webpack, that allows a JavaScript application to dynamically load code from another application at runtime. It is a powerful tool for building **Micro-Frontends**.

## The Problem Solved by Module Federation

Imagine you have multiple, independent front-end applications (e.g., one for user profiles, one for product search, one for checkout). You want to combine them into a single, cohesive user experience.

**Traditional approaches had drawbacks:**
- **NPM Packages:** You could share code by publishing it as an NPM package, but this creates a tight coupling. Every time the shared package is updated, all consuming applications need to be updated and redeployed.
- **iFrames:** iFrames provide isolation but are clunky, bad for SEO, and make communication between the different parts of the application difficult.

## How Module Federation Works

Module Federation allows one application (a **host**) to load a "remote entry" file from another application (a **remote**). This entry file contains information about the code that the remote application is exposing.

- **Host Application:** The main application shell that consumes code from other applications.
- **Remote Application:** An application that exposes some of its modules to be consumed by other applications.
- **An application can be both a host and a remote.**

**Key Features:**
- **Runtime Integration:** Code is loaded at runtime, not at build time. This means a remote application can be deployed independently, and the host application will pick up the changes on the next page load without needing to be redeployed itself.
- **Dependency Sharing:** Module Federation is smart about dependencies. If the host and the remote both depend on `react@18.2.0`, it will only be loaded once. This avoids bloating the user's browser with duplicate libraries.

### Example Configuration (Webpack)

**Remote Application (`webpack.config.js`)**
```javascript
// products-app
new ModuleFederationPlugin({
  name: 'products',
  filename: 'remoteEntry.js',
  exposes: {
    './ProductListPage': './src/ProductListPage', // Expose the ProductListPage component
  },
  shared: ['react', 'react-dom'], // List shared dependencies
}),
```

**Host Application (`webpack.config.js`)**
```javascript
// home-app (the shell)
new ModuleFederationPlugin({
  name: 'home',
  remotes: {
    products: 'products@http://localhost:3002/remoteEntry.js', // URL to the remote's entry file
  },
  shared: ['react', 'react-dom'],
}),
```

**Host Application (Usage)**
```javascript
// In a component in the home-app
import React, { Suspense } from 'react';
const ProductListPage = React.lazy(() => import('products/ProductListPage'));

function App() {
  return (
    <div>
      <h1>Welcome to the Shell</h1>
      <Suspense fallback="Loading Products...">
        <ProductListPage />
      </Suspense>
    </div>
  );
}
```
This technology is a game-changer for large organizations that want to allow multiple teams to work on and deploy different parts of a large web application independently.
