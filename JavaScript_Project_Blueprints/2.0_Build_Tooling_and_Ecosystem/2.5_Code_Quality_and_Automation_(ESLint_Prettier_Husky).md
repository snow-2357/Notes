# 2.5 Code Quality and Automation (ESLint, Prettier, Husky)

A consistent and high-quality codebase is crucial for maintainability and collaboration. This is achieved through a combination of linting, formatting, and automation.

## ESLint (Code Linter)
A tool for identifying and reporting on patterns found in ECMAScript/JavaScript code, with the goal of making code more consistent and avoiding bugs.

- **Purpose:** To enforce code quality rules. It can find potential errors, enforce best practices, and highlight stylistic issues.
- **Configuration:** `.eslintrc.js` or `.eslintrc.json`. Here you define rules, extend popular style guides (like `eslint-config-airbnb` or `eslint:recommended`), and add plugins for frameworks (`eslint-plugin-react`) or TypeScript (`@typescript-eslint/eslint-plugin`).
- **Example Rule:** `no-unused-vars` will warn you if you have a variable that is declared but never used.

## Prettier (Code Formatter)
An opinionated code formatter that enforces a consistent style by parsing your code and re-printing it with its own rules.

- **Purpose:** To enforce code style. It doesn't check for errors, only for formatting (line length, indentation, quotes, etc.).
- **Configuration:** `.prettierrc`. Configuration is intentionally limited.
- **Why use both?** ESLint handles *code quality* (e.g., "don't use `var`"), while Prettier handles *code style* (e.g., "use 2 spaces for indentation"). They work together. You often use `eslint-config-prettier` to disable all ESLint style rules so they don't conflict with Prettier.

## Husky (Git Hooks)
A tool that makes it easy to use Git hooks. Git hooks are scripts that run automatically at certain points in the Git lifecycle, such as before a commit or a push.

- **Purpose:** To automate quality checks before code enters the repository.
- **Configuration:** A `.husky/` directory in your project root.
- **Common Use Case: Pre-Commit Hook**
    - A `pre-commit` script is created in the `.husky/` directory.
    - This script can run commands like `npx lint-staged`.
    - `lint-staged` is a tool that runs commands only on the files that are currently staged in Git.
    - **Workflow:**
        1. You run `git commit`.
        2. Husky triggers the `pre-commit` hook.
        3. The hook executes `lint-staged`.
        4. `lint-staged` runs Prettier and/or ESLint on only the files you're about to commit.
        5. If the linter/formatter finds issues, the commit is aborted, forcing you to fix the issues before you can commit.
