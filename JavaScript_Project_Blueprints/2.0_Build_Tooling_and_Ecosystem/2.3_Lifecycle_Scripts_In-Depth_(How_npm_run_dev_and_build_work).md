# 2.3 Lifecycle Scripts In-Depth (How npm run dev and build work)

The `scripts` section of `package.json` is a powerful way to automate tasks related to your project.

```json
"scripts": {
  "dev": "vite",
  "build": "vite build",
  "preview": "vite preview",
  "test": "jest"
}
```

## How `npm run <script>` Works

1.  When you run `npm run dev`, `npm` looks for a `dev` key in the `scripts` object of your `package.json`.
2.  It then executes the command string associated with that key (`"vite"` in this case).
3.  Crucially, `npm` temporarily adds your project's `node_modules/.bin` directory to the system's `PATH`. This is how it knows what the `vite` command is without you having to type `./node_modules/.bin/vite`.

## `npm run dev` (or `npm start`)

This script is used to start a local development server.

**What's happening under the hood?**
1.  You run `npm run dev`.
2.  `npm` executes the `vite` command.
3.  The Vite dev server starts up.
4.  It pre-bundles your dependencies using `esbuild` for extreme speed.
5.  It serves your source code over native ES Modules. When your browser requests a file (`/src/main.jsx`), Vite intercepts the request, transforms the file if necessary (e.g., JSX to JS), and serves it.
6.  It sets up a WebSocket connection for **Hot Module Replacement (HMR)**. When you save a file, Vite pushes the updated module to the browser, which swaps it in without a full page reload, preserving application state.

## `npm run build`

This script is used to create an optimized, production-ready build of your application.

**What's happening under the hood?**
1.  You run `npm run build`.
2.  `npm` executes the `vite build` command.
3.  Vite (or Webpack, if you're using `react-scripts`) reads your source code starting from the entry point (`index.html`).
4.  It performs a series of optimizations:
    - **Bundling:** It follows all `import` statements and combines your modules into a small number of JavaScript files ("chunks" or "bundles").
    - **Tree-Shaking:** It analyzes your code and removes any unused exports, making the final bundle smaller.
    - **Transpilation:** It might use a tool like Babel to convert modern JavaScript (and JSX) into an older version that is compatible with more browsers.
    - **Minification:** It removes all unnecessary characters from the code (whitespace, comments, renaming variables to be shorter) to drastically reduce file size.
    - **CSS Optimization:** It does the same for CSS files.
5.  The final, optimized static assets (HTML, JS, CSS files) are written to a `dist` (or `build`) directory. These are the files you would deploy to a web server.
