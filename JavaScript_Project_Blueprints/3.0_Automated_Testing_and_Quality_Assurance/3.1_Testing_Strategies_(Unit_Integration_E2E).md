# 3.1 Testing Strategies (Unit, Integration, E2E)

A robust testing strategy is essential for building reliable and maintainable applications. It's often visualized as the "Testing Pyramid."

## The Testing Pyramid

A model for grouping tests into buckets of different granularity.

```
      /======\
     /  E2E   \   (Slow, Expensive)
    /----------\
   / Integration\
  /--------------\
 /      Unit      \  (Fast, Cheap)
/==================\
```

### 1. Unit Tests (The Foundation)
- **Scope:** Tests the smallest possible unit of your application in isolation (e.g., a single function or React component).
- **Characteristics:**
    - **Fast:** They run in milliseconds.
    - **Isolated:** Dependencies are "mocked" or "stubbed" out. You don't talk to a real database or make real network requests.
    - **Numerous:** You should have many unit tests. They form the largest part of your test suite.
- **Example:** Given a `sum(a, b)` function, a unit test would assert that `sum(2, 3)` returns `5`. For a React component, you would test that it renders correctly given a certain set of props, without testing the child components it renders.

### 2. Integration Tests (The Middle)
- **Scope:** Tests how multiple units work together.
- **Characteristics:**
    - Slower than unit tests.
    - They might involve talking to a real (but controlled) service, like a test database or a mocked API server.
- **Example:** Testing a login form component. An integration test would simulate a user typing in the inputs, clicking the submit button, and verifying that the authentication service's `login` method was called with the correct arguments. It tests the integration between the form, the button, and the service module.

### 3. End-to-End (E2E) Tests (The Peak)
- **Scope:** Tests the entire application flow from the user's perspective.
- **Characteristics:**
    - **Slow:** They can take seconds or even minutes to run.
    - **Brittle:** They can fail due to minor UI changes.
    - **Few:** You should have only a few key E2E tests for your most critical user journeys.
- **Example:** An E2E test for an e-commerce site might:
    1.  Automate a real browser (like Chrome or Firefox).
    2.  Navigate to the homepage.
    3.  Search for a product.
    4.  Add the product to the cart.
    5.  Go to the checkout page.
    6.  Verify that the correct product and price are displayed.

A balanced testing strategy relies heavily on fast unit tests, has a good number of integration tests to verify that the units work together, and uses a few E2E tests as a final sanity check for critical paths.
