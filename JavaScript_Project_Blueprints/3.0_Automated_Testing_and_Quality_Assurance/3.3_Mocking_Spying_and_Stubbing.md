# 3.3 Mocking, Spying, and Stubbing

In testing, especially unit testing, you need to isolate the code you are testing from its dependencies. Mocks, spies, and stubs are different techniques for achieving this isolation. These are often collectively referred to as "Test Doubles."

Most major testing frameworks (like Jest and Vitest) have built-in support for creating these test doubles.

## Spies

A spy is a function that wraps another function, allowing you to "spy" on it. It records information about how the original function was used without changing its behavior.

- **Purpose:** To verify that a function was called, how many times it was called, and what arguments it was called with.
- **When to use:** When you want to check if a side effect occurred (e.g., a logger was called, an analytics event was sent) but you still want the original function to execute.

```javascript
// Example using Jest/Vitest
test('should call the logger', () => {
  const logger = { log: () => {} };
  const logSpy = vi.spyOn(logger, 'log'); // or jest.spyOn
  
  myFunctionThatLogs(logger);

  expect(logSpy).toHaveBeenCalledWith('Something was logged');
});
```

## Stubs

A stub is a function that completely replaces another function. It has a pre-programmed behavior.

- **Purpose:** To control the behavior of a dependency and force your code down a specific path.
- **When to use:** When you need to prevent a function from running (e.g., to avoid a real API call or database write) and you want to control what it returns.

```javascript
// Example using Jest/Vitest
test('should return users from the database', async () => {
  const db = { getUsers: async () => {} };
  // Replace db.getUsers with a stub that returns a fake user list
  vi.spyOn(db, 'getUsers').mockResolvedValue([{ id: 1, name: 'Alice' }]); // or jest.spyOn

  const users = await fetchUsers(db);

  expect(users).toEqual([{ id: 1, name: 'Alice' }]);
});
```

## Mocks

The term "mock" is often used interchangeably with "stub" or "spy," but it can also refer to a more complex object that is pre-programmed with expectations. Test frameworks often provide mock functions.

- **Purpose:** A mock function allows you to stub a function, spy on it, and define its implementation all at once.
- **When to use:** This is the most common tool you will use. You use it any time you need to provide a fake version of a function to the system under test.

```javascript
// Example using Jest/Vitest
test('should filter out odd numbers', () => {
  const myFilterCallback = vi.fn(num => num % 2 === 0); // or jest.fn()
  
  const result = [1, 2, 3, 4].filter(myFilterCallback);

  expect(result).toEqual([2, 4]);

  // You can also assert how the mock was used
  expect(myFilterCallback).toHaveBeenCalledTimes(4);
});
```
