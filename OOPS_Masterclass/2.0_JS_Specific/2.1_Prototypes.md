# 2.1 Prototypes: Under the Hood

In JavaScript, classes are "syntactic sugar" over **Prototypal Inheritance**. Every object has a hidden property called `[[Prototype]]` that points to another object.

## How it Works
When you try to access a property or method on an object:
1.  JS looks at the object itself.
2.  If not found, it looks at the object's **prototype**.
3.  It continues up the **Prototype Chain** until it finds the property or reaches `null`.

```javascript
function Person(name) {
  this.name = name;
}

// Adding a method to the prototype so it's shared by all instances
Person.prototype.greet = function() {
  console.log(`Hi, I'm ${this.name}`);
};

const p1 = new Person("Simanta");
p1.greet(); // Works!

console.log(Object.getPrototypeOf(p1) === Person.prototype); // true
```

## Class vs. Prototype
The `class` keyword (introduced in ES6) makes this easier to write, but it does the exact same thing behind the scenes.

```javascript
class Person {
  constructor(name) { this.name = name; }
  greet() { console.log(`Hi, I'm ${this.name}`); }
}
// Under the hood: greet() is added to Person.prototype
```

## Memory Efficiency
By putting methods on the prototype instead of inside the constructor, you save memory. If you create 1,000 objects, there is still only **one** copy of the method in memory.
