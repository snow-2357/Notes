# 4.1 Clean Architecture: Layered Design

In large projects, OOP is used to separate concerns into layers. This ensures that changing the database doesn't break your UI.

## The 3 Key Layers

### 1. Entities (The Core)
Pure data classes or domain models. They contain the business rules that are true even without a computer (e.g., a "User" must have an "Email").

### 2. Services / Use Cases
Contains the **Business Logic**. It orchestrates how entities interact.
**Example:** `RegisterUser` service checks if the user exists, hashes the password, and sends a welcome email.

### 3. Controllers / Adapters
The entry points. They handle the "Outside World" (HTTP requests, CLI inputs, File system). They translate external data into a format the Services understand.

## Code Structure Example
```javascript
// Entity
class User {
  constructor(email, password) {
    this.email = email;
    this.password = password;
  }
}

// Service (Business Logic)
class UserService {
  constructor(repo) { this.repo = repo; }
  
  async register(userData) {
    const user = new User(userData.email, userData.password);
    return await this.repo.save(user);
  }
}

// Controller (Express.js Example)
const userController = async (req, res) => {
  const service = new UserService(new DatabaseRepo());
  const result = await service.register(req.body);
  res.status(201).json(result);
};
```

## Why this matters?
*   **Independent of Database:** You can swap MongoDB for PostgreSQL by only changing the Repository.
*   **Independent of UI:** The same `UserService` can work for a Web App, a Mobile App, or a CLI tool.
*   **Testable:** You can test the `UserService` without actually starting a server or a database.
