# 4.2 Service-Repository Pattern

This is the most common OOP pattern in Backend development. It separates **HOW** data is stored from **WHAT** you do with it.

## 1. The Repository (The Data Layer)
Abstracts the database logic. It should look like a simple collection (like an Array).

```javascript
class UserRepository {
  async findById(id) {
    // Complex SQL: SELECT * FROM users WHERE id = ...
    return { id, name: "Simanta" };
  }
  async save(user) {
    // Complex SQL: INSERT INTO users ...
    console.log("User saved to DB");
  }
}
```

## 2. The Service (The Logic Layer)
Contains the business rules. It uses the Repository but doesn't know *which* database is being used.

```javascript
class UserService {
  constructor(userRepo) {
    this.userRepo = userRepo;
  }

  async getUserProfile(id) {
    const user = await this.userRepo.findById(id);
    if (!user) throw new Error("User not found");
    
    // Additional logic: transform data, check permissions
    return { ...user, viewedAt: new Date() };
  }
}
```

## 3. Implementation Flow
1.  **Request** hits the **Controller**.
2.  **Controller** calls the **Service**.
3.  **Service** calls the **Repository**.
4.  **Repository** talks to the **Database**.

## Benefits
*   **Cleanliness:** No SQL queries inside your business logic.
*   **Reusability:** Multiple services can use the same Repository.
*   **Mocking:** During testing, you can pass a "FakeRepository" to the Service to avoid hitting a real DB.
