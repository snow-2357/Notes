# 4.3 Dependency Injection (DI)

Dependency Injection is a technique where an object receives other objects that it depends on, instead of creating them itself.

## The Problem: Hardcoded Dependencies
If a Service creates its own Repository, you cannot easily test it.

```javascript
class UserService {
  constructor() {
    this.repo = new SQLRepository(); // ❌ Hardcoded!
  }
}
```

## The Solution: Injection
Pass the dependency through the constructor.

```javascript
class UserService {
  constructor(repo) {
    this.repo = repo; // ✅ Injected!
  }

  doSomething() {
    this.repo.getData();
  }
}

// Production: Use real DB
const service = new UserService(new RealDatabaseRepo());

// Testing: Use Mock (Fake) DB
const mockRepo = { getData: () => "Fake Data" };
const testService = new UserService(mockRepo);
```

## Why use DI?
1.  **Decoupling:** The Service doesn't care how the Repository is built.
2.  **Testability:** You can "mock" dependencies to test a single class in isolation.
3.  **Flexibility:** You can swap implementations at runtime.

## In Modern JS
Frameworks like **NestJS** automate this using Decorators, but the core principle is always this: **Don't use `new` inside your business logic; pass the instance in.**
