# 1.2 Abstraction: Hiding Complexity

Abstraction is about showing only the **essential features** of an object and hiding the complex implementation details.

## The Concept
Think of a Coffee Machine. You only see the buttons: "Espresso", "Latte", "Power". You don't see the boiler, the water pump, or the bean grinder. You just press a button and get coffee.

## Code Example: An Email Service
Without abstraction, the user would have to handle connection, authentication, and protocols manually.

```javascript
class EmailService {
  // Private methods (The "Complex Machinery")
  #connect() { console.log("Connecting to SMTP..."); }
  #authenticate() { console.log("Authenticating credentials..."); }
  #disconnect() { console.log("Disconnecting..."); }

  // Public method (The "Button")
  sendEmail(to, message) {
    this.#connect();
    this.#authenticate();
    console.log(`Sending: [${message}] to [${to}]`);
    this.#disconnect();
  }
}

const mailer = new EmailService();
mailer.sendEmail("user@example.com", "Hi there!"); 
// ✅ Simple! The user doesn't know (or care) how connection works.
```

## Why use Abstraction?
1.  **Reduces Complexity:** Users don't need to understand the whole system to use one part of it.
2.  **Reduces Impact of Change:** If you change your SMTP server logic, the `sendEmail` button remains the same for the user.
3.  **Improved Security:** Only exposes necessary parts of the system.
