# 1.1 Encapsulation: State Management

Encapsulation is the bundling of data and the methods that act on that data. It also involves restricting direct access to some of an object's components.

## The Problem: Data Corruption
If an object's data is public, external code can change it in ways it shouldn't.

```javascript
class User {
  constructor(name, age) {
    this.name = name;
    this.age = age;
  }
}

const user = new User("John", 25);
user.age = -500; // ❌ This makes no sense, but nothing stops it!
```

## The Solution: Private Fields & Validation
By using **Private Fields** (`#`), we ensure that internal data can only be changed via methods that include validation logic.

```javascript
class SecureUser {
  #age; // Private field (Cannot be accessed outside the class)

  constructor(name, age) {
    this.name = name;
    this.setAge(age);
  }

  // Getter: Read-only access or formatted access
  get age() {
    return `${this.#age} years old`;
  }

  // Setter: Logic to control how data is changed
  setAge(newAge) {
    if (newAge > 0 && newAge < 120) {
      this.#age = newAge;
    } else {
      console.error("Invalid age provided!");
    }
  }
}

const user = new SecureUser("John", 25);
user.setAge(-500); // ❌ Error logged, #age remains 25.
console.log(user.age); // ✅ "25 years old"
```

## Key Benefits
*   **Controlled Access:** You decide who can read or write data.
*   **Validation:** You can check data integrity *before* it gets saved.
*   **Refactoring:** You can change internal logic without breaking external code.
