# 6.3 Performance and Styling in React

## Leveraging `useCallback` and `useMemo` for Performance Optimization

In React, unnecessary re-renders are a common cause of performance bottlenecks. The `useCallback` and `useMemo` hooks are powerful tools to prevent these re-renders by memoizing functions and values, respectively.

### `useCallback` (Memoizing Functions)

**Purpose:** `useCallback` returns a memoized version of the callback function that only changes if one of the `dependencies` has changed. This is particularly useful when passing callbacks to optimized child components that rely on reference equality to prevent unnecessary re-renders (e.g., `React.memo` components).

**When to use `useCallback`:**

1.  **Passing callbacks to `React.memo` children:** If a child component is wrapped in `React.memo` (or extends `PureComponent`), it will only re-render if its props change. If a parent component re-renders, and it passes a new *function instance* (even if the function's logic is the same) to the child on every re-render, the `React.memo` child will re-render unnecessarily. `useCallback` prevents this by ensuring the same function instance is passed as long as its dependencies haven't changed.
2.  **Referential equality in `useEffect` dependencies:** Sometimes, a function is a dependency in a `useEffect` hook. If that function is re-created on every render, it can cause the `useEffect` to run unnecessarily. Wrapping it in `useCallback` can stabilize its reference.
3.  **Optimization for very expensive calculations:** If a function performs a very heavy, synchronous calculation and is called frequently, memoizing it might provide a slight benefit, though this is less common than the first two use cases.

**Example:**

```javascript
import React, { useState, useCallback } from 'react';

// Optimized child component (e.g., a button that doesn't need to re-render unless its props change)
const MemoizedButton = React.memo(({ onClick, label }) => {
  console.log(`Rendering MemoizedButton: ${label}`);
  return <button onClick={onClick}>{label}</button>;
});

function ParentComponent() {
  const [count, setCount] = useState(0);
  const [text, setText] = useState('');

  // This function will only be re-created if 'count' changes
  const handleClick = useCallback(() => {
    setCount(prevCount => prevCount + 1);
  }, [count]); // Dependency array

  // This function will be re-created on every render (due to 'text' changing)
  // const handleInputChange = (e) => {
  //   setText(e.target.value);
  // };

  // This function will only be re-created if 'text' changes
  const handleInputChange = useCallback((e) => {
    setText(e.target.value);
  }, [text]);


  return (
    <div>
      <p>Count: {count}</p>
      <MemoizedButton onClick={handleClick} label="Increment Count" />
      <input type="text" value={text} onChange={handleInputChange} />
      <p>Text: {text}</p>
    </div>
  );
}
```

### `useMemo` (Memoizing Values)

**Purpose:** `useMemo` returns a memoized value. It only recomputes the memoized value when one of the `dependencies` has changed. This optimization helps to avoid expensive calculations on every render.

**When to use `useMemo`:**

1.  **Expensive calculations:** When you have a function that performs a complex, time-consuming calculation, and you don't need to re-run it unless its inputs change.
2.  **Referential equality for object/array props:** Similar to `useCallback`, if you're passing an object or array literal as a prop to a `React.memo` child, that object/array will be a new instance on every render, causing the child to re-render. `useMemo` can memoize these objects/arrays to maintain referential equality.
3.  **Derived state:** When you derive a value from existing state or props, and that derivation is computationally expensive.

**Example:**

```javascript
import React, { useState, useMemo } from 'react';

function ProductList({ products, filter }) {
  const [search, setSearch] = useState('');

  // This is an expensive calculation that should only re-run if 'products' or 'filter' changes
  const filteredProducts = useMemo(() => {
    console.log('Filtering products...');
    return products.filter(product =>
      product.name.includes(search) && product.category === filter
    );
  }, [products, search, filter]); // Dependencies

  return (
    <div>
      <input
        type="text"
        value={search}
        onChange={(e) => setSearch(e.target.value)}
        placeholder="Search products"
      />
      <h2>Filtered Products ({filteredProducts.length})</h2>
      <ul>
        {filteredProducts.map(product => (
          <li key={product.id}>{product.name} ({product.category})</li>
        ))}
      </ul>
    </div>
  );
}
```

### Important Considerations for `useCallback` and `useMemo`:

*   **Don't overuse:** Memoization comes with its own overhead (memory for storing previous values, and the cost of comparison in the dependency array). Use them judiciously for genuinely expensive computations or to prevent unnecessary re-renders of `React.memo` components.
*   **Correct dependency arrays:** Incorrect dependency arrays are a common source of bugs. If a memoized function or value relies on a variable that changes but isn't in the dependency array, it will use a stale value.
*   **Referential equality:** Both hooks work based on referential equality. If a dependency is an object or array created inline, it will always be considered "new" unless it's also memoized.

## The Advantage of One CSS Library and One Theme

Maintaining a consistent and scalable design system in a React application is crucial for user experience, developer efficiency, and long-term project health. Adopting a strategy of **one primary CSS library/framework** and enforcing **one cohesive theme** provides significant benefits.

### Benefits of a Single CSS Library/Framework:

1.  **Consistency:** Ensures a unified visual language across the entire application. All components adhere to the same styling principles, reducing design drift.
2.  **Reduced Bundle Size:** Avoids the overhead of including multiple large CSS frameworks or libraries, each with their own styling paradigms and utility classes.
3.  **Simplified Maintenance:** Developers only need to learn and maintain one set of styling conventions, reducing cognitive load and simplifying debugging.
4.  **Improved Collaboration:** A single source of truth for styling fosters better collaboration among designers and developers, ensuring everyone speaks the same visual language.
5.  **Easier Theming/Customization:** When a single library is used, applying a custom theme or making global style adjustments is much simpler and more predictable. Overriding styles from multiple libraries can be a nightmare.
6.  **Performance:** Fewer CSS files and clearer cascade rules can lead to faster rendering and fewer layout shifts.

**Examples of popular CSS approaches in React:**

*   **Utility-first CSS (e.g., Tailwind CSS):** Rapid development, highly customizable, but can lead to long class lists in JSX.
*   **CSS-in-JS (e.g., Styled Components, Emotion):** Encapsulated styles, dynamic theming, component-oriented, but can have a runtime performance cost.
*   **Component Libraries (e.g., Material UI, Ant Design, Chakra UI):** Provides pre-built, accessible components, speeding up development, but can be opinionated.

The choice of library depends on project needs, but the principle remains: **choose one and stick to it.**

### Benefits of One Cohesive Theme:

A theme defines the visual attributes of your application (colors, typography, spacing, shadows, etc.). Having one cohesive theme, ideally managed through a dedicated theming system (e.g., using CSS variables, a ThemeProvider from a CSS-in-JS library, or a utility-first configuration), offers:

1.  **Brand Consistency:** Ensures all visual elements align with your brand guidelines.
2.  **Dark/Light Mode Support:** Easier to implement and manage consistent dark/light mode switching.
3.  **Accessibility:** Centralized control over colors and typography makes it simpler to meet accessibility standards.
4.  **Rapid Design Changes:** Global style changes (e.g., changing primary color) can be applied universally from a single point of configuration.
5.  **Developer Efficiency:** Developers can quickly apply consistent styles without guessing hex codes or pixel values.

In summary, strategic use of `useCallback` and `useMemo` tackles performance by preventing unnecessary re-renders, while a disciplined approach to styling with a single CSS library and a cohesive theme ensures maintainability, consistency, and a better user experience in your React applications.
