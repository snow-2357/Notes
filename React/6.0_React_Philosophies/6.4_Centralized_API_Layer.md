# 6.4 Centralized API Layer and TanStack Query

## Building a Robust Centralized API Layer

In any non-trivial React application, managing data fetching, caching, error handling, and loading states effectively is paramount. A well-designed, centralized API layer simplifies these concerns, leading to cleaner, more maintainable, and robust code.

### The Problem with Decentralized API Calls:

Without a centralized API layer, it's common to see API calls scattered throughout components, often leading to:

*   **Duplication:** Similar fetching logic (e.g., error handling, authentication headers) repeated across multiple components.
*   **Inconsistency:** Variations in error handling, loading states, and data transformation.
*   **Maintainability Nightmares:** Changes to API endpoints or error structures require widespread modifications.
*   **Hard to Test:** Testing individual components becomes harder as API calls are tightly coupled.
*   **Prop Drilling of Status:** Loading and error states often have to be "prop drilled" down through components.

### Benefits of a Centralized API Layer:

A centralized API layer acts as a single point of contact between your frontend and backend. It typically involves:

1.  **Shared HTTP Client Configuration:** Configure a single instance of an HTTP client (e.g., `axios`, `fetch` with wrappers) with base URLs, headers (e.g., `Authorization` tokens), timeouts, etc.
2.  **Common API Controller/Wrapper:** This is the core of the centralized layer. It provides utility functions to make API requests and handles all common concerns **other than successful data transformation**:
    *   **Loading State Management:** Automatically sets and resets a global or request-specific loading state.
    *   **Error Handling:** Catches network errors, HTTP error codes (4xx, 5xx), and API-specific error structures. It can:
        *   Show global error notifications (toasts/modals).
        *   Log errors to a central logging service.
        *   Perform automatic retries for transient errors.
        *   Handle specific status codes (e.g., redirect to login for 401 Unauthorized, show a "server down" page for 5xx).
    *   **Authentication/Authorization:** Automatically attaches authentication tokens to requests and handles token refresh logic.
    *   **Request/Response Interceptors:** Modify requests before they are sent or responses before they are returned to the calling component (e.g., logging, data serialization/deserialization).
    *   **Type Safety:** When using TypeScript, this layer can ensure that both request payloads and response data adhere to predefined interfaces.

**Example Structure (conceptual):**

```javascript
// apiService.ts
import axios from 'axios';

const api = axios.create({
  baseURL: process.env.REACT_APP_API_BASE_URL || '/api',
  headers: {
    'Content-Type': 'application/json',
  },
  timeout: 10000,
});

// Request Interceptor (e.g., attach auth token)
api.interceptors.request.use(
  (config) => {
    const token = localStorage.getItem('authToken'); // Or get from Context/Redux
    if (token) {
      config.headers.Authorization = `Bearer ${token}`;
    }
    return config;
  },
  (error) => Promise.reject(error)
);

// Response Interceptor (e.g., global error handling, token refresh)
api.interceptors.response.use(
  (response) => response, // Pass successful responses through
  async (error) => {
    // Example: Handle 401 Unauthorized globally
    if (error.response && error.response.status === 401) {
      // Potentially refresh token, then retry request, or redirect to login
      console.error('Unauthorized request, redirecting to login...');
      // window.location.href = '/login'; // Example: redirect
    }
    // Example: Log other errors
    console.error('API Error:', error.response?.data || error.message);
    // Show a global toast notification for generic errors
    // toast.error(error.response?.data?.message || 'An unexpected error occurred');

    return Promise.reject(error); // Re-throw the error so component can handle specific cases
  }
);

// Specific API calls using the configured instance
export const getUsers = () => api.get('/users');
export const getUserById = (id: string) => api.get(`/users/${id}`);
export const createUser = (userData) => api.post('/users', userData);
// ... more API endpoints
```

## Why TanStack Query (React Query) over Custom API Hooks?

Even with a centralized API layer, managing the *state* of asynchronous data (loading, error, success, caching, refetching) within individual components can become complex. This is where a dedicated data fetching library like TanStack Query (formerly React Query) shines.

### Problems with Custom `useApiCall` Hooks:

While creating custom hooks like `useFetchUsers` can abstract away basic fetching logic, they often reinvent:

*   **Caching:** Manually implementing efficient client-side caching (stale-while-revalidate, garbage collection) is hard.
*   **Background Refetching:** Handling data invalidation, refetching on window focus, or retry logic.
*   **Synchronization:** Ensuring all instances of a hook fetch the same data only once, and keeping them updated.
*   **Deduping:** Preventing multiple simultaneous identical requests.
*   **Pagination & Infinite Scroll:** Managing these patterns robustly.

### Advantages of TanStack Query:

TanStack Query provides a powerful, declarative, and highly optimized way to manage server state in your React applications. It integrates seamlessly with a centralized API layer.

1.  **Automatic Caching & Data Synchronization:** Out-of-the-box caching with sensible defaults (stale-while-revalidate), automatic background refetching, and intelligent data synchronization across all components using the same query key.
2.  **Simplified Loading & Error States:** Provides `isLoading`, `isError`, `data`, `error` directly from the `useQuery` hook, making it trivial to display UI based on server state.
3.  **Built-in Optimizations:** Request deduping, retries, garbage collection of unused data, prefetching, and more, all handled automatically.
4.  **Excellent Developer Experience:** Devtools for inspecting queries, mutations, and cache.
5.  **Declarative API:** Define your data requirements, and TanStack Query handles the "how" of fetching and managing that data.
6.  **Mutations:** `useMutation` hook for updating server data, with optimistic updates and automatic query invalidation.
7.  **Server State Management:** It elegantly separates "server state" (data fetched from an API) from "client state" (UI state like modal open/close), which often gets conflated in custom hooks.

**Integration Example:**

```javascript
// In apiService.ts (as above)
export const getUsers = async () => {
  const { data } = await api.get('/users');
  return data;
};

// In a React Component
import { useQuery } from '@tanstack/react-query';
import { getUsers } from './apiService'; // Your centralized API service

function UserList() {
  const { data: users, isLoading, isError, error } = useQuery({
    queryKey: ['users'], // Unique key for this query
    queryFn: getUsers, // Function that fetches the data
  });

  if (isLoading) return <div>Loading users...</div>;
  if (isError) return <div>Error: {error.message}</div>;

  return (
    <div>
      <h1>Users</h1>
      <ul>
        {users.map(user => (
          <li key={user.id}>{user.name}</li>
        ))}
      </ul>
    </div>
  );
}
```

By combining a robust, centralized API layer (handling common request/response logic) with a specialized server state management library like TanStack Query, you can build highly performant, resilient, and maintainable React applications with significantly reduced boilerplate and increased developer productivity.
