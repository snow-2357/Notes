# React `useEffect` – Multiple API Calls

## 1. Problem
An API call inside `useEffect` can run **multiple times unexpectedly**, especially when the dependency array includes values like:

- `id`
- `page`
- `filters` (object)

```ts
useEffect(() => {
  fetchData(id, page, filters);
}, [id, page, filters]);

2. Why Multiple API Calls Happen
3. Multiple dependency updates
If dependencies update separately:

ts
Copy code
setPage(1);
setFilters(newFilters);
Each update causes a re-render

useEffect runs once per render

2. Objects in dependency array (most common issue)
ts
Copy code
setFilters({ category: "shoes" });
Objects are compared by reference

New object = new reference

Effect runs again even if values are the same

3. React 18 Strict Mode (development only)
useEffect runs twice on mount in dev

Used to detect side effects

Production runs only once

4. State updates inside useEffect
ts
Copy code
useEffect(() => {
  fetchData();
  setPage(1);
}, [filters]);
Flow:

filters changes → effect runs

setPage triggers re-render

page change triggers effect again

3. How to Prevent Multiple API Calls
4. Memoize objects with useMemo
ts
Copy code
const filters = useMemo(() => ({
  category,
  priceRange,
}), [category, priceRange]);
Stable reference

Effect runs only when values change

2. Debounce filters (best for search)
ts
Copy code
const debouncedFilters = useDebounce(filters, 500);

useEffect(() => {
  fetchData(id, page, debouncedFilters);
}, [id, page, debouncedFilters]);
Prevents rapid API calls

3. Combine related state into one object
ts
Copy code
const [query, setQuery] = useState({
  id,
  page,
  filters
});

useEffect(() => {
  fetchData(query);
}, [query]);
One render → one API call

4. Guard the effect manually
ts
Copy code
const prevKeyRef = useRef("");

useEffect(() => {
  const key = JSON.stringify({ id, page, filters });
  if (prevKeyRef.current === key) return;

  prevKeyRef.current = key;
  fetchData(id, page, filters);
}, [id, page, filters]);
Prevents duplicate calls

5. Cancel previous requests
ts
Copy code
useEffect(() => {
  const controller = new AbortController();

  fetch(url, { signal: controller.signal });

  return () => controller.abort();
}, [id, page, filters]);
Prevents race conditions

Avoids stale responses

4. Best Practice (Industry Standard)
Use React Query / TanStack Query
ts
Copy code
useQuery({
  queryKey: ["products", id, page, filters],
  queryFn: fetchProducts,
});
Benefits:

Automatic caching

Request deduplication

Cancel stale requests

No manual useEffect

5. When to Use What
Scenario	Recommendation
Simple fetch	useEffect
Filters + pagination	Debounced useEffect
Frequent updates	React Query
Global async data	React Query / Redux

6. Interview One-Liner
APIs can be called multiple times in useEffect because dependencies update separately, objects change by reference, or React Strict Mode runs effects twice in development. This is solved using memoization, debouncing, request cancellation, or libraries like React Query.
