# 4.2 Redux Overview

Redux is a predictable state container for JavaScript applications. It helps you write applications that behave consistently, run in different environments (client, server, and native), and are easy to test. On top of that, it provides a great developer experience, such as live code editing combined with a time-travel debugger.

While Redux can be used with any UI layer, it's most commonly used with React.

## Three Core Principles of Redux:

1.  **Single Source of Truth:** The entire application's state is stored in a single object tree within a single *store*. This makes it easy to debug and inspect the application's state.
2.  **State is Read-Only:** The only way to change the state is to emit an *action*, an object describing what happened. This ensures that the UI and network callbacks don't write directly to state, preventing race conditions and hard-to-reproduce bugs.
3.  **Changes are Made with Pure Functions:** To specify how the state tree is transformed by actions, you write pure *reducers*. Reducers are functions that take the current state and an action as arguments, and return a *new* state. They must not mutate the original state.

## Redux Flow (The Cycle):

1.  **View Dispatches an Action:** A user interaction (e.g., clicking a button) or an event triggers the dispatch of an action.
    *   **Actions:** Plain JavaScript objects that have a `type` field (a string constant) indicating the type of action performed. They can also carry data.
        ```javascript
        {
          type: 'ADD_TODO',
          payload: {
            id: 1,
            text: 'Learn Redux'
          }
        }
        ```
    *   **Action Creators:** Functions that create and return actions.
        ```javascript
        function addTodo(text) {
          return {
            type: 'ADD_TODO',
            payload: {
              id: nextTodoId++,
              text
            }
          };
        }
        ```
2.  **Middleware (Optional):** Actions can optionally pass through middleware (e.g., Redux Thunk, Redux Saga) before reaching the reducers. Middleware can intercept, modify, delay, or asynchronously dispatch actions. This is often used for side effects like API calls.
3.  **Reducer Updates State:** The action reaches the reducer, which is a pure function that takes the current state and the action, and returns a new state object.
    *   Reducers should *never* mutate the original state. Instead, they should return new state objects (e.g., using spread syntax `...`).
    ```javascript
    function todosReducer(state = [], action) {
      switch (action.type) {
        case 'ADD_TODO':
          return [
            ...state,
            {
              id: action.payload.id,
              text: action.payload.text,
              completed: false
            }
          ];
        case 'TOGGLE_TODO':
          return state.map(todo =>
            todo.id === action.payload.id ? { ...todo, completed: !todo.completed } : todo
          );
        default:
          return state;
      }
    }
    ```
4.  **Store Notifies Subscribers:** After the root reducer combines all individual reducers and updates the state, the Redux store notifies all subscribed UI components.
    *   **Store:** Holds the application state, allows access to state via `getState()`, allows state to be updated via `dispatch(action)`, and registers listeners via `subscribe(listener)`.
5.  **View Re-renders:** React components connected to the store detect changes in the parts of the state they care about and re-render with the new data.

## Key Redux Components:

*   **Store:** The single source of truth for your application's state.
*   **Actions:** Objects that describe what happened.
*   **Reducers:** Pure functions that specify how the application's state changes in response to actions.
*   **Middleware:** Extends Redux's capabilities (e.g., for async operations, logging).
*   **Selectors:** Functions used to extract specific pieces of data from the Redux store state. They can also derive computed data.

## Redux with React (`react-redux`):

The `react-redux` library provides official React bindings for Redux.

*   **`<Provider store>`:** A component that wraps your entire React application and makes the Redux store available to all connected components.
*   **`useSelector` Hook:** Allows functional components to extract data from the Redux store state.
*   **`useDispatch` Hook:** Returns a reference to the `dispatch` function from the Redux store, allowing functional components to dispatch actions.

## Redux Toolkit (RTK):

Redux Toolkit is the official, opinionated, batteries-included toolset for efficient Redux development. It simplifies common Redux tasks and reduces boilerplate.

Key features of RTK:
*   **`configureStore`:** Simplifies store setup with good defaults.
*   **`createSlice`:** Automatically generates action creators and action types, and a reducer based on a slice of state and a set of reducers.
*   **`createAsyncThunk`:** Simplifies handling async logic (like API calls).
*   **`createEntityAdapter`:** Helps manage normalized state (collections of items) more easily.

**Modern Redux development strongly encourages the use of Redux Toolkit.**

## When to Use Redux:
Redux is a powerful tool, but it adds overhead. Consider using it when:
*   You have a large application with complex global state requirements.
*   State changes frequently and needs to be synchronized across many parts of the application.
*   You need powerful developer tools for debugging and time-traveling.
*   You have a large team and need strict conventions for state management.

For simpler applications, `useState`/`useReducer` combined with `useContext` might be sufficient.
