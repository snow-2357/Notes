# 2.1 Introduction to Hooks

React Hooks, introduced in React 16.8, are functions that let you "hook into" React state and lifecycle features from function components. They allow you to use state and other React features without writing a class.

## Why Hooks?
Before Hooks, stateful logic and lifecycle features were primarily available in class components. Hooks solve several problems:

1.  **Reusing Stateful Logic:** Hooks allow you to extract stateful logic from a component so it can be tested independently and reused. This makes it easier to share logic between components without complex patterns like Higher-Order Components (HOCs) or Render Props.
2.  **Complex Components:** Class components can become hard to understand due to `this` keyword, method binding, and the way related logic is split across different lifecycle methods. Hooks organize logic based on what's related (e.g., setting up a subscription and cleaning it up) rather than a lifecycle method name.
3.  **Classes are Confusing:** JavaScript classes can be a barrier for new learners, and they don't always align with the functional programming paradigm that React often encourages. Hooks provide a more functional approach to component development.

## Rules of Hooks:
There are two main rules to follow when using Hooks:

1.  **Only Call Hooks at the Top Level:** Don’t call Hooks inside loops, conditions, or nested functions. This ensures that Hooks are called in the same order each time a component renders, which is crucial for React to correctly associate local state with each component.
2.  **Only Call Hooks from React Function Components or Custom Hooks:** Don’t call Hooks from regular JavaScript functions. You can call Hooks from custom Hooks (which we'll cover later) or from React function components.

## Common Built-in Hooks:
*   `useState`: For adding state to function components.
*   `useEffect`: For performing side effects in function components (data fetching, subscriptions, manual DOM manipulation).
*   `useContext`: For subscribing to React context without introducing nesting.
*   `useReducer`: An alternative to `useState` for more complex state logic.
*   `useCallback`: For memoizing functions to prevent unnecessary re-renders.
*   `useMemo`: For memoizing values to prevent expensive recalculations.
*   `useRef`: For creating mutable `ref` objects that persist across renders.
