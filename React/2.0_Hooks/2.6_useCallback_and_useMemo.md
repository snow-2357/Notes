# 2.6 `useCallback` and `useMemo` Hooks (Memoization)

`useCallback` and `useMemo` are optimization Hooks in React. They help prevent unnecessary re-renders of components and recalculations of expensive values, leading to better performance in certain scenarios. Both are forms of "memoization," a technique that caches the result of a function call and returns the cached result when the same inputs occur again.

## 2.6.1 `useCallback`

`useCallback` returns a memoized callback function. It's useful when passing callbacks to optimized child components that rely on reference equality to prevent unnecessary renders (e.g., `React.memo`).

**Signature:** `const memoizedCallback = useCallback(fn, dependencies);`

*   `fn`: The function to be memoized.
*   `dependencies`: An array of values that the `fn` depends on. The callback will only re-create if one of these dependencies changes.

**Problem `useCallback` solves:**
In React, when a parent component re-renders, all its child components also re-render by default. If a child component is optimized using `React.memo` (which prevents re-renders if its props haven't changed), and a prop it receives is a callback function, that callback function is re-created on every parent re-render. Since JavaScript functions are objects, a new function means a new reference, causing `React.memo` to see a "changed" prop and re-render the child unnecessarily.

**Example:**
```jsx
import React, { useState, useCallback, memo } from 'react';

// Optimized child component (will only re-render if its props change)
const Button = memo(({ onClick, children }) => {
  console.log('Button rendered:', children);
  return <button onClick={onClick}>{children}</button>;
});

function ParentComponent() {
  const [count, setCount] = useState(0);
  const [name, setName] = useState('Alice');

  // This function will be re-created on every render of ParentComponent
  // const handleClickNormal = () => {
  //   setCount(count + 1);
  // };

  // This function is memoized. It will only be re-created if 'count' changes.
  const handleClickMemoized = useCallback(() => {
    setCount(count + 1);
  }, [count]); // Dependency array: recreate if count changes

  // This function is memoized and will only be re-created if 'name' changes.
  const handleNameChange = useCallback(() => {
    setName(name === 'Alice' ? 'Bob' : 'Alice');
  }, [name]);


  return (
    <div>
      <p>Count: {count}</p>
      <p>Name: {name}</p>
      {/* Button will re-render even if 'name' changes, because handleClickNormal is new */}
      {/* <Button onClick={handleClickNormal}>Increment (Normal)</Button> */}

      {/* Button will only re-render if 'count' changes (because handleClickMemoized's reference is stable) */}
      <Button onClick={handleClickMemoized}>Increment (Memoized)</Button>

      <Button onClick={handleNameChange}>Change Name</Button> {/* This button will cause "Increment (Memoized)" to re-render IF handleClickMemoized wasn't memoized */}
      <button onClick={() => console.log('Parent re-rendered')}>Re-render Parent</button>
    </div>
  );
}
```
In this example, `handleClickMemoized` will only be re-created when `count` changes. If `ParentComponent` re-renders due to `name` changing, `handleClickMemoized` will retain its reference, and the `Button` component (wrapped in `memo`) will not unnecessarily re-render.

## 2.6.2 `useMemo`

`useMemo` returns a memoized value. It's useful for optimizing expensive calculations that you don't want to re-run on every render if the inputs to those calculations haven't changed.

**Signature:** `const memoizedValue = useMemo(() => computeExpensiveValue(a, b), [a, b]);`

*   `() => computeExpensiveValue(a, b)`: A function that returns the value to be memoized.
*   `[a, b]`: An array of dependencies. The `computeExpensiveValue` function will only re-run if one of these dependencies changes.

**Problem `useMemo` solves:**
If you have a computationally expensive function that runs during render, and its result is only needed if certain inputs change, `useMemo` can prevent that function from running on every render.

**Example:**
```jsx
import React, { useState, useMemo } from 'react';

function ExpensiveCalculation({ num }) {
  const expensiveFunction = (number) => {
    console.log('Performing expensive calculation...');
    let result = 0;
    for (let i = 0; i < 1000000000; i++) { // Simulate expensive calculation
      result += number;
    }
    return result;
  };

  // The expensive calculation will only re-run if 'num' changes.
  const memoizedResult = useMemo(() => expensiveFunction(num), [num]);

  return (
    <div>
      <p>Number: {num}</p>
      <p>Result of expensive calculation: {memoizedResult}</p>
    </div>
  );
}

function App() {
  const [value, setValue] = useState(1);
  const [toggle, setToggle] = useState(false);

  return (
    <div>
      <input
        type="number"
        value={value}
        onChange={(e) => setValue(parseInt(e.target.value))}
      />
      <button onClick={() => setToggle(!toggle)}>Toggle Re-render</button>
      <p>Toggle state: {toggle ? 'On' : 'Off'}</p>

      <ExpensiveCalculation num={value} />
    </div>
  );
}
```
In this example, `expensiveFunction` will only execute when the `num` prop changes. If the `App` component re-renders because `toggle` changes, `memoizedResult` will return the cached value, and `expensiveFunction` will not be called again.

## Key Differences and When to Use Which:
*   **`useCallback`**: Memoizes a **function**. Use it when you need to prevent a function prop from causing unnecessary re-renders of child components (especially those wrapped in `React.memo`).
*   **`useMemo`**: Memoizes a **value**. Use it when you have an expensive calculation that you want to avoid re-running on every render if its dependencies haven't changed.

**Important Note on Dependencies:**
For both `useCallback` and `useMemo`, it is crucial to correctly specify the dependency array. If you omit a dependency that is used inside the memoized function or value, you might encounter bugs where the memoized item uses a stale value from a previous render. The React linter (`eslint-plugin-react-hooks`) often helps catch missing dependencies.

**When to avoid memoization:**
Don't use these Hooks everywhere. Memoization adds a slight overhead. Only use them when profiling shows a performance bottleneck caused by unnecessary re-renders or expensive calculations. For simple components or cheap calculations, the overhead might outweigh the benefits.
