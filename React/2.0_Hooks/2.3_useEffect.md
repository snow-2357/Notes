# 2.3 `useEffect` Hook

The `useEffect` Hook lets you perform side effects in functional components. Side effects include data fetching, subscriptions, manually changing the DOM, timers, logging, etc. It serves the same purpose as `componentDidMount`, `componentDidUpdate`, and `componentWillUnmount` in React class components, but unified into a single API.

## Basic Usage:
`useEffect` accepts two arguments:
1.  **A function:** This is the effect itself, where you put your side effect logic.
2.  **An optional dependency array:** This array tells React when to re-run the effect.

```jsx
import React, { useState, useEffect } from 'react';

function MyComponent() {
  const [count, setCount] = useState(0);

  // Effect runs after every render
  useEffect(() => {
    document.title = `You clicked ${count} times`;
  });

  return (
    <div>
      <p>You clicked {count} times</p>
      <button onClick={() => setCount(count + 1)}>
        Click me
      </button>
    </div>
  );
}
```

## Cleanup Function:
Some side effects require cleanup (e.g., unsubscribing, clearing timers). The function passed to `useEffect` can return a cleanup function. React will run this cleanup function when the component unmounts, and before re-running the effect due to changes in dependencies.

```jsx
import React, { useState, useEffect } from 'react';

function FriendStatus(props) {
  const [isOnline, setIsOnline] = useState(null);

  useEffect(() => {
    function handleStatusChange(status) {
      setIsOnline(status.isOnline);
    }
    ChatAPI.subscribeToFriendStatus(props.friend.id, handleStatusChange);

    // Specify how to clean up after this effect:
    return function cleanup() {
      ChatAPI.unsubscribeFromFriendStatus(props.friend.id, handleStatusChange);
    };
  }, [props.friend.id]); // Re-run if props.friend.id changes

  if (isOnline === null) {
    return 'Loading...';
  }
  return isOnline ? 'Online' : 'Offline';
}
```

## When Does `useEffect` Run? (Dependency Array):

The second argument to `useEffect` is the dependency array, which is crucial for controlling when the effect re-runs.

1.  **No dependency array:**
    ```jsx
    useEffect(() => {
      // Runs after *every* render (initial and all updates)
    });
    ```
    This is rarely what you want for effects that have cleanup or involve external resources, as it can lead to performance issues or infinite loops.

2.  **Empty dependency array `[]`:**
    ```jsx
    useEffect(() => {
      // Runs once after the initial render (like componentDidMount)
      // Cleans up when the component unmounts (like componentWillUnmount)
      return () => {
        // Cleanup logic
      };
    }, []);
    ```
    Useful for effects that only need to run once, like initial data fetching or setting up event listeners that don't depend on props or state that changes.

3.  **Dependency array with values `[prop1, state1]`:**
    ```jsx
    useEffect(() => {
      // Runs after the initial render
      // Runs again whenever any value in the array changes
      // Cleans up before re-running and on unmount
      return () => {
        // Cleanup logic
      };
    }, [prop1, state1]);
    ```
    This is the most common use case. React will re-run the effect if `prop1` or `state1` (or both) have changed between renders. **Always include all values from your component scope (props and state) that the effect depends on in this array.** If you omit a dependency that the effect uses, your effect will "see" a stale value from a previous render, leading to bugs.

## Common Mistakes with `useEffect`:
*   **Forgetting dependencies:** Not including all values used inside the effect in the dependency array can lead to stale closures and bugs where the effect operates on outdated data.
*   **Including unnecessary dependencies:** Including functions or objects that are re-created on every render (and are not memoized) can cause the effect to run too often. Use `useCallback` or `useMemo` for these cases.
*   **Infinite loops:** For example, setting state inside `useEffect` without a dependency array or with a dependency that directly causes the state to change can lead to an infinite loop of re-renders.
