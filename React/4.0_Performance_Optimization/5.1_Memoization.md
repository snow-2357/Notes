# 5.1 Memoization in React (React.memo, useCallback, useMemo)

Memoization is an optimization technique used to speed up computer programs by caching the results of expensive function calls and returning the cached result when the same inputs occur again. In React, memoization helps prevent unnecessary re-renders of components and recalculations of expensive values.

## When to Optimize with Memoization:
React is generally very fast. Optimizing with memoization is usually only necessary when:
*   Components render frequently with the same props.
*   Components have expensive calculations or render complex UI trees.
*   You encounter noticeable performance bottlenecks (always profile first!).

Overuse of memoization can introduce its own overhead, potentially making your application slower.

## 5.1.1 `React.memo` (for Functional Components)

`React.memo` is a higher-order component (HOC) that memoizes your functional component. If your component renders the same result given the same props, you can wrap it in `React.memo` for a performance boost in some cases.

**How it works:** `React.memo` performs a shallow comparison of props. If the props are the same, it reuses the last rendered result and skips re-rendering the component.

```jsx
import React from 'react';

// This component will re-render only if its 'name' prop changes
const MyFunctionalComponent = React.memo(function MyComponent(props) {
  console.log('MyFunctionalComponent re-rendered');
  return <div>Hello, {props.name}</div>;
});

function Parent() {
  const [count, setCount] = React.useState(0);
  const [name, setName] = React.useState('Alice');

  return (
    <div>
      <button onClick={() => setCount(count + 1)}>Increment Count ({count})</button>
      <button onClick={() => setName(name === 'Alice' ? 'Bob' : 'Alice')}>Change Name</button>
      <MyFunctionalComponent name={name} />
      {/* If count changes, Parent re-renders, but MyFunctionalComponent does NOT re-render
          because its 'name' prop has not changed. */}
    </div>
  );
}
```

**Custom Comparison Function:** You can provide a custom comparison function as the second argument to `React.memo` if you need a deeper comparison or a different comparison logic than the shallow one.

```jsx
function arePropsEqual(prevProps, nextProps) {
  // Return true if prevProps are equal to nextProps, false otherwise
  // This will prevent a re-render if it returns true.
  return prevProps.name === nextProps.name && prevProps.age === nextProps.age;
}

const MyComplexComponent = React.memo(function MyComplexComponent(props) {
  console.log('MyComplexComponent re-rendered');
  return (
    <div>
      <p>Name: {props.name}</p>
      <p>Age: {props.age}</p>
      {/* ... potentially expensive rendering logic ... */}
    </div>
  );
}, arePropsEqual);
```
**Caveat:** `React.memo` only checks for prop changes. It does not check for changes in internal state, context, or `useRef` values.

## 5.1.2 `useCallback` Hook

`useCallback` returns a memoized callback function. It's used to prevent functions from being re-created on every render, which can be important when passing callbacks to optimized child components (`React.memo`).

**Review from Hooks section:**
`const memoizedCallback = useCallback(() => { doSomething(); }, [dependencies]);`

*   **Purpose:** To keep function references stable across re-renders.
*   **Benefit:** Prevents child components wrapped in `React.memo` from re-rendering when the parent re-renders, if the only "changed" prop is a callback function that hasn't actually changed its logic or dependencies.

```jsx
import React, { useState, useCallback, memo } from 'react';

const Button = memo(({ onClick, children }) => {
  console.log('Button rendered:', children);
  return <button onClick={onClick}>{children}</button>;
});

function ParentComponentWithCallback() {
  const [count, setCount] = useState(0);

  // This function is memoized and will only be re-created if 'count' changes.
  const handleClick = useCallback(() => {
    setCount(count + 1);
  }, [count]); // Dependency array: recreate if count changes

  return (
    <div>
      <Button onClick={handleClick}>Increment ({count})</Button>
    </div>
  );
}
```

## 5.1.3 `useMemo` Hook

`useMemo` returns a memoized value. It's used for optimizing expensive calculations that should only be re-run when their dependencies change.

**Review from Hooks section:**
`const memoizedValue = useMemo(() => computeExpensiveValue(a, b), [a, b]);`

*   **Purpose:** To prevent expensive computations from running on every render.
*   **Benefit:** Improves performance by only re-calculating a value when the inputs to that calculation change.

```jsx
import React, { useState, useMemo } from 'react';

const calculateExpensiveValue = (num) => {
  console.log('Calculating expensive value...');
  // Simulate an expensive calculation
  let sum = 0;
  for (let i = 0; i < 100000000; i++) {
    sum += num;
  }
  return sum;
};

function ComponentWithExpensiveCalc() {
  const [number, setNumber] = useState(1);
  const [toggle, setToggle] = useState(false);

  // The expensive calculation will only re-run if 'number' changes.
  const memoizedResult = useMemo(() => calculateExpensiveValue(number), [number]);

  return (
    <div>
      <input type="number" value={number} onChange={e => setNumber(parseInt(e.target.value))} />
      <button onClick={() => setToggle(!toggle)}>Toggle Rerender ({toggle.toString()})</button>
      <p>Expensive result: {memoizedResult}</p>
      {/* Toggling will re-render the component, but calculateExpensiveValue won't run again unless 'number' changes */}
    </div>
  );
}
```

## Summary of Memoization Tools:
| Tool             | What it Memoizes   | When to Use                                             |
| :--------------- | :----------------- | :------------------------------------------------------ |
| `React.memo`     | A functional component | To prevent a component from re-rendering if its props (shallowly) haven't changed. |
| `useCallback`    | A function           | To prevent a callback prop from changing its reference, helping `React.memo`'d children. |
| `useMemo`        | A value            | To prevent an expensive calculation from re-running if its dependencies haven't changed. |

Remember to always profile your application before applying these optimizations, as they can sometimes add unnecessary complexity or overhead if not used judiciously. The React DevTools profiler is a great tool for identifying performance bottlenecks.
