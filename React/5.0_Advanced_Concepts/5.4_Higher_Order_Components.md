# 5.4 Higher-Order Components (HOCs)

A Higher-Order Component (HOC) is an advanced technique in React for reusing component logic. HOCs are not part of the React API, but rather a pattern that emerges from React's compositional nature.

Specifically, a HOC is a function that takes a component as an argument and returns a new component.

## What is a Higher-Order Component?

Consider components as functions that transform props into UI. HOCs are functions that take a component and return a *new* component that wraps the original. This wrapping component can inject props, manage state, subscribe to external data sources, or perform other logic that enhances the "wrapped" component.

**Signature of a HOC:**

```javascript
const HOC = (WrappedComponent) => {
  return class extends React.Component {
    // ... logic for enhancing WrappedComponent
    render() {
      return <WrappedComponent {...this.props} />;
    }
  };
};
```
Or, with functional components and Hooks:
```javascript
const HOC = (WrappedComponent) => {
  return function EnhancedComponent(props) {
    // ... logic for enhancing WrappedComponent
    return <WrappedComponent {...props} />;
  };
};
```

## How to Create a HOC

A common example is a HOC that subscribes to some external data source and injects that data as props into the wrapped component.

```jsx
import React, { useState, useEffect } from 'react';

// Imagine this is some external data service
const DataSource = {
  getComments: () => ['Comment 1', 'Comment 2'],
  getBlogPost: () => 'This is a blog post.',
  addChangeListener: (cb) => { /* ... */ },
  removeChangeListener: (cb) => { /* ... */ },
};

// This HOC subscribes to a data source and passes its data as a prop
function withSubscription(WrappedComponent, selectData) {
  return class extends React.Component {
    constructor(props) {
      super(props);
      this.state = {
        data: selectData(DataSource, props),
      };
    }

    componentDidMount() {
      // Subscribe to changes
      DataSource.addChangeListener(this.handleChange);
    }

    componentWillUnmount() {
      // Clean up subscription
      DataSource.removeChangeListener(this.handleChange);
    }

    handleChange = () => {
      this.setState({
        data: selectData(DataSource, this.props),
      });
    };

    render() {
      // Render the wrapped component with the injected data as props
      return <WrappedComponent data={this.state.data} {...this.props} />;
    }
  };
}

// Example Wrapped Components
function CommentList(props) {
  return (
    <div>
      <h2>Comments</h2>
      {props.data.map((comment, index) => (
        <p key={index}>{comment}</p>
      ))}
    </div>
  );
}

function BlogPost(props) {
  return (
    <div>
      <h2>Blog Post</h2>
      <p>{props.data}</p>
    </div>
  );
}

// Enhance components with the HOC
const CommentListWithSubscription = withSubscription(
  CommentList,
  (DataSource, props) => DataSource.getComments()
);

const BlogPostWithSubscription = withSubscription(
  BlogPost,
  (DataSource, props) => DataSource.getBlogPost(props.id) // Imagine props.id is passed from parent
);

function App() {
  return (
    <div>
      <CommentListWithSubscription />
      <BlogPostWithSubscription id={123} />
    </div>
  );
}

export default App;
```

## Advantages and Disadvantages of HOCs

**Advantages:**
- **Reusability:** Easily reuse component logic across different components.
- **Separation of Concerns:** Keep presentational components clean and focused on rendering, while HOCs handle data fetching, subscriptions, and other side effects.
- **Prop Injection:** HOCs can inject additional props into the wrapped component.

**Disadvantages:**
- **Prop Name Collisions:** If the HOC injects a prop with the same name as an existing prop in the wrapped component, it can silently overwrite it.
- **Wrapper Hell:** Composing multiple HOCs can lead to deeply nested component trees in the React DevTools, making debugging harder.
- **Inversion of Control:** The wrapped component is unaware of the HOC's logic, which can sometimes make reasoning about the data flow more difficult.
- **Static Composition:** HOCs are composed at definition time. You can't dynamically apply them inside the render method.

## Comparison with Render Props and Hooks

- **Render Props:** Offer similar capabilities for code sharing. Render props provide more explicit control over what props are passed down, avoiding the prop name collision issue of HOCs. They tend to be more flexible for dynamic rendering.
- **Hooks:** With the introduction of Hooks, many of the patterns previously solved by HOCs (e.g., managing state, subscribing to data) can now be achieved more simply and directly within functional components without introducing extra layers of component hierarchy. Hooks have largely become the preferred way to share reusable stateful logic.

While Hooks are the modern preferred approach, understanding HOCs is still valuable, especially when working with older codebases or libraries that rely on this pattern (e.g., `react-redux`'s `connect` function, which is a HOC).
