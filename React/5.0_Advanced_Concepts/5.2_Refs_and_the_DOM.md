# 5.2 Refs and the DOM

Refs provide a way to access DOM nodes or React elements created in the `render` method. In the typical React data flow, props are the only way parent components interact with their children. However, there are a few cases where you need to imperatively modify a child outside of the typical data flow.

## What are Refs?

Refs are a special attribute that can be attached to any component. They allow you to get a direct reference to a React element or a DOM node.

**When to use Refs:**
- Managing focus, text selection, or media playback.
- Triggering imperative animations.
- Integrating with third-party DOM libraries (e.g., D3.js, Chart.js).
- Measuring the size or position of a DOM element.

**Avoid using Refs for:**
- Anything that can be done declaratively. Props and state should be your first choice.
- Directly manipulating the DOM in ways that conflict with React's declarative updates.

## Creating Refs

### `React.createRef()` (Class Components)

`React.createRef()` is typically used in class components to create Refs.

```jsx
import React from 'react';

class MyTextInput extends React.Component {
  constructor(props) {
    super(props);
    this.textInput = React.createRef(); // Create a ref
  }

  focusTextInput = () => {
    // Directly access the DOM node via the ref and call its methods
    this.textInput.current.focus();
  };

  render() {
    return (
      <div>
        <input type="text" ref={this.textInput} /> {/* Attach the ref to an element */}
        <button onClick={this.focusTextInput}>Focus the text input</button>
      </div>
    );
  }
}

export default MyTextInput;
```

### `useRef()` (Functional Components)

The `useRef` Hook returns a mutable ref object whose `.current` property is initialized to the passed argument (`initialValue`). The returned ref object will persist for the full lifetime of the component.

```jsx
import React, { useRef } from 'react';

function MyFunctionalTextInput() {
  const textInput = useRef(null); // Create a ref with an initial value of null

  const focusTextInput = () => {
    // `current` points to the mounted text input element
    textInput.current.focus();
  };

  return (
    <div>
      <input type="text" ref={textInput} /> {/* Attach the ref */}
      <button onClick={focusTextInput}>Focus the text input</button>
    </div>
  );
}

export default MyFunctionalTextInput;
```

## Accessing DOM Nodes

When a ref is attached to an HTML element (like `<input>`, `<div>`), `ref.current` receives the underlying DOM element as its value.

When a ref is attached to a custom class component, `ref.current` holds the *instance* of the mounted component. You generally shouldn't do this, but it's possible.

**Note:** You cannot attach refs to functional components directly because they don't have instances. If you need to access a DOM node inside a functional component, you can use `useRef` directly on an HTML element within that component, or use `forwardRef` (see below).

## Forwarding Refs (`React.forwardRef`)

Ref forwarding is a technique for passing a ref through a component to one of its children's DOM node or component instances. This is especially useful for reusable component libraries.

```jsx
import React from 'react';

// MyButton is a functional component that forwards its ref to the native <button> DOM element
const MyButton = React.forwardRef((props, ref) => (
  <button ref={ref} className="MyButton">
    {props.children}
  </button>
));

function App() {
  const buttonRef = React.useRef();

  const handleClick = () => {
    buttonRef.current.focus(); // We can focus the native button via the ref
  };

  return (
    <div>
      <MyButton ref={buttonRef}>Click to Focus</MyButton>
      <button onClick={handleClick}>Focus MyButton</button>
    </div>
  );
}

export default App;
```

## Callback Refs

Instead of passing a ref object created by `createRef` or `useRef`, you can pass a function to the `ref` attribute. This function receives the DOM element or component instance directly.

```jsx
import React, { useCallback, useEffect } from 'react';

function MeasureDiv() {
  const measuredRef = useCallback(node => {
    if (node !== null) { // node will be null on unmount
      console.log('Div width:', node.getBoundingClientRect().width);
    }
  }, []); // Empty dependency array ensures the callback itself doesn't change

  return <div ref={measuredRef}>I will be measured!</div>;
}

export default MeasureDiv;
```
Callback refs are useful when you need more control over when the ref is set and unset, or when integrating with third-party libraries that expect a function.

## Best Practices and Common Pitfalls

- **Avoid overusing Refs:** Use them sparingly for imperative interactions. Most updates should be handled via state and props.
- **Refs don't trigger re-renders:** Updating `ref.current` does not cause your component to re-render. If you need a value to change and trigger a re-render, use state.
- **Never rely on the order of refs:** Don't assume that if you have multiple refs, they will be initialized in any particular order.
- **Refs are for escape hatches:** Think of refs as a way to "escape" React's declarative world when necessary, but always prefer declarative solutions first.
