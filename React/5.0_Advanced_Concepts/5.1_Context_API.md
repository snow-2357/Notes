# 5.1 Context API

React's Context API provides a way to pass data through the component tree without having to pass props down manually at every level. This is particularly useful for global data (like user authentication, theme, or preferred language) that many components in an application might need access to.

## What is the Context API and its Purpose?

At its core, Context is designed to share "global" data across a component tree. It helps avoid "prop drilling," which is the process of passing props down through multiple layers of intermediate components that don't directly need the data themselves.

**Purpose:**
- To make certain data accessible to any component, regardless of how deep it is in the component tree.
- Simplifies component interfaces by reducing the number of props passed.
- Ideal for data that is considered "global" or "application-wide."

## When to use Context vs. Prop Drilling

**Use Context when:**
- The data is truly global and required by many, potentially deeply nested, components.
- The data doesn't change frequently or changes trigger acceptable re-renders.
- Prop drilling becomes cumbersome (e.g., passing a prop through 3+ layers of components).

**Avoid Context when:**
- The data is only needed by a few components, especially if they are closely related in the tree (prop drilling might be simpler).
- You need a more robust, feature-rich state management solution (e.g., Redux, Zustand) for complex application state, side effects, or a highly optimized performance profile. Context is a good solution for *sharing* state, but not necessarily for *managing* complex state logic.

## Creating a Context: `React.createContext()`

You create a Context object with `React.createContext()`. It returns an object with a `Provider` and a `Consumer` component. The argument passed to `createContext` is the *default value*. This default value is used when a component consumes the context but there's no matching `Provider` above it in the tree, or if the component consumes outside of a provider.

```jsx
// theme-context.js
import React from 'react';

// Create a Context with a default light theme value
export const ThemeContext = React.createContext('light');
```

## Providing Context: `Context.Provider`

Every Context object comes with a Provider React component. It allows consuming components to subscribe to context changes. The Provider accepts a `value` prop to be passed to consuming components that are descendants of this Provider. One Provider can be connected to many consumers.

```jsx
// App.js
import React, { useState } from 'react';
import { ThemeContext } from './theme-context';
import Toolbar from './Toolbar';

function App() {
  const [theme, setTheme] = useState('light');

  const toggleTheme = () => {
    setTheme(prevTheme => (prevTheme === 'light' ? 'dark' : 'light'));
  };

  return (
    <ThemeContext.Provider value={theme}>
      <button onClick={toggleTheme}>Toggle Theme</button>
      <Toolbar />
    </ThemeContext.Provider>
  );
}

export default App;
```

## Consuming Context: `Context.Consumer` and the `useContext` Hook

### `Context.Consumer` (Class Components / Older Approach)

The `Context.Consumer` component uses a render prop pattern. It requires a function as a child that receives the current context value and returns a React node.

```jsx
// ThemedButton.js
import React from 'react';
import { ThemeContext } from './theme-context';

class ThemedButton extends React.Component {
  render() {
    return (
      <ThemeContext.Consumer>
        {theme => <button style={{ background: theme === 'dark' ? 'black' : 'white', color: theme === 'dark' ? 'white' : 'black' }}>
          I am a {theme} button
        </button>}
      </ThemeContext.Consumer>
    );
  }
}

export default ThemedButton;
```

### `useContext` Hook (Functional Components / Modern Approach)

The `useContext` hook is the simplest way to consume context in functional components. It takes the context object (the value returned from `React.createContext`) and returns the current context value for that context.

```jsx
// Toolbar.js
import React, { useContext } from 'react';
import ThemedButton from './ThemedButton';
import { ThemeContext } from './theme-context';

function Toolbar() {
  const theme = useContext(ThemeContext); // Directly get the theme value
  return (
    <div style={{ padding: '10px', background: theme === 'dark' ? '#333' : '#eee' }}>
      <p>Current Theme: {theme}</p>
      <ThemedButton />
    </div>
  );
}

export default Toolbar;
```

## Updating Context Values

To update a context value, you typically store the state in the parent component where the `Provider` is located and pass both the state value and the state update function down through the `Provider`'s `value` prop.

```jsx
// App.js (revisited)
import React, { useState } from 'react';
import { ThemeContext } from './theme-context';
import Toolbar from './Toolbar';

// Create a context that can hold both value and updater function
export const ThemeUpdaterContext = React.createContext({
  theme: 'light',
  toggleTheme: () => {}, // Provide a default no-op function
});

function App() {
  const [theme, setTheme] = useState('light');

  const toggleTheme = () => {
    setTheme(prevTheme => (prevTheme === 'light' ? 'dark' : 'light'));
  };

  // Provide both the theme and the toggle function
  const contextValue = { theme, toggleTheme };

  return (
    <ThemeUpdaterContext.Provider value={contextValue}>
      {/* The button can now consume toggleTheme from context */}
      <Toolbar />
    </ThemeUpdaterContext.Provider>
  );
}
```
And in a consuming component:
```jsx
// ThemedButton.js (with updater)
import React, { useContext } from 'react';
import { ThemeUpdaterContext } from './App'; // Import the context

function ThemedButton() {
  const { theme, toggleTheme } = useContext(ThemeUpdaterContext);
  return (
    <button
      onClick={toggleTheme}
      style={{ background: theme === 'dark' ? 'black' : 'white', color: theme === 'dark' ? 'white' : 'black' }}
    >
      Toggle to {theme === 'dark' ? 'Light' : 'Dark'} Theme
    </button>
  );
}

export default ThemedButton;
```

## Performance Considerations with Context

- **Re-renders:** When the `value` prop of a `Provider` changes, **all** consumers that are descendants of that Provider will re-render, regardless of whether they actually use the part of the value that changed.
- **Optimization:**
    - **Split Contexts:** If your context value contains multiple independent pieces of state, consider splitting it into multiple smaller contexts. This way, a change in one piece of state only re-renders consumers of that specific context.
    - **Memoization of `value` prop:** If the `value` prop is an object or array literal, it will be a new object on every render of the Provider, causing unnecessary re-renders in consumers. Use `useMemo` to memoize the `value` prop if it contains stable data.
    ```jsx
    const contextValue = useMemo(() => ({ theme, toggleTheme }), [theme, toggleTheme]);
    return (
      <ThemeUpdaterContext.Provider value={contextValue}>
        {/* ... */}
      </ThemeUpdaterContext.Provider>
    );
    ```
- Context is not a full-fledged state management library like Redux or Zustand, which often come with built-in performance optimizations like selectors and memoized state updates. Use Context for simple global state; for complex state logic, consider dedicated libraries.
