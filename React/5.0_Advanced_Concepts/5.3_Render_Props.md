# 5.3 Render Props

The "render prop" is a technique for sharing code between React components using a prop whose value is a function. This function's return value (a React element) determines what gets rendered. The component with the render prop doesn't render anything by itself; instead, it delegates the rendering responsibility to its consumers.

## What is the Render Props Pattern?

A component with a render prop takes a function as a prop, and that function returns a React element. The component then calls this function instead of implementing its own `render` logic.

The "render prop" is not necessarily named `render`. Any prop that is a function and is used by the component to determine what to render can be considered a render prop. The children prop is also technically a render prop.

## How to Implement Render Props

A common use case for render props is to share stateful logic.

```jsx
import React, { useState, useEffect } from 'react';

// This component encapsulates the logic for tracking mouse position
function Mouse(props) {
  const [position, setPosition] = useState({ x: 0, y: 0 });

  const handleMouseMove = (event) => {
    setPosition({
      x: event.clientX,
      y: event.clientY,
    });
  };

  useEffect(() => {
    window.addEventListener('mousemove', handleMouseMove);
    return () => {
      window.removeEventListener('mousemove', handleMouseMove);
    };
  }, []);

  // The render prop receives the state (mouse position) as an argument
  return props.render(position);
}

// Component that consumes the Mouse component and renders a cat image
function Cat(props) {
  const mouse = props.mouse; // This `mouse` prop comes from the render prop
  return (
    <img
      src="https://www.freeiconspng.com/thumbs/cat-png/cat-png-15.png"
      style={{ position: 'absolute', left: mouse.x, top: mouse.y, width: 50, height: 50 }}
      alt="cat"
    />
  );
}

// Application entry point
function App() {
  return (
    <div>
      <h1>Move the mouse around!</h1>
      {/* The Mouse component calls our render prop function, passing its state */}
      <Mouse render={(mousePosition) => <Cat mouse={mousePosition} />} />
    </div>
  );
}

export default App;
```

In this example:
- `Mouse` is the component that has the render prop (`props.render`). It contains the reusable logic (tracking mouse position).
- `App` provides the render prop function, which takes `mousePosition` and returns a `Cat` component configured with that position.

## Sharing Code and Logic between Components

The primary advantage of the render props pattern is its flexibility in sharing behavior. The component providing the render prop (e.g., `Mouse`) is solely responsible for managing the shared state or behavior, while the consumer dictates what gets rendered based on that state/behavior. This achieves a high degree of separation of concerns.

## Examples: `React-Router` (historically), `Formik`

- **`React-Router`:** Older versions used a `<Route>` component where `render` or `children` props could receive `match`, `location`, and `history` objects.
    ```jsx
    <Route path="/profile" render={({ match, history }) => (
      <UserProfile match={match} history={history} />
    )} />
    ```
- **`Formik`:** Uses render props (or hooks) to provide form state and methods to its children.
    ```jsx
    <Formik
      initialValues={{ email: '', password: '' }}
      onSubmit={(values) => { /* ... */ }}
    >
      {({ values, handleChange, handleSubmit }) => (
        <form onSubmit={handleSubmit}>
          <input name="email" value={values.email} onChange={handleChange} />
          {/* ... */}
        </form>
      )}
    </Formik>
    ```

## Advantages and Disadvantages of Render Props

**Advantages:**
- **Flexibility:** Allows consumers to fully control the rendering logic.
- **Decoupling:** Clearly separates reusable logic from UI representation.
- **Composable:** Can easily compose multiple render prop components.

**Disadvantages:**
- **Nested components (Wrapper Hell):** Can lead to deeply nested components when composing multiple render props, making the JSX harder to read.
- **Performance:** Could cause unnecessary re-renders if the render prop function creates new components or functions on every render (this can be mitigated with `React.memo` or `useCallback`).
- **Complexity:** Can be less intuitive to understand for newcomers compared to simpler patterns like hooks.

## Comparison with Hooks and Higher-Order Components

- **Hooks:** With the introduction of Hooks (`useState`, `useEffect`, custom Hooks), many of the use cases for render props (especially sharing stateful logic) can now be achieved more cleanly and directly. Hooks reduce nesting and make code more readable.
- **Higher-Order Components (HOCs):** HOCs also share logic but do so by wrapping components, which can lead to prop name collisions and an opaque source of props. Render props generally offer more explicit control over what props are passed down.

While Hooks have largely superseded render props for sharing stateful logic, render props still remain a valid and powerful pattern, especially for libraries that need to give consumers ultimate control over rendering.
