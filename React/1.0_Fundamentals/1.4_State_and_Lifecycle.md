# 1.4 State and Lifecycle

In React, components can have internal data that changes over time. This data is called "state." Unlike props, which are passed down from a parent and are immutable for the child, state is managed within the component itself and can be changed. When a component's state changes, React re-renders the component to reflect the new state.

## State in Class Components (Legacy):
In class components, state is an object managed within the component.

```jsx
class Clock extends React.Component {
  constructor(props) {
    super(props);
    this.state = {date: new Date()};
  }

  render() {
    return (
      <div>
        <h1>Hello, world!</h1>
        <h2>It is {this.state.date.toLocaleTimeString()}.</h2>
      </div>
    );
  }
}
```

To update state in a class component, you use the `this.setState()` method. React may batch multiple `setState()` calls for performance, so state updates can be asynchronous. It's recommended to use a function form of `setState()` if the new state depends on the previous state.

```jsx
// Correct way to update state based on previous state
this.setState((state, props) => ({
  counter: state.counter + props.increment
}));
```

## State in Function Components (with `useState` Hook - Modern):
With the introduction of Hooks in React 16.8, function components can now have state using the `useState` Hook. This is the recommended way to manage state in modern React applications.

```jsx
import React, { useState } from 'react';

function Clock() {
  const [date, setDate] = useState(new Date());

  // ... rest of the component logic
  return (
    <div>
      <h1>Hello, world!</h1>
      <h2>It is {date.toLocaleTimeString()}.</h2>
    </div>
  );
}
```
The `useState` Hook returns a pair: the current state value and a function that lets you update it. You can call this function from an event handler or elsewhere.

## Component Lifecycle (Class Components - Legacy):
Class components have "lifecycle methods" that allow you to run code at specific points in a component's life (when it mounts, updates, or unmounts).

*   **Mounting:**
    *   `constructor()`: Called before it is mounted. Good for initializing state and binding methods.
    *   `static getDerivedStateFromProps()`: Seldom used. Updates state based on changes in props.
    *   `render()`: The only required method. Renders the component.
    *   `componentDidMount()`: Called after the component is rendered to the DOM. Ideal for data fetching, subscriptions, or DOM manipulation.

*   **Updating:**
    *   `static getDerivedStateFromProps()`: (Same as mounting)
    *   `shouldComponentUpdate()`: Performance optimization. Allows you to prevent re-renders if props/state haven't changed.
    *   `render()`: Renders the component.
    *   `getSnapshotBeforeUpdate()`: Seldom used. Captures some information from the DOM before it is potentially changed.
    *   `componentDidUpdate()`: Called after an update occurs. Good for network requests as long as you compare `this.props` with `prevProps` (and `this.state` with `prevState`).

*   **Unmounting:**
    *   `componentWillUnmount()`: Called right before a component is unmounted and destroyed. Perform cleanup here (e.g., clear timers, cancel network requests, unsubscribe from events).

## Lifecycle in Function Components (with `useEffect` Hook - Modern):
Function components use the `useEffect` Hook to handle side effects and mimic lifecycle behaviors.

```jsx
import React, { useState, useEffect } from 'react';

function Clock() {
  const [date, setDate] = useState(new Date());

  useEffect(() => {
    // This function runs after every render
    const timerID = setInterval(() => {
      setDate(new Date());
    }, 1000);

    // Return a cleanup function
    return () => {
      clearInterval(timerID);
    };
  }, []); // Empty dependency array means this effect runs once on mount and cleans up on unmount

  return (
    <div>
      <h1>Hello, world!</h1>
      <h2>It is {date.toLocaleTimeString()}.</h2>
    </div>
  );
}
```
`useEffect` replaces `componentDidMount`, `componentDidUpdate`, and `componentWillUnmount` in a single API. The second argument, the dependency array, controls when the effect re-runs.
*   **Empty array `[]`**: Effect runs once after the initial render and cleans up on unmount (like `componentDidMount` and `componentWillUnmount`).
*   **No dependency array**: Effect runs after every render (like `componentDidMount` and `componentDidUpdate`).
*   **Array with dependencies `[dep1, dep2]`**: Effect runs after the initial render and whenever any of the dependencies change. It cleans up before re-running.
