# 3.1 Context API (Legacy vs. Hooks)

The React Context API provides a way to pass data through the component tree without having to pass props down manually at every level (prop drilling). It's designed to share data that can be considered "global" for a tree of React components, such as the current authenticated user, theme, or preferred language.

While `useContext` (covered in the Hooks section) is the modern way to consume context, understanding the older `Context.Consumer` and `Context.Provider` pattern is still useful, especially when working with older codebases or creating custom provider components.

## Key Concepts of Context API:

1.  **`React.createContext()`**: Creates a Context object. It takes one optional argument: `defaultValue`.
    *   `defaultValue`: The value that components will receive if they consume the context but there's no matching Provider above them in the tree. This can be useful for testing components in isolation without wrapping them.

2.  **`Context.Provider`**: A React component that allows consuming components to subscribe to context changes.
    *   It accepts a `value` prop to be passed to consuming components that are descendants of this Provider.
    *   A Provider can be nested inside other Providers to override values deeper within the tree.

3.  **`Context.Consumer` (Legacy way to consume Context)**: A React component that subscribes to context changes.
    *   It requires a function as a child. The function receives the current context value and returns a React node. This pattern is often referred to as a "render prop."

## Legacy Example (`Context.Consumer`):

```jsx
import React, { createContext, useState } from 'react';

// 1. Create a Context
const ThemeContext = createContext('light'); // Default value is 'light'

// Component that provides the theme
function App() {
  const [theme, setTheme] = useState('light');

  const toggleTheme = () => {
    setTheme(prevTheme => (prevTheme === 'light' ? 'dark' : 'light'));
  };

  return (
    <ThemeContext.Provider value={theme}> {/* Provide the current theme */}
      <button onClick={toggleTheme}>Toggle Theme</button>
      <Toolbar />
    </ThemeContext.Provider>
  );
}

// Intermediate component - doesn't care about the theme
function Toolbar() {
  return (
    <div>
      <ThemedButton />
    </div>
  );
}

// Component that consumes the theme using Context.Consumer
function ThemedButton() {
  return (
    <ThemeContext.Consumer>
      {theme => ( // theme is the value from the nearest ThemeContext.Provider
        <button style={{
          background: theme === 'light' ? '#eee' : '#333',
          color: theme === 'light' ? '#333' : '#eee',
        }}>
          Current theme from Consumer: {theme}
        </button>
      )}
    </ThemeContext.Consumer>
  );
}
```

## Modern Way to Consume Context (`useContext` Hook):

As discussed in the Hooks section, the `useContext` Hook is the preferred way to consume context in functional components.

```jsx
import React, { createContext, useContext, useState } from 'react';

// 1. Create a Context (same as before)
const ThemeContext = createContext('light');

// Component that provides the theme (same as before)
function App() {
  const [theme, setTheme] = useState('light');
  const toggleTheme = () => setTheme(prevTheme => (prevTheme === 'light' ? 'dark' : 'light'));

  return (
    <ThemeContext.Provider value={theme}>
      <button onClick={toggleTheme}>Toggle Theme</button>
      <Toolbar />
    </ThemeContext.Provider>
  );
}

// Intermediate component (same as before)
function Toolbar() {
  return (
    <div>
      <ModernThemedButton />
    </div>
  );
}

// Component that consumes the theme using useContext Hook
function ModernThemedButton() {
  const theme = useContext(ThemeContext); // Directly get the theme value

  return (
    <button style={{
      background: theme === 'light' ? '#eee' : '#333',
      color: theme === 'light' ? '#333' : '#eee',
    }}>
      Current theme from useContext: {theme}
    </button>
  );
}
```

## When to use Context:
*   **Global Data:** When you have data that needs to be accessible by many components at different nesting levels.
*   **Theming:** Easily switch between light/dark themes, or apply specific styling preferences.
*   **User Authentication:** Store and access the current user's details across the app.
*   **Locale/Language Preferences:** Manage and switch between different languages.

## Limitations and Alternatives:
*   **Not a Replacement for Redux/Zustand:** While Context can manage global state, it's not a full-fledged state management solution like Redux or Zustand. It lacks features like middlewares, time-travel debugging, and a structured way to handle complex async logic out-of-the-box. For complex application-wide state management, dedicated libraries might be more suitable.
*   **Performance Considerations:** When a Provider's `value` prop changes, all consumers re-render, even if they only use a part of the provided value. For performance-critical scenarios with large context values, careful memoization or splitting context into smaller, more specific contexts might be necessary. You can also combine `useContext` with `useMemo` or `useCallback` on the `value` prop of the Provider to prevent unnecessary re-renders of consumers.
