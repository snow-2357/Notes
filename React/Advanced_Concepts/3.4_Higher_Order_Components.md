# 3.4 Higher-Order Components (HOCs)

A Higher-Order Component (HOC) is an advanced technique in React for reusing component logic. HOCs are not part of the React API, but are a pattern that emerges from React's compositional nature.

Specifically, **a higher-order component is a function that takes a component as an argument and returns a new component.**

```javascript
const EnhancedComponent = higherOrderComponent(OriginalComponent);
```

## Why Use HOCs?
HOCs are useful for a variety of cross-cutting concerns:
*   **Code Reuse, Logic Abstraction:** Abstracting common stateful logic (e.g., data fetching, subscriptions, authentication checking).
*   **Prop Manipulation:** Injecting, modifying, or removing props from the wrapped component.
*   **Render Hijacking:** Controlling what the wrapped component renders.
*   **Performance Optimization:** Preventing unnecessary re-renders.

## Example: `withLogger` HOC
Let's create a simple HOC that logs when a component mounts and unmounts.

```jsx
import React, { useEffect } from 'react';

// HOC definition
function withLogger(WrappedComponent) {
  return function WithLogging(props) {
    const componentName = WrappedComponent.displayName || WrappedComponent.name || 'Component';

    useEffect(() => {
      console.log(`${componentName} Mounted!`);
      return () => {
        console.log(`${componentName} Unmounted!`);
      };
    }, []); // Run effect once on mount and cleanup on unmount

    return <WrappedComponent {...props} />;
  };
}

// A simple component
function MyPureComponent(props) {
  return <p>Hello, {props.name}</p>;
}

// Apply the HOC
const MyComponentWithLogger = withLogger(MyPureComponent);

// Usage
function App() {
  return (
    <div>
      <MyComponentWithLogger name="Alice" />
      <MyComponentWithLogger name="Bob" />
    </div>
  );
}
```

In this example:
*   `withLogger` is a function that takes `WrappedComponent` (`MyPureComponent`) as an argument.
*   It returns a new functional component `WithLogging`.
*   `WithLogging` component handles the logging logic using `useEffect` and then renders the `WrappedComponent` (`MyPureComponent`) with all its original props.

## Example: `withData` HOC (Data Fetching)
A more complex HOC might fetch data and pass it as props.

```jsx
import React, { useState, useEffect } from 'react';

function withData(WrappedComponent, selectData) {
  return function WithData(props) {
    const [data, setData] = useState(null);
    const [loading, setLoading] = useState(true);
    const [error, setError] = useState(null);

    useEffect(() => {
      const fetchData = async () => {
        setLoading(true);
        setError(null);
        try {
          const response = await fetch('/api/some-data'); // Replace with actual API endpoint
          if (!response.ok) throw new Error('Network response was not ok.');
          const json = await response.json();
          setData(selectData(json, props)); // Process fetched data
        } catch (err) {
          setError(err);
        } finally {
          setLoading(false);
        }
      };
      fetchData();
    }, [props.dataSource, selectData]); // Re-fetch if dataSource changes

    if (loading) return <div>Loading...</div>;
    if (error) return <div>Error: {error.message}</div>;

    // Inject 'data' prop to the WrappedComponent
    return <WrappedComponent data={data} {...props} />;
  };
}

// Component that needs data
function UserList(props) {
  if (!props.data) return <p>No users to display.</p>;
  return (
    <ul>
      {props.data.map(user => (
        <li key={user.id}>{user.name}</li>
      ))}
    </ul>
  );
}

// A function to select data for the HOC
const mapUsersToProps = (apiData) => apiData.users;

// Apply the HOC
const UserListWithData = withData(UserList, mapUsersToProps);

// Usage
// function App() {
//   return <UserListWithData dataSource="/users" />;
// }
```

## Naming Convention:
It's common to prefix HOC names with `with` (e.g., `withAuth`, `withRouter`, `withStyles`).

## Don't Mutate the Original Component:
The HOC should not modify the passed component; instead, it should return a new component that wraps the original one. This is because mutating the original component can lead to issues with reuse and debugging.

## Pass Unrelated Props Through:
Always pass through props that are not used by the HOC to the wrapped component. This ensures flexibility.

## Display Name for Debugging:
To make debugging easier, give the wrapper component a descriptive display name.
```jsx
function withLogger(WrappedComponent) {
  const WithLogging = function WithLogging(props) { /* ... */ };
  WithLogging.displayName = `withLogger(${getDisplayName(WrappedComponent)})`;
  return WithLogging;
}

function getDisplayName(WrappedComponent) {
  return WrappedComponent.displayName || WrappedComponent.name || 'Component';
}
```

## Limitations and Alternatives:
*   **Prop Collisions:** If the HOC injects props with the same names as the wrapped component already uses, it can lead to confusion or overwrite props.
*   **Nesting (Wrapper Hell):** Composing multiple HOCs can lead to deeply nested component trees in the React DevTools and can make it harder to trace where props are coming from.
*   **Implicit Dependencies:** It can be less clear which props are being injected by HOCs, making components harder to understand at a glance.

**Alternatives:**
*   **Render Props:** Offers similar capabilities for sharing logic but with a different structural approach.
*   **Hooks (especially Custom Hooks):** With the introduction of Hooks, custom Hooks have become the primary way to reuse stateful logic in modern React. They generally offer a cleaner and more direct way to achieve what HOCs and render props do, without the "wrapper hell" or prop collision issues.

For new projects, custom Hooks are generally preferred for logic reuse. However, HOCs are still prevalent in many existing libraries and codebases, so understanding them is crucial.
