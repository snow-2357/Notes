# 3.3 Render Props

"Render Props" is a technique for sharing code between React components using a prop whose value is a function. This function's return value determines what will be rendered by the component.

The term "render prop" refers to a simple technique for sharing code between React components using a prop whose value is a function.

## How Render Props Work:
A component with a render prop takes a function that returns a React element and calls it instead of implementing its own render logic. This function is typically passed as a `render` prop, but any prop that's a function can technically be considered a "render prop." The `children` prop can also be used as a render prop.

## Example: `MouseTracker`
Let's create a `MouseTracker` component that encapsulates the logic for tracking the mouse position, and then uses a render prop to allow other components to render something based on that position.

```jsx
import React from 'react';

// Component with a Render Prop
class MouseTracker extends React.Component {
  constructor(props) {
    super(props);
    this.state = { x: 0, y: 0 };
  }

  handleMouseMove = (event) => {
    this.setState({
      x: event.clientX,
      y: event.clientY
    });
  };

  render() {
    // The render prop is called here, passing down the state
    return (
      <div style={{ height: '100vh', border: '1px solid black' }} onMouseMove={this.handleMouseMove}>
        {/*
          Instead of hardcoding a <p>, use the prop.render function to
          give the control over what to render to the consumer.
        */}
        {this.props.render(this.state)}
      </div>
    );
  }
}

// Component that uses MouseTracker with a custom rendering function
function Cat({ mouse }) {
  return (
    <img src="https://www.reactjs.org/logo-og.png" style={{ position: 'absolute', left: mouse.x, top: mouse.y, width: '50px' }} alt="cat" />
  );
}

function App() {
  return (
    <div>
      <h1>Move the mouse around!</h1>
      <MouseTracker render={mouse => (
        <Cat mouse={mouse} />
      )}/>
    </div>
  );
}
```

In this example:
*   `MouseTracker` manages the mouse position state (`x`, `y`).
*   It doesn't render any specific UI for the mouse position itself. Instead, it calls `this.props.render` and passes its current state to it.
*   `App` (the consumer) passes a function to the `render` prop. This function receives the `mouse` state from `MouseTracker` and renders a `Cat` component at that position.

## Using `children` as a Render Prop:
You can also use `props.children` as a render prop. This is a common pattern and sometimes considered more idiomatic.

```jsx
import React from 'react';

class MouseTrackerWithChildren extends React.Component {
  constructor(props) {
    super(props);
    this.state = { x: 0, y: 0 };
  }

  handleMouseMove = (event) => {
    this.setState({ x: event.clientX, y: event.clientY });
  };

  render() {
    return (
      <div style={{ height: '100vh', border: '1px dashed gray' }} onMouseMove={this.handleMouseMove}>
        {/* Render the children function, passing the state */}
        {this.props.children(this.state)}
      </div>
    );
  }
}

function AppWithChildren() {
  return (
    <div>
      <h1>Move the mouse around (children as render prop)!</h1>
      <MouseTrackerWithChildren>
        {mouse => ( // The function is passed as children
          <p>The mouse position is {mouse.x}, {mouse.y}</p>
        )}
      </MouseTrackerWithChildren>
    </div>
  );
}
```

## Advantages of Render Props:
*   **Highly Reusable Logic:** Share behaviors (like data fetching, mouse tracking, toggling state) across components without tightly coupling them.
*   **Flexible Rendering:** The consumer has full control over *what* is rendered, while the render prop component controls *how* the data or behavior is provided.
*   **Avoids Prop Drilling:** No need to pass down callbacks through many layers.

## Limitations and Alternatives:
*   **Nesting:** Can lead to deeply nested JSX if many render prop components are composed together, sometimes referred to as "wrapper hell."
*   **Performance:** Can cause unnecessary re-renders if the function passed as a prop is re-created on every render and not memoized (e.g., using `useCallback` in a functional component that provides the render prop).

**Alternatives:**
*   **Higher-Order Components (HOCs):** Another pattern for sharing logic, often preferred when you want to inject props into a wrapped component.
*   **Hooks:** With the advent of Hooks (especially custom Hooks), many use cases for render props can now be solved more simply and cleanly using custom Hooks. Custom Hooks are generally the preferred modern approach for reusing stateful logic.

For most new code, custom Hooks are recommended over render props for sharing stateful logic. However, render props are still a valid and powerful pattern, especially in certain library designs or when the rendering logic is truly dynamic.
