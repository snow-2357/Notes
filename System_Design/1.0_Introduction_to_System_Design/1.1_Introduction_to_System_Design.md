
# 1.1 Introduction to System Design

System design is the process of architecting a software system to meet a set of functional and non-functional requirements. It involves making high-level design choices, such as selecting the right technologies, defining the system's architecture, and specifying how its various components will interact.

## Key Characteristics of a Well-Designed System

A well-designed system typically exhibits several key characteristics:

*   **Scalability:** The system's ability to handle increasing load.
    *   **Vertical Scaling (Scaling Up):** Increasing the resources of a single server (e.g., adding more CPU, RAM).
    *   **Horizontal Scaling (Scaling Out):** Adding more servers to the system and distributing the load among them. Horizontal scaling is generally preferred for large-scale systems.
*   **Reliability & Availability:**
    *   **Reliability:** The probability that a system will perform its intended function for a specified period without failure.
    *   **Availability:** The percentage of time a system is operational and available to users. Often expressed in "nines" (e.g., 99.9% availability, or "three nines").
*   **Performance & Latency:**
    *   **Performance:** A measure of how quickly a system can respond to a request.
    *   **Latency:** The time it takes for a single request to be processed, from the moment it is sent to the moment a response is received.
*   **Maintainability:** The ease with which a system can be modified, repaired, or enhanced. This is influenced by code quality, documentation, and architectural clarity.
*   **Consistency:** Refers to how data is kept up-to-date across different nodes in a distributed system.
    *   **Strong Consistency:** Ensures that all clients see the same data at the same time. This can come at the cost of higher latency.
    *   **Eventual Consistency:** Guarantees that, if no new updates are made to a given data item, all accesses to that item will eventually return the last updated value. This often results in lower latency.

## The System Design Process

A typical system design process involves the following steps:

1.  **Requirements Gathering:**
    *   **Functional Requirements:** What the system should do (e.g., "users can upload photos").
    *   **Non-Functional Requirements:** How the system should perform (e.g., "the system should handle 1 million daily active users," "uploads should complete within 2 seconds").
2.  **High-Level Design:**
    *   Sketch out the main components and services (e.g., web server, application server, database, cache).
    *   Define the relationships and interactions between these components.
3.  **Detailed Design:**
    *   Flesh out the details of each component.
    *   Design the API contracts between services.
    *   Define the database schema.
4.  **Identifying Bottlenecks and Trade-offs:**
    *   Analyze the design for potential performance bottlenecks.
    *   Evaluate the trade-offs of different design choices (e.g., choosing a NoSQL database for scalability might mean sacrificing strong consistency).

System design is an iterative process. It's common to revisit and refine the design as you uncover new requirements or constraints.
