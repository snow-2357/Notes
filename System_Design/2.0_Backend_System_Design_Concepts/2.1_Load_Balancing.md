
# 2.1 Load Balancing

A load balancer is a critical component in any scalable and highly available system. It acts as a "traffic cop," sitting in front of your application servers and distributing incoming network traffic across a group of backend servers (a server farm or pool).

## 1. Introduction

The primary purpose of a load balancer is to prevent any single server from becoming a bottleneck and to ensure the overall system remains responsive and available, even if some of the backend servers fail.

## 2. Benefits of Load Balancing

*   **Improved Scalability:** Allows you to scale your application horizontally by adding more servers to the pool.
*   **High Availability & Fault Tolerance:** Load balancers can perform health checks on backend servers. If a server becomes unresponsive, the load balancer automatically stops sending traffic to it, ensuring the application remains available.
*   **Enhanced Performance:** By distributing the load, response times are improved, and the user experience is more consistent.
*   **Easier Maintenance:** You can perform rolling updates or maintenance on individual servers without taking the entire application offline. The load balancer simply routes traffic away from the server being worked on.

## 3. Load Balancer Types

Load balancers are typically categorized by the networking layer at which they operate.

### 3.1 Layer 4 (L4) Load Balancer

*   **Layer:** Operates at the transport layer (TCP/UDP).
*   **How it works:** It makes routing decisions based on information from the first few packets in the TCP stream, such as source/destination IP addresses and ports. It doesn't inspect the actual content of the packets.
*   **Pros:** Very fast and efficient due to its simplicity.
*   **Cons:** Not content-aware. It cannot make routing decisions based on HTTP headers, cookies, or URL paths.

### 3.2 Layer 7 (L7) Load Balancer

*   **Layer:** Operates at the application layer (HTTP/HTTPS).
*   **How it works:** An L7 load balancer terminates the network traffic, reads the message content, and makes routing decisions based on application-level information.
*   **Capabilities:**
    *   **Path-based Routing:** Route `/api/*` to your API servers and `/images/*` to a different set of servers.
    *   **Host-based Routing:** Route `blog.example.com` and `api.example.com` to different server pools.
    *   **Cookie-based Routing:** Use cookies for session persistence.
    *   **SSL Termination:** Offload the work of encrypting and decrypting HTTPS traffic from your backend servers.
*   **Pros:** Enables much more intelligent and flexible routing.
*   **Cons:** Slower than L4 load balancers due to the overhead of inspecting packet content.

## 4. Load Balancing Algorithms

This is the logic a load balancer uses to decide which server should receive the next request.

*   **Round Robin:** Distributes requests sequentially to each server in the pool. Simple but doesn't account for server load or capacity.
*   **Least Connections:** Directs traffic to the server with the fewest active connections. This is often a good choice for applications where sessions can have varying lengths.
*   **Least Response Time:** Sends the request to the server with the fastest response time and fewest active connections.
*   **IP Hash:** A hash of the client's IP address is calculated to determine which server receives the request. This ensures that a user is consistently sent to the same server.
*   **Weighted Algorithms:** (e.g., Weighted Round Robin, Weighted Least Connections). Allows an administrator to assign a "weight" to each server based on its capacity (e.g., a more powerful server gets a higher weight and receives more traffic).

## 5. Session Persistence (Sticky Sessions)

**What it is:** A mechanism to ensure that requests from a single user are consistently sent to the same backend server for the duration of their session.

**Why it's needed:** This is primarily required for **stateful** applications that store user session data locally on the server.

**How it's achieved:**
*   **Source IP Affinity:** The load balancer uses the client's IP address to route their requests to the same server (same as the IP Hash algorithm).
*   **Cookies:** The load balancer sets a cookie on the user's first request. Subsequent requests containing this cookie are routed to the same server.

**Drawbacks:**
*   Can lead to uneven load distribution if some users create much heavier sessions than others.
*   If the "sticky" server goes down, the user's session data is lost.

**Important Note:** The modern and preferred approach is to design **stateless** application services. In a stateless architecture, session data is stored in an external, shared data store (like a Redis cache or a database), so any application server can handle any user's request at any time. This simplifies scaling and improves fault tolerance.
