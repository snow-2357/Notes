# 4.3 Decorators and Metadata Reflection

Decorators are a special kind of declaration that can be attached to a class declaration, method, accessor, property, or parameter. They provide a way to add annotations and a meta-programming syntax for class members.

**Note:** Decorators are an experimental feature in TypeScript. You must enable the `experimentalDecorators` compiler option in your `tsconfig.json`.

## What are Decorators?

Decorators use the form `@expression`, where `expression` must evaluate to a function that will be called at runtime with information about the decorated declaration.

They are essentially functions that receive the thing they are decorating as an argument, allowing them to modify or wrap it.

## Common Use Cases

Decorators are heavily used in frameworks that rely on Object-Oriented Programming (OOP) patterns, particularly those that use Dependency Injection.

- **Angular:** Uses decorators extensively to define components (`@Component`), services (`@Injectable`), and more.
- **NestJS:** A Node.js framework that uses decorators for routing (`@Controller`, `@Get`), dependency injection (`@Injectable`), and data validation (`@Body`).
- **TypeORM / MikroORM:** Use decorators to define database entities and columns (`@Entity`, `@Column`).

## Example: A Simple Method Decorator

A method decorator is a function that accepts three arguments:
1.  `target`: The class prototype.
2.  `propertyKey`: The name of the method.
3.  `descriptor`: The property descriptor for the method.

```typescript
// A decorator that logs when a method is called
function LogMethod(target: any, propertyKey: string, descriptor: PropertyDescriptor) {
    const originalMethod = descriptor.value;

    descriptor.value = function (...args: any[]) {
        console.log(`Calling "${propertyKey}" with arguments:`, args);
        const result = originalMethod.apply(this, args);
        console.log(`Method "${propertyKey}" returned:`, result);
        return result;
    };

    return descriptor;
}

class Calculator {
    @LogMethod
    add(a: number, b: number): number {
        return a + b;
    }
}

const calc = new Calculator();
calc.add(2, 3);
// Logs: Calling "add" with arguments: [2, 3]
// Logs: Method "add" returned: 5
```

## Metadata Reflection

When used with a library like `reflect-metadata`, decorators can be used to emit type information at runtime. This is the foundation of how dependency injection containers work.

```typescript
import 'reflect-metadata';

// When this class is compiled, TypeScript (with the right options)
// will emit metadata about the types of the constructor parameters.
@Injectable()
class UserService {
    constructor(private http: HttpClient) {}
}

// A DI container can then use this metadata to know it needs to
// inject an instance of HttpClient when creating a UserService.
const requiredParams = Reflect.getMetadata('design:paramtypes', UserService); // [HttpClient]
```
While you may not write decorators often yourself, understanding how they work is key to understanding many modern backend and frontend frameworks.
