# 4.2 Configuration Deep Dive (tsconfig.json)

The `tsconfig.json` file is the heart of a TypeScript project. It specifies the root files and the compiler options required to compile the project.

Running `tsc --init` will create a well-commented default `tsconfig.json` file.

## Key Sections

1.  **`compilerOptions`**: The most important section, where you configure the behavior of the TypeScript compiler.
2.  **`include`**: An array of glob patterns specifying which files to include in the compilation.
3.  **`exclude`**: An array of glob patterns specifying which files to exclude (e.g., `node_modules`).
4.  **`extends`**: A path to another configuration file to inherit from. This is common in monorepos or to share a base configuration.

## Important `compilerOptions`

### Core Options
- **`target`**: The JavaScript language version to emit (e.g., `ES2016`, `ESNext`).
- **`module`**: The module system to use for the generated code (e.g., `CommonJS`, `ESNext`).
- **`outDir`**: The directory where the compiled `.js` files will be placed (e.g., `./dist`).
- **`rootDir`**: The root directory of your source files.
- **`jsx`**: How to handle JSX files (`preserve`, `react`, `react-jsxdev`). `react-jsxdev` is the modern default.
- **`lib`**: A list of standard library files to be included in the compilation (e.g., `DOM`, `ES2020`). TypeScript includes a sensible default based on your `target`.

### Strictness Flags (Highly Recommended)
It's best practice to enable all strictness options for maximum type safety.
- **`strict`**: A master switch that enables all the strict mode options below. **Always set this to `true`**.
- **`noImplicitAny`**: Raises an error on expressions and declarations with an implied `any` type.
- **`strictNullChecks`**: When true, `null` and `undefined` have their own distinct types and you'll get an error where you might be using a value that could be null/undefined. This is one of the most powerful features of TypeScript.
- **`strictFunctionTypes`**: Ensures function parameters are checked more correctly.
- **`alwaysStrict`**: Ensures `"use strict";` is emitted in generated JavaScript.

### Module Resolution
- **`moduleResolution`**: How the compiler looks for a module. Almost always should be `node`.
- **`baseUrl`**: The base directory for resolving non-absolute module names.
- **`paths`**: A series of entries which re-map imports to lookup locations relative to the `baseUrl`. This allows for "absolute imports" (e.g., `import { Button } from '@/components/Button'`).

```json
{
  "compilerOptions": {
    "baseUrl": "./src",
    "paths": {
      "@/*": ["*"]
    }
  }
}
```
A well-configured `tsconfig.json` is the foundation of a robust and maintainable TypeScript project.
