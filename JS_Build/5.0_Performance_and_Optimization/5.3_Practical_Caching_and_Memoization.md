# 5.3 Practical Caching and Memoization

Caching and memoization are techniques used to store the results of expensive operations and return the cached result when the same operation occurs again. This can significantly improve performance by avoiding redundant computation or data fetching.

## Memoization

Memoization is an optimization technique used primarily to speed up pure functions by caching their return values based on their inputs.

- **Pure Function:** A function that, given the same input, will always return the same output and has no side effects.
- **How it works:** A memoized function stores a map of inputs to outputs. When called, it first checks if it has already computed the result for the given set of arguments. If so, it returns the cached result. If not, it computes the result, stores it, and then returns it.

### React.memo
In React, you can prevent a component from re-rendering if its props haven't changed by wrapping it in `React.memo`. This is a form of memoization for components.

```javascript
const MyComponent = React.memo(function MyComponent(props) {
  /* render using props */
});
```

### `useMemo` and `useCallback`
- **`useMemo`:** Memoizes the *return value* of a function. Use this to avoid re-computing expensive calculations on every render.
- **`useCallback`:** Memoizes the *function instance* itself. Use this to prevent child components from re-rendering when you pass them a callback function as a prop.

```javascript
function Parent({ term }) {
    // This expensive calculation only runs when `term` changes.
    const expensiveData = useMemo(() => computeExpensiveValue(term), [term]);

    // This function instance is preserved between renders.
    const handleClick = useCallback(() => {
        console.log('Button clicked');
    }, []);

    return <ChildComponent data={expensiveData} onClick={handleClick} />;
}
```

## Data Fetching Caching

Caching network requests is one of the most effective ways to make an application feel faster and reduce load on your backend.

### HTTP Caching
The first line of defense. By setting correct cache headers on your API responses (`Cache-Control`, `ETag`), you can instruct the browser to cache responses and avoid making a network request at all if the data hasn't changed.

### Client-Side Caching Libraries
Modern data-fetching libraries have sophisticated built-in caching mechanisms.

- **Tools:** **React Query (TanStack Query)**, **SWR**.
- **Features:**
    - **In-memory cache:** They maintain a client-side cache of your server state.
    - **Automatic Refetching:** They can automatically refetch data in the background to keep it fresh (`stale-while-revalidate`).
    - **Deduping:** If you request the same data in multiple components at the same time, they will only make one network request.
    - **Optimistic Updates:** You can update the UI instantly before the server has confirmed the change, providing a very fast perceived performance.

Using a library like React Query is the recommended approach for managing server state in modern React applications, as it handles the complexities of caching, revalidation, and loading/error states for you.
