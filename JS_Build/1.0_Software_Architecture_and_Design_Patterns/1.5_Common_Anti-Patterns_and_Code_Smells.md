# 1.5 Common Anti-Patterns and Code Smells

An anti-pattern is a common response to a recurring problem that is usually ineffective and risks being counterproductive. A code smell is a surface indication that usually corresponds to a deeper problem in the system.

## Common JavaScript Anti-Patterns

- **Polluting the Global Namespace:** Declaring variables in the global scope can lead to naming collisions and unpredictable behavior. Modern ES Modules largely solve this, but it's still possible in older code or scripts.
- **Callback Hell (The Pyramid of Doom):** Deeply nested callbacks make code hard to read, reason about, and debug.
    - **Solution:** Use Promises, `async/await`.
- **Large, Monolithic Functions:** A function that does too many things is hard to test, reuse, and understand.
    - **Solution:** Decompose the function into smaller, single-purpose functions.
- **Magic Strings / Magic Numbers:** Using unnamed string or number literals directly in the code.
    - **Solution:** Extract them into named constants. This improves readability and makes them easier to change.
- **Mutable State and Side Effects:** Uncontrolled changes to state can make your application's behavior unpredictable.
    - **Solution:** Favor pure functions, immutability, and clear state management patterns (e.g., Redux, Zustand).
- **Not Using a Linter/Formatter:** Inconsistent code style and failure to catch simple errors makes collaboration and maintenance difficult.
    - **Solution:** Integrate ESLint and Prettier into your workflow.

## Code Smells

- **Excessive Comments:** Comments should explain *why* something is done, not *what* it does. If the code is so complex it needs comments to explain *what* it's doing, the code should be refactored.
- **Duplicated Code:** Violates the "Don't Repeat Yourself" (DRY) principle.
    - **Solution:** Abstract the duplicated logic into a reusable function or component.
- **Dead Code:** Unused variables, functions, or files.
    - **Solution:** A good linter and bundler (with tree-shaking) can help identify and remove this.
- **Long Parameter List:** A function with too many parameters can be hard to use correctly.
    - **Solution:** Group parameters into an options object.
