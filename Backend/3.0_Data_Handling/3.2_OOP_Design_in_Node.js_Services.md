# 3.2 OOP Design in Node.js Services

While JavaScript is often associated with functional programming paradigms, Object-Oriented Programming (OOP) principles can be effectively applied in Node.js backend services, especially for building scalable, maintainable, and testable applications. OOP helps in structuring code by encapsulating data and behavior into objects.

## Core OOP Concepts Applicable to Node.js:

1.  **Encapsulation:** Bundling data (attributes) and methods (functions) that operate on the data within a single unit or object. It restricts direct access to some of an object's components, which means state changes are controlled through defined methods.
    *   **In Node.js:** Use classes to define objects where properties and methods are grouped. Private class fields (with `#` prefix, available in modern JS) or closures can enforce privacy.

    ```javascript
    class UserService {
      #users = []; // Private field (modern JS)

      constructor(userRepository) {
        this.userRepository = userRepository; // Dependency Injection
      }

      async createUser(userData) {
        // Validate user data
        if (!userData.email || !userData.password) {
          throw new Error('Email and password are required');
        }
        // Hash password
        userData.password = await hashPassword(userData.password);
        const newUser = await this.userRepository.save(userData);
        // ...
        return newUser;
      }

      async getUserById(id) {
        return this.userRepository.findById(id);
      }
    }
    ```

2.  **Inheritance:** A mechanism where one class (child/subclass) can inherit properties and methods from another class (parent/superclass). It promotes code reuse.
    *   **In Node.js:** Use the `extends` keyword with ES6 classes.

    ```javascript
    class BaseController {
      constructor(service) {
        this.service = service;
      }

      async getAll(req, res, next) {
        try {
          const items = await this.service.findAll();
          res.json(items);
        } catch (error) {
          next(error);
        }
      }

      // ... other common CRUD methods
    }

    class UserController extends BaseController {
      constructor(userService) {
        super(userService); // Call parent constructor
      }

      async getProfile(req, res, next) {
        try {
          const user = await this.service.getUserById(req.user.id);
          res.json(user);
        } catch (error) {
          next(error);
        }
      }
    }
    ```

3.  **Polymorphism:** The ability of objects of different classes to be treated as objects of a common superclass. This allows for a single interface to represent different underlying forms (many shapes).
    *   **In Node.js:** Achieved through method overriding in subclasses or by implementing common interfaces (implicitly, using duck typing, or explicitly with TypeScript interfaces).

    ```javascript
    // Implicit polymorphism via duck typing
    class EmailNotifier {
      notify(user, message) {
        console.log(`Sending email to ${user.email}: ${message}`);
      }
    }

    class SMSNotifier {
      notify(user, message) {
        console.log(`Sending SMS to ${user.phone}: ${message}`);
      }
    }

    class NotificationService {
      constructor(notifier) {
        this.notifier = notifier; // Can be EmailNotifier or SMSNotifier
      }

      sendWelcomeNotification(user) {
        this.notifier.notify(user, 'Welcome to our service!');
      }
    }

    const emailService = new NotificationService(new EmailNotifier());
    const smsService = new NotificationService(new SMSNotifier());
    ```

4.  **Abstraction:** Hiding complex implementation details and showing only the essential features of an object.
    *   **In Node.js:** Use interfaces (in TypeScript) or abstract classes (which JavaScript doesn't natively support, but can be simulated) to define contracts. Custom Hooks in React are a good example of abstraction. In backend, a `Repository` pattern is a form of abstraction.

    ```javascript
    // In TypeScript:
    // interface IUserRepository {
    //   findById(id: string): Promise<User | null>;
    //   save(user: User): Promise<User>;
    //   // ...
    // }

    class UserRepository { // Implements IUserRepository (implicitly in JS)
      constructor(dbClient) {
        this.dbClient = dbClient;
      }

      async findById(id) {
        // Complex database logic
        return this.dbClient.query('SELECT * FROM users WHERE id = ?', [id]);
      }

      async save(user) {
        // Complex database insert/update logic
        return this.dbClient.query('INSERT INTO users (...) VALUES (...)', [user]);
      }
    }
    ```

## Common OOP Design Patterns in Node.js Services:

1.  **Repository Pattern:** Abstracts the data layer, providing a collection-like interface to access domain objects. This separates the application's business logic from how data is stored and retrieved.
2.  **Service Layer:** Contains business logic and orchestrates operations across multiple repositories or other services.
3.  **Controller Layer:** Handles incoming HTTP requests, validates input, calls the appropriate service methods, and sends back HTTP responses.
4.  **Dependency Injection (DI):** A technique where objects receive other objects that they depend on. This promotes loose coupling and makes testing easier.
    *   Instead of `new UserRepository()`, you pass `userRepository` to `UserService`'s constructor.

## Example Structure for an Express.js Service with OOP:

```
src/
├── app.js             // Entry point, Express app setup, middleware, route mounting
├── config/            // Configuration files
├── controllers/       // Request handlers (e.g., UserController.js)
│   └── user.controller.js
├── services/          // Business logic (e.g., UserService.js)
│   └── user.service.js
├── repositories/      // Data access logic (e.g., UserRepository.js)
│   └── user.repository.js
├── models/            // Data structures / Schemas (e.g., User.js)
│   └── user.model.js
├── middlewares/       // Custom Express middleware (e.g., auth.middleware.js)
├── utils/             // Utility functions (e.g., passwordHasher.js)
├── routes/            // Route definitions (e.g., user.routes.js)
│   └── user.routes.js
└── index.js           // Server startup
```

## Benefits of OOP in Node.js Backends:
*   **Modularity:** Code is organized into independent, reusable modules.
*   **Maintainability:** Easier to understand, debug, and modify specific parts of the codebase.
*   **Testability:** Decoupled components are easier to unit test.
*   **Scalability:** Clear separation of concerns helps manage complexity as the application grows.
*   **Collaboration:** Provides a clear structure for larger teams to work on different parts of the application.

While JavaScript's asynchronous nature and functional roots are prominent, combining them with solid OOP design principles can lead to robust and scalable backend systems in Node.js. TypeScript enhances this further by providing strong typing and explicit interface definitions.
