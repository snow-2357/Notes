# 3.7 Indexing Strategies (MongoDB)

Indexing is crucial for optimizing query performance in MongoDB. An index is a special data structure that stores a small portion of the collection's data in an easy-to-traverse form. Indexes improve the speed of read operations by allowing MongoDB to quickly locate documents without scanning every document in a collection (full collection scan).

## Why Use Indexes?
*   **Faster Queries:** Drastically reduces the time taken for `find()` queries, sorts, and aggregations.
*   **Unique Constraints:** Unique indexes enforce uniqueness for the indexed fields, preventing duplicate data.
*   **Efficient Sorting:** Improves the performance of sort operations by allowing the database to read documents in sorted order directly from the index.

## Basic Indexing:

### 1. Single Field Indexes:
*   Indexes a single field. MongoDB creates a B-tree index by default.
*   Can be ascending (1) or descending (-1). The order often doesn't matter for single-field indexes as MongoDB can traverse in either direction, but it can matter for compound indexes or specific sort orders.

```javascript
db.collection.createIndex({ fieldName: 1 }); // Ascending index
db.collection.createIndex({ fieldName: -1 }); // Descending index
```

### 2. Compound Indexes:
*   Indexes multiple fields in a single index structure.
*   **Order matters:** The order of fields in a compound index is critical. An index `(a, b)` can support queries on `a`, or `(a, b)`, but not typically `b` alone.
*   **Prefixes:** A compound index `(a, b, c)` can support queries that use `a`, `(a, b)`, or `(a, b, c)`. It *cannot* support queries on `(b, c)` or `c` alone unless a separate index exists for those.

```javascript
db.collection.createIndex({ field1: 1, field2: -1 });
// This index can support queries on:
// { field1: value }
// { field1: value, field2: value }
// It can also support sorts on { field1: 1, field2: -1 } or { field1: -1, field2: 1 } (for covered queries)
```

## Special Index Types:

### 1. Multikey Indexes:
*   Automatically created if you index a field that holds an array.
*   MongoDB creates a separate index entry for each element of the array.
*   Useful for querying documents based on values within arrays.

```javascript
db.products.createIndex({ tags: 1 }); // If 'tags' is an array: ["electronics", "gadget"]
```

### 2. Text Indexes:
*   Used to support full-text search queries on string content.
*   Allows searching for words and phrases within documents.

```javascript
db.articles.createIndex({ content: "text" });
// Query: db.articles.find({ $text: { $search: "database systems" } });
```
*   You can create a text index on multiple fields, or on all string fields in a document.

### 3. Geospatial Indexes (2dsphere, 2d):
*   Used to query geospatial coordinate data (e.g., longitude, latitude).
*   `2dsphere` index supports queries on spherical geometries.
*   `2d` index supports queries on flat Cartesian geometries.

```javascript
db.places.createIndex({ location: "2dsphere" });
// Query: db.places.find({ location: { $near: { $geometry: { type: "Point", coordinates: [...] }, $maxDistance: 1000 } } });
```

### 4. Hashed Indexes:
*   Computes a hash of the field's value and indexes the hashed value.
*   Supports equality matches but not range queries.
*   Useful for sharding a collection using a hashed shard key.

```javascript
db.users.createIndex({ email: "hashed" });
```

### 5. TTL Indexes (Time-To-Live):
*   Indexes on a date field and automatically remove documents from a collection after a specified number of seconds.
*   Useful for managing data that expires after a certain time, like session data or log events.

```javascript
db.log_events.createIndex({ createdAt: 1 }, { expireAfterSeconds: 3600 }); // Documents expire after 1 hour
```

## Indexing Strategies:

1.  **Identify Query Patterns:** Analyze your application's most frequent and performance-critical queries (`db.collection.explain().find(...)`).
    *   What fields are in `db.collection.find({ ... })` clauses?
    *   What fields are in `db.collection.sort({ ... })` clauses?
    *   What fields are used for `$match` and `$sort` in aggregation pipelines?
    *   What fields are used in `$lookup` operations?

2.  **Covered Queries:** An index *covers* a query if all the fields returned in the query results are available in the index itself, and all fields in the query predicate (the `WHERE` clause) are also in the index.
    *   MongoDB can fulfill covered queries using only the index, without looking at the actual documents, which is very fast.
    *   In `explain()` output, look for `indexOnly: true` (or similar depending on MongoDB version) in the `winningPlan`.

3.  **Sort Order and Compound Indexes:**
    *   If you frequently query on `field1` and sort by `field2`, a compound index `(field1: 1, field2: 1)` can optimize both.
    *   If you query on `field1` and sort by `field2` in descending order, an index `(field1: 1, field2: -1)` might be ideal.

4.  **Unique Indexes for Constraints:** Use unique indexes to enforce uniqueness constraints on fields like usernames, emails, or product SKUs.

5.  **Sparse Indexes:** Indexes that only contain entries for documents that have the indexed field.
    *   Useful when only a subset of documents contains a specific field, and you only query on that subset.
    *   `db.collection.createIndex({ fieldName: 1 }, { sparse: true });`

6.  **Analyze `explain()` Output:** Always use `explain()` to see if your indexes are being used effectively. Look for:
    *   `COLLSCAN`: Full collection scan (bad).
    *   `IXSCAN`: Index scan (good).
    *   `totalKeysExamined` and `totalDocsExamined`: Aim to keep `totalDocsExamined` close to `totalKeysExamined` and `nReturned`. If `totalDocsExamined` is much higher, the index might not be selective enough, or another index is needed.

## Index Maintenance:
*   **Avoid Over-indexing:** Every index consumes disk space and adds overhead to write operations (inserts, updates, deletes). Only create indexes that are truly necessary.
*   **Remove Unused Indexes:** Periodically review and remove indexes that are no longer used (`db.collection.aggregate([{$indexStats: {}}])` can help).
*   **Background Index Creation:** Create indexes in the background (`db.collection.createIndex({ field: 1 }, { background: true })`) to avoid blocking read/write operations on the collection during creation.

Effective indexing is an ongoing process of monitoring, analyzing query performance, and iteratively refining your indexes based on your application's evolving workload.
