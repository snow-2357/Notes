# 3.6 Aggregation Pipeline (MongoDB)

The MongoDB Aggregation Pipeline is a powerful framework for data aggregation. It allows you to process data records and return computed results. It's similar to the concept of `GROUP BY` in SQL, but far more flexible and versatile, enabling complex data transformations and analyses directly within the database.

## How it Works:
The aggregation pipeline consists of one or more *stages*. Each stage transforms the documents as they pass through the pipeline. Documents enter the pipeline, pass through each stage, and are transformed according to the stage's operation. The output of one stage becomes the input for the next stage.

## Key Concepts:

1.  **Stages:** Each stage is an operation that processes documents. Common stages include:
    *   `$match`: Filters documents to pass only those that match the specified condition(s) to the next pipeline stage. (Similar to `WHERE` clause in SQL).
    *   `$project`: Reshapes each document in the stream, including or excluding fields, or adding new fields based on expressions. (Similar to `SELECT` in SQL).
    *   `$group`: Groups documents by some specified identifier expression and applies accumulator expressions to each group. (Similar to `GROUP BY` in SQL).
    *   `$sort`: Reorders the document stream by a specified key. (Similar to `ORDER BY` in SQL).
    *   `$limit`: Passes the first `N` documents to the next stage. (Similar to `LIMIT` in SQL).
    *   `$skip`: Skips the first `N` documents and passes the rest to the next stage. (Similar to `OFFSET` in SQL).
    *   `$unwind`: Deconstructs an array field from the input documents to output a document for each element. (Useful for working with embedded arrays).
    *   `$lookup`: Performs a left outer join to an unsharded collection in the same database to filter in documents from the "joined" collection for processing.
    *   `$addFields`: Adds new fields to documents. Similar to `$project` but keeps existing fields by default.
    *   `$set`: Adds new fields to documents or replaces existing fields.

2.  **Expressions:** Operators used within stages (especially `$project`, `$group`, `$addFields`) to specify criteria, perform computations, or transform data.
    *   **Field Path:** `$field` to reference a field.
    *   **Literals:** Numbers, strings, booleans.
    *   **System Variables:** `$$ROOT`, `$$NOW`.
    *   **Arithmetic Operators:** `$add`, `$subtract`, `$multiply`, `$divide`, `$mod`.
    *   **String Operators:** `$concat`, `$substr`, `$toUpper`, `$toLower`.
    *   **Date Operators:** `$dayOfMonth`, `$month`, `$year`, `$dayOfWeek`.
    *   **Conditional Operators:** `$cond`, `$ifNull`, `$switch`.
    *   **Array Operators:** `$size`, `$arrayElemAt`.
    *   **Accumulators (used with `$group`):** `$sum`, `$avg`, `$min`, `$max`, `$first`, `$last`, `$push`.

## Example: Calculating Total Sales by Category

Suppose you have an `orders` collection with documents like:
```json
{ "_id": 1, "item": "laptop", "category": "electronics", "price": 1200, "quantity": 1 }
{ "_id": 2, "item": "mouse", "category": "electronics", "price": 25, "quantity": 2 }
{ "_id": 3, "item": "t-shirt", "category": "apparel", "price": 30, "quantity": 5 }
{ "_id": 4, "item": "keyboard", "category": "electronics", "price": 75, "quantity": 1 }
```

To calculate the total sales for each category:

```javascript
db.orders.aggregate([
  {
    $match: {
      "quantity": { $gt: 0 } // Only consider orders with positive quantity
    }
  },
  {
    $group: {
      _id: "$category", // Group by the 'category' field
      totalSales: { $sum: { $multiply: ["$price", "$quantity"] } }, // Calculate total sales for each group
      averageQuantity: { $avg: "$quantity" }, // Calculate average quantity
      count: { $sum: 1 } // Count documents in each group
    }
  },
  {
    $sort: {
      totalSales: -1 // Sort results by totalSales in descending order
    }
  },
  {
    $project: {
      _id: 0, // Exclude the default _id field
      category: "$_id", // Rename _id to category
      totalSales: 1, // Include totalSales
      averageQuantity: { $round: ["$averageQuantity", 2] }, // Round average quantity to 2 decimal places
      numberOfOrders: "$count" // Include count as numberOfOrders
    }
  }
]);
```

**Output:**
```json
[
  { "category": "electronics", "totalSales": 1300, "averageQuantity": 1.33, "numberOfOrders": 3 },
  { "category": "apparel", "totalSales": 150, "averageQuantity": 5, "numberOfOrders": 1 }
]
```

## Optimizing Aggregation Pipelines:

*   **Order of Stages:** Place `$match` and `$project` stages as early as possible in the pipeline.
    *   `$match` reduces the number of documents passed to subsequent stages.
    *   `$project` reduces the number of fields (and thus document size) passed to subsequent stages.
*   **Indexes:** Use indexes to optimize `$match` and `$sort` stages. If a `$match` or `$sort` stage is the first in the pipeline, and it uses an indexable field, MongoDB can use an index to perform the operation.
*   **Avoid `$unwind` on large arrays:** `$unwind` can significantly increase the number of documents in the pipeline. Use it judiciously.
*   **Memory Limits:** Aggregation operations have a default memory limit (100MB). For larger operations, you might need to enable `allowDiskUse: true` (which uses temporary files on disk, but can be slower).
*   **`$lookup` Usage:** While `$lookup` allows joining, it can be expensive. Consider your schema design to minimize its use if performance is critical (see 3.5 MongoDB Schema Design).
*   **`$facet`:** Use `$facet` for multi-faceted aggregations, allowing different aggregation pipelines to run concurrently on the same input set of documents within a single stage.

The Aggregation Pipeline is an extremely powerful tool for data analysis and reporting directly within MongoDB. Mastering its various stages and expressions is key to efficiently processing and deriving insights from your NoSQL data.
