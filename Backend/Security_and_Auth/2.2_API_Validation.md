# 2.2 API Validation

API validation is the process of ensuring that data received by your backend API (from clients or other services) conforms to expected formats, types, and constraints. It's a critical security measure and also ensures the reliability and correctness of your application logic.

## Why is API Validation Crucial?
1.  **Security:** Prevents common vulnerabilities like SQL injection, cross-site scripting (XSS), and buffer overflows by sanitizing and restricting input. Malicious or malformed input is a primary vector for attacks.
2.  **Data Integrity:** Ensures that only valid data enters your system, maintaining the consistency and reliability of your database and application state.
3.  **Application Stability:** Prevents errors, crashes, and unexpected behavior that can occur when your application tries to process invalid data.
4.  **User Experience:** Provides clear and immediate feedback to clients (users or other services) when their input is incorrect, allowing them to correct it.
5.  **Maintainability:** Reduces the amount of defensive programming needed deeper within your business logic, as you can trust that incoming data has already been vetted.

## Where to Validate:

1.  **Client-side Validation (Frontend):**
    *   **Purpose:** Improves user experience by providing immediate feedback.
    *   **Limitation:** Easily bypassed and **cannot be trusted** for security. Always re-validate on the server.

2.  **Server-side Validation (Backend):**
    *   **Purpose:** The ultimate and most critical line of defense for data integrity and security.
    *   **Location:** Typically implemented in middleware, route handlers, or service layers before data interacts with the database.

## Types of Validation:

*   **Syntax/Format Validation:**
    *   **Type Checking:** Is it a string, number, boolean, array, object?
    *   **Format Checking:** Does it match a specific pattern (email, URL, UUID, phone number, date format)? (e.g., using regular expressions).
    *   **Length Constraints:** Minimum/maximum length for strings or number of items in an array.
    *   **Presence:** Is a required field present?

*   **Semantic/Business Logic Validation:**
    *   **Range Constraints:** Is a number within an acceptable range (e.g., age > 0)?
    *   **Uniqueness:** Is an email address or username already taken? (often requires database lookup).
    *   **Referential Integrity:** Does a foreign key reference an existing record?
    *   **Conditional Logic:** Is field B present if field A has a certain value?

## Common Validation Libraries in Node.js:

1.  **Joi:** A powerful schema description language and data validator.
    *   Highly expressive, allowing complex nested schemas and custom validation rules.
    *   Separates validation logic from business logic.

    ```javascript
    const Joi = require('joi');
    const express = require('express');
    const app = express();
    app.use(express.json());

    // Define a Joi schema for user registration
    const userSchema = Joi.object({
      username: Joi.string().alphanum().min(3).max(30).required(),
      password: Joi.string().pattern(new RegExp('^[a-zA-Z0-9]{3,30}$')).required(),
      email: Joi.string().email({ minDomainSegments: 2, tlds: { allow: ['com', 'net'] } }).required(),
      age: Joi.number().integer().min(18).max(100),
      isPremium: Joi.boolean().default(false),
    });

    // Middleware for Joi validation
    function validate(schema, property) {
      return (req, res, next) => {
        const { error } = schema.validate(req[property]);
        const valid = error == null;

        if (valid) {
          next();
        } else {
          const { details } = error;
          const message = details.map(i => i.message).join(',');
          console.log("Validation error:", message);
          res.status(400).json({ error: message });
        }
      };
    }

    app.post('/register', validate(userSchema, 'body'), (req, res) => {
      // If we reach here, the request body is valid
      const newUser = req.body;
      // Save user to database...
      res.status(201).json({ message: 'User registered successfully!', user: newUser });
    });

    app.listen(3000, () => console.log('Server running on port 3000'));
    ```

2.  **Yup:** A JavaScript schema builder for value parsing and validation. Similar to Joi but often considered more lightweight and React-friendly (integrates well with form libraries).

3.  **Zod:** A TypeScript-first schema declaration and validation library. Provides excellent type inference, which is a huge benefit for TypeScript projects.

4.  **Express-validator:** A set of Express.js middleware that wraps `validator.js` functionalities, providing a more imperative API directly integrated with Express.

## Validation Best Practices:
*   **Fail Fast, Fail Early:** Validate input as early as possible in the request-response cycle. This minimizes resource usage for invalid requests.
*   **Comprehensive Error Messages:** Provide clear, user-friendly, and actionable error messages. Avoid exposing internal server details.
*   **Sanitization vs. Validation:** Validation ensures data is correct; sanitization cleans or escapes data to prevent malicious content (e.g., removing HTML tags from user input). Both are important.
*   **DRY (Don't Repeat Yourself):** Define validation schemas once and reuse them across different endpoints or contexts.
*   **Versioning:** Ensure your validation rules evolve with your API versions.
*   **Test Thoroughly:** Write unit and integration tests for all validation rules to ensure they work as expected.

By implementing robust API validation, you create a more secure, stable, and reliable backend service that is easier to maintain and interact with.
