# 1.1 Streams

Streams are a fundamental concept in Node.js, providing a way to handle reading or writing files, network communications, or any kind of end-to-end information exchange in an efficient, chunked manner. They are instances of `EventEmitter` and offer a more memory-efficient approach than traditional data handling for large data sets.

## Why Use Streams?
*   **Memory Efficiency:** Instead of loading an entire file or data into memory before processing, streams process data in small chunks. This is crucial for handling large files or continuous data flows (like video streams) without exhausting available memory.
*   **Time Efficiency:** Data processing can begin as soon as the first chunk arrives, rather than waiting for the entire payload. This reduces latency.
*   **Composability:** Streams are highly composable using the `pipe()` method, allowing you to chain operations (e.g., read, compress, encrypt, write) in a declarative way.

## Types of Streams:
Node.js offers four fundamental stream types:

1.  **Readable Streams:** Abstract source from which data is read.
    *   Examples: `fs.createReadStream()` (for reading files), HTTP responses (`http.IncomingMessage`), `process.stdin`.
    *   Key events: `data`, `end`, `error`, `readable`.
    *   Key methods: `read()`, `pipe()`.

2.  **Writable Streams:** Abstract destination to which data is written.
    *   Examples: `fs.createWriteStream()` (for writing to files), HTTP requests (`http.ClientRequest`), `process.stdout`.
    *   Key events: `drain`, `finish`, `error`, `pipe`.
    *   Key methods: `write()`, `end()`.

3.  **Duplex Streams:** Streams that are both `Readable` and `Writable`.
    *   Examples: TCP sockets (`net.Socket`), Zlib streams (`zlib.Gzip`).
    *   Behave as a readable stream on one end and a writable stream on the other.

4.  **Transform Streams:** Duplex streams that can modify or transform the data as it's written and read.
    *   Examples: Zlib streams (`zlib.createGzip()`, `zlib.createGunzip()`), Crypto streams.
    *   Data written to a transform stream is processed before being made available for reading.

## `pipe()` Method:
The `pipe()` method is the most common way to consume streams. It connects the output of a Readable stream to the input of a Writable stream, automatically managing data flow so that the destination stream is not overwhelmed by data from the source stream (backpressure handling).

```javascript
const fs = require('fs');
const zlib = require('zlib'); // For compression

// Create a readable stream from 'input.txt'
const readableStream = fs.createReadStream('input.txt');

// Create a writable stream to 'output.txt'
const writableStream = fs.createWriteStream('output.txt');

// Create a transform stream for compression
const gzip = zlib.createGzip();

// Example 1: Piping a readable stream to a writable stream
// readableStream.pipe(writableStream);
// console.log('File copied using streams.');

// Example 2: Chaining multiple streams (read -> compress -> write)
readableStream
  .pipe(gzip) // Pipe to gzip transform stream
  .pipe(writableStream); // Pipe compressed data to writable stream

console.log('File compressed and written using streams.');

readableStream.on('error', (err) => {
  console.error('Error reading file:', err);
});

writableStream.on('error', (err) => {
  console.error('Error writing file:', err);
});

writableStream.on('finish', () => {
  console.log('Stream operations finished.');
});
```
This example reads `input.txt`, compresses it using `gzip`, and then writes the compressed data to `output.txt`, all in a highly efficient manner.

## Backpressure:
Streams in Node.js automatically handle backpressure. When a Writable stream's internal buffer is full (meaning it cannot process data as fast as the Readable stream is producing it), it signals to the Readable stream to pause. Once the Writable stream is ready for more data, it signals the Readable stream to resume. This prevents memory overflows and ensures efficient resource usage.

## Stream Events:
*   **`data`**: Emitted when a chunk of data is available for reading.
*   **`end`**: Emitted when there is no more data to be consumed from the stream.
*   **`finish`**: Emitted when all data has been flushed to the underlying system (for Writable streams).
*   **`error`**: Emitted if an error occurs.
*   **`pipe`**: Emitted when the `pipe()` method is called on a readable stream.
*   **`unpipe`**: Emitted when the `unpipe()` method is called on a readable stream.
*   **`close`**: Emitted when the underlying resource (e.g., file descriptor) has been closed.

Understanding streams is crucial for building performant and scalable Node.js applications, especially when dealing with I/O-intensive operations.
