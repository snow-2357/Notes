# 1.3 Logging

Logging is a critical aspect of any production-ready backend application. It involves recording events, errors, and operational information to help monitor application health, debug issues, understand user behavior, and ensure security. Effective logging provides visibility into your application's runtime.

## Why is Logging Important?
*   **Debugging:** Pinpoint the source of errors and unexpected behavior in development and production environments.
*   **Monitoring:** Track application performance, resource usage, and key metrics.
*   **Auditing/Security:** Record important events (e.g., login attempts, data modifications) for security audits and compliance.
*   **Troubleshooting:** Help support teams diagnose and resolve customer issues.
*   **Understanding Application Flow:** Trace how requests are processed and how data moves through the system.

## Types of Logs:
Different types of log messages convey different levels of severity and information. Common logging levels include:

*   **`DEBUG`**: Fine-grained informational events that are most useful to debug an application.
*   **`INFO`**: Informational messages that highlight the progress of the application at a coarse-grained level.
*   **`WARN`**: Potentially harmful situations that might indicate a problem.
*   **`ERROR`**: Error events that might still allow the application to continue running.
*   **`FATAL`**: Very severe error events that will likely lead to the application aborting.

## Logging Best Practices:
1.  **Use a Logging Library:** Avoid `console.log()` in production. Use dedicated logging libraries that provide features like logging levels, structured logging, transport mechanisms, and integration with monitoring systems. Popular Node.js libraries include Winston, Pino, and Bunyan.
2.  **Structured Logging:** Output logs in a structured format (e.g., JSON) rather than plain text. This makes logs easily parsable by machines, facilitating analysis, querying, and integration with log management systems (ELK Stack, Splunk, Datadog).
3.  **Contextual Information:** Include relevant context in your log messages. For example, for an API request, include `request ID`, `user ID`, `endpoint`, `IP address`, `timestamp`.
4.  **Appropriate Logging Levels:** Use the correct logging level for each message. Don't log `DEBUG` messages in production by default, but make it configurable.
5.  **Centralized Log Management:** Ship logs from all instances of your application to a centralized log management system. This allows for aggregation, searching, filtering, and alerting across your entire infrastructure.
6.  **Asynchronous Logging:** Logging operations should ideally be asynchronous and non-blocking to avoid impacting application performance. Logging libraries usually handle this.
7.  **Sensitive Data:** NEVER log sensitive information like passwords, API keys, credit card numbers, or personally identifiable information (PII). Ensure proper redaction or filtering.
8.  **Error Handling:** Log errors comprehensively, including stack traces, error codes, and request details.
9.  **Performance:** Be mindful of the performance overhead of excessive logging. Log what's necessary, but don't log every single variable change.

## Example with Winston (Popular Node.js Logger):

```javascript
const winston = require('winston');

// 1. Create a logger instance
const logger = winston.createLogger({
  level: 'info', // Default logging level
  format: winston.format.json(), // Structured logging in JSON format
  // format: winston.format.simple(), // Or simple text format
  transports: [
    // Console transport: log to console
    new winston.transports.Console({
      format: winston.format.combine(
        winston.format.colorize(), // Add colors for console output
        winston.format.simple()    // Simple format for console
      ),
      level: 'debug' // Can set different levels for different transports
    }),
    // File transport: log to a file
    new winston.transports.File({ filename: 'error.log', level: 'error' }),
    new winston.transports.File({ filename: 'combined.log' })
  ],
});

// If we're not in production then log to the `console` with the format:
// `${info.level}: ${info.message} JSON.stringify({ ...rest })`
if (process.env.NODE_ENV !== 'production') {
  logger.add(new winston.transports.Console({
    format: winston.format.simple(),
  }));
}

// 2. Use the logger
logger.info('Application started successfully.', { service: 'auth-service', startupTime: new Date() });
logger.warn('Deprecation notice: Feature X will be removed in v2.0', { feature: 'X' });
logger.error('Failed to connect to database.', { dbHost: 'localhost', port: 27017, error: new Error('Connection refused') });
logger.debug('User authenticated', { userId: '123', ip: '192.168.1.1' });

// Example of an Express middleware for request logging
function requestLogger(req, res, next) {
  const start = process.hrtime.bigint();
  res.on('finish', () => {
    const end = process.hrtime.bigint();
    const durationMs = Number(end - start) / 1_000_000;
    logger.info('HTTP Request', {
      method: req.method,
      url: req.url,
      statusCode: res.statusCode,
      duration: `${durationMs.toFixed(2)}ms`,
      ip: req.ip,
      // userId: req.user ? req.user.id : 'guest', // if authentication is in place
    });
  });
  next();
}

// app.use(requestLogger); // Example usage in an Express app
```

By implementing robust logging practices, you can gain invaluable insights into your backend application's behavior and health, significantly improving your ability to develop, deploy, and maintain reliable services.
