# 1.7 Middleware Patterns

Middleware is a crucial concept in many web frameworks, especially in Node.js with frameworks like Express.js, Koa, or Hapi. It refers to functions that have access to the request object (`req`), the response object (`res`), and the next middleware function in the application's request-response cycle. These functions can perform various tasks:

*   Execute any code.
*   Make changes to the request and the response objects.
*   End the request-response cycle.
*   Call the next middleware in the stack.

## Why Use Middleware?
Middleware allows you to cleanly separate concerns and add functionality to your application without cluttering your main route handlers. Common use cases include:
*   Logging requests.
*   Authentication and authorization checks.
*   Parsing request bodies (JSON, URL-encoded).
*   Handling CORS (Cross-Origin Resource Sharing).
*   Compressing responses.
*   Error handling.
*   Rate limiting.

## Middleware in Express.js:

Express.js is a classic example of a framework that heavily utilizes middleware. There are different types of middleware in Express:

1.  **Application-level middleware:** Bound to an instance of the `app` object using `app.use()` or `app.METHOD()`.
    ```javascript
    const express = require('express');
    const app = express();

    // A simple logger middleware
    app.use((req, res, next) => {
      console.log('Time:', Date.now(), ' - Method:', req.method, ' - URL:', req.originalUrl);
      next(); // Pass control to the next middleware function
    });

    // Route-specific middleware
    app.get('/users/:id', (req, res, next) => {
      console.log('Request Type:', req.method);
      next(); // Pass control to the next middleware in this route handler
    }, (req, res) => {
      res.send(`User: ${req.params.id}`);
    });

    app.listen(3000);
    ```

2.  **Router-level middleware:** Works the same as application-level middleware but is bound to an instance of `express.Router()`.
    ```javascript
    const express = require('express');
    const router = express.Router();

    // Logger for this specific router
    router.use((req, res, next) => {
      console.log('Router Time:', Date.now());
      next();
    });

    router.get('/', (req, res) => {
      res.send('Birds home page');
    });

    // app.use('/birds', router); // Mount the router to a path
    ```

3.  **Error-handling middleware:** Always takes four arguments: `(err, req, res, next)`.
    ```javascript
    app.use((err, req, res, next) => {
      console.error(err.stack);
      res.status(500).send('Something broke!');
    });
    ```
    *   Error-handling middleware must be defined *last* in the middleware stack to catch errors from preceding middleware and route handlers.

4.  **Built-in middleware:** `express.static`, `express.json`, `express.urlencoded`.
    *   `express.static`: Serves static assets.
    *   `express.json()`: Parses incoming requests with JSON payloads.
    *   `express.urlencoded()`: Parses incoming requests with URL-encoded payloads.

5.  **Third-party middleware:** Middleware for specific tasks, like `cookie-parser`, `cors`, `helmet`, `morgan`, `express-rate-limit`.
    ```javascript
    const express = require('express');
    const app = express();
    const morgan = require('morgan'); // For request logging

    app.use(morgan('tiny')); // Use 'tiny' predefined format for logging
    app.use(express.json()); // Parse JSON request bodies

    app.post('/api/data', (req, res) => {
      console.log(req.body); // Contains the parsed JSON data
      res.json({ message: 'Data received!' });
    });

    app.listen(3000);
    ```

## Common Middleware Patterns:

1.  **Request Pre-processing:**
    *   **Authentication:** Verify user credentials (e.g., JWT token). If valid, attach user info to `req.user`.
    *   **Authorization:** Check if the authenticated user has permission to access the requested resource.
    *   **Validation:** Validate incoming request body, query parameters, or headers (e.g., using Joi, Zod).
    *   **Parsing:** Convert raw request body into usable formats (JSON, XML, form data).
    *   **Logging:** Record details of incoming requests.

2.  **Response Post-processing:**
    *   **Compression:** Gzip or Brotli compress the response payload.
    *   **CORS Headers:** Add appropriate `Access-Control-Allow-Origin` headers.
    *   **Security Headers:** Add `Helmet` headers for common web vulnerabilities.

3.  **Conditional Middleware:** Applying middleware only under certain conditions.
    ```javascript
    const authMiddleware = (req, res, next) => { /* ... auth logic ... */ next(); };
    app.get('/admin', authMiddleware, (req, res) => { /* ... admin route ... */ });
    ```

4.  **Chaining Middleware:** Middleware can be chained in an array.
    ```javascript
    const validateUser = (req, res, next) => { /* ... */ next(); };
    const isAdmin = (req, res, next) => { /* ... */ next(); };

    app.get('/admin/dashboard', [authMiddleware, validateUser, isAdmin], (req, res) => {
      res.send('Admin Dashboard');
    });
    ```

## Middleware Best Practices:
*   **Keep them focused:** Each middleware should ideally do one thing well.
*   **Order matters:** The order in which you `app.use()` middleware is crucial, as they execute sequentially. For example, `express.json()` must come before routes that need to parse JSON. Error handlers must come last.
*   **Handle errors:** Use error-handling middleware effectively.
*   **Don't forget `next()`:** Unless you are ending the request-response cycle, always call `next()` to pass control to the next middleware.
*   **Early exit:** If a middleware detects an issue (e.g., unauthorized access, invalid input), it should end the request-response cycle by sending a response (`res.status().send()`) and not call `next()`.

Middleware is an extremely powerful and flexible pattern for structuring backend applications, promoting modularity and maintainability.
