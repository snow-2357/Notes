# 3.1 Streams

Streams are fundamental to Node.js's ability to handle large amounts of data efficiently and in a non-blocking manner. They are an abstract interface for working with streaming data, allowing Node.js applications to process data piece by piece rather than holding the entire dataset in memory.

## What are Streams?

At its core, a stream is an event emitter. Data flows through streams as a sequence of small chunks. This model is incredibly powerful for I/O operations and data processing.

## Why Use Streams?

1.  **Memory Efficiency:** Streams allow you to process large files or data feeds without buffering them entirely into memory. You read or write data in chunks, keeping memory usage low and constant regardless of the total data size.
2.  **Time Efficiency:** Processing can begin as soon as the first chunk of data arrives, rather than waiting for the entire data set to be available. This reduces latency.
3.  **Composability:** Streams can be easily piped together (`.pipe()`) to create complex data processing pipelines, making code modular and reusable.

## Types of Streams

Node.js defines four fundamental types of streams, all of which are instances of `EventEmitter` and `stream.Readable`, `stream.Writable`, `stream.Duplex`, or `stream.Transform`.

1.  **`Readable` Streams:**
    *   Act as a **source** of data.
    *   Data can be consumed from a Readable stream (e.g., `fs.createReadStream`, `http.IncomingMessage` from a client request, `process.stdin`).
    *   **Modes:**
        *   **Flowing Mode:** Data is read automatically and passed to your application as fast as possible. You interact with `data` events.
        *   **Paused Mode:** You must explicitly call `read()` to pull chunks of data.
    *   **Events:** `data`, `end`, `error`, `close`, `readable`.

    ```javascript
    const fs = require('fs');
    const readableStream = fs.createReadStream('large-file.txt', { encoding: 'utf8', highWaterMark: 16 * 1024 }); // 16KB chunks

    readableStream.on('data', (chunk) => {
      console.log(`Received ${chunk.length} bytes of data.`);
      // Process chunk
    });

    readableStream.on('end', () => {
      console.log('Finished reading file.');
    });

    readableStream.on('error', (err) => {
      console.error('Error reading file:', err);
    });
    ```

2.  **`Writable` Streams:**
    *   Act as a **destination** for data.
    *   Data can be written to a Writable stream (e.g., `fs.createWriteStream`, `http.ServerResponse` to a client, `process.stdout`).
    *   **Events:** `finish`, `error`, `close`, `pipe`, `unpipe`, `drain`.

    ```javascript
    const fs = require('fs');
    const writableStream = fs.createWriteStream('output.txt');

    writableStream.write('Hello, Node.js streams!\n');
    writableStream.write('This is another line.\n');
    writableStream.end('Finishing up.'); // Signals no more data will be written

    writableStream.on('finish', () => {
      console.log('All writes are now complete.');
    });

    writableStream.on('error', (err) => {
      console.error('Error writing file:', err);
    });
    ```

3.  **`Duplex` Streams:**
    *   Are both `Readable` and `Writable`.
    *   Data written to a Duplex stream can be read from it (e.g., `net.Socket` for TCP connections, `crypto.createCipher` for encryption).

    ```javascript
    const net = require('net');
    // Example of a TCP socket being a duplex stream
    const socket = new net.Socket();
    socket.write('Hello from client!');
    socket.on('data', (data) => {
        console.log('Received:', data.toString());
    });
    // In a real app, you'd connect it: socket.connect(port, host);
    ```

4.  **`Transform` Streams:**
    *   Are `Duplex` streams that can modify or transform data as it is written to one side and read from the other.
    *   Data is written, processed, and then read (e.g., `zlib.createGzip` for compression, `crypto.createCipher` for encryption).
    *   They implement `_transform()` instead of `_read()` and `_write()`.

    ```javascript
    const { Transform } = require('stream');

    // Custom transform stream to convert text to uppercase
    class UppercaseTransform extends Transform {
      _transform(chunk, encoding, callback) {
        this.push(chunk.toString().toUpperCase());
        callback();
      }
    }

    const uppercaseStream = new UppercaseTransform();
    uppercaseStream.write('hello');
    uppercaseStream.write('world');
    uppercaseStream.end();

    uppercaseStream.on('data', (chunk) => {
      console.log(chunk.toString()); // HELLOWORLD (chunks might merge)
    });
    ```

## The `pipe()` Method

The `pipe()` method is the easiest way to consume a Readable stream and send its output to a Writable stream. It handles flow control (backpressure) automatically.

```javascript
const fs = require('fs');
const zlib = require('zlib'); // Node.js built-in compression module

// Compress a file
fs.createReadStream('input.txt')
  .pipe(zlib.createGzip()) // Transform stream: compresses data
  .pipe(fs.createWriteStream('input.txt.gz')) // Writable stream: writes compressed data to file
  .on('finish', () => console.log('File successfully compressed.'));

// Decompress a file (pipeline is more robust, see below)
// fs.createReadStream('input.txt.gz')
//   .pipe(zlib.createGunzip()) // Transform stream: decompresses data
//   .pipe(fs.createWriteStream('decompressed.txt'))
//   .on('finish', () => console.log('File successfully decompressed.'));
```

## The `pipeline()` Method (Node.js v10+)

The `stream.pipeline()` method is a more robust way to chain streams, especially for handling errors and ensuring proper cleanup. It's recommended over `pipe()` for most production use cases involving multiple streams.

```javascript
const { pipeline } = require('stream');
const fs = require('fs');
const zlib = require('zlib');

pipeline(
  fs.createReadStream('input.txt'),
  zlib.createGzip(),
  fs.createWriteStream('input.txt.gz'),
  (err) => {
    if (err) {
      console.error('Pipeline failed.', err);
    } else {
      console.log('Pipeline succeeded.');
    }
  }
);
```
`pipeline()` ensures that all streams are properly closed and handles errors propagating through the chain.

## Backpressure

Backpressure is a crucial mechanism in streams that prevents a Writable stream from being overwhelmed by a faster Readable stream.

-   **How it Works:** When a Writable stream receives data faster than it can process, its `.write()` method returns `false`. This signals to the Readable stream to pause sending data.
-   **`drain` Event:** Once the Writable stream has processed its internal buffer and is ready to accept more data, it emits a `drain` event. The Readable stream can then resume sending data.
-   **Importance:** Without backpressure, a fast Readable stream could continuously send data to a slow Writable stream, causing the Writable stream's internal buffer to grow indefinitely, leading to memory exhaustion and application crashes. The `pipe()` and `pipeline()` methods automatically handle backpressure.

## Practical Use Cases

-   **File Processing:** Reading and writing large files, logging.
-   **Network Communication:** Handling HTTP requests/responses, TCP sockets.
-   **Data Transformation:** Compressing/decompressing data, encrypting/decrypting, parsing (e.g., CSV).
-   **Real-time Analytics:** Processing live data feeds.

Streams are a cornerstone of efficient data handling in Node.js, empowering developers to build scalable and performant applications that are not bottlenecked by I/O.
