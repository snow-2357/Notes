# 3.5 `events` and `EventEmitter`

Node.js is built upon an event-driven architecture, where components communicate by emitting and listening for events. The `events` module, and specifically the `EventEmitter` class, is the cornerstone of this paradigm, providing a simple yet powerful mechanism for handling events in your applications. Many core Node.js modules, like Streams, HTTP, and File System (`fs`), inherit from `EventEmitter`.

## What is `EventEmitter`?

The `EventEmitter` class implements the **Observer Pattern** (also known as Publish-Subscribe). It allows you to:
-   **Emit** named events.
-   **Register listener functions** that are called when specific events are emitted.

Essentially, it's a way for objects to signal that something has happened, and for other objects to react to those signals without being tightly coupled to the emitter.

## Basic Usage

To use `EventEmitter`, you first need to `require` the `events` module and create an instance of `EventEmitter`.

```javascript
const EventEmitter = require('events');
const myEmitter = new EventEmitter();

// 1. Registering an event listener using .on()
myEmitter.on('greet', (name) => {
  console.log(`Hello, ${name}!`);
});

// 2. Emitting an event using .emit()
myEmitter.emit('greet', 'Alice'); // Output: Hello, Alice!
myEmitter.emit('greet', 'Bob');   // Output: Hello, Bob!
```

### Key Methods

-   **`emitter.on(eventName, listener)` / `emitter.addListener(eventName, listener)`**:
    Registers a `listener` function to be called when the `eventName` event is emitted. Listeners are executed in the order they were registered.

-   **`emitter.emit(eventName[, ...args])`**:
    Synchronously calls each of the listeners registered for the `eventName` event, passing any supplied arguments to each listener.

-   **`emitter.once(eventName, listener)`**:
    Registers a `listener` function that will be invoked at most once for the `eventName` event. After it's invoked, it's automatically removed.

    ```javascript
    myEmitter.once('setup', () => {
      console.log('Application setup completed!');
    });

    myEmitter.emit('setup'); // Output: Application setup completed!
    myEmitter.emit('setup'); // Nothing happens, listener already removed
    ```

-   **`emitter.removeListener(eventName, listener)` / `emitter.off(eventName, listener)`**:
    Removes a specific `listener` from the listener array for the `eventName` event. The `listener` must be the same function instance that was originally registered.

-   **`emitter.removeAllListeners([eventName])`**:
    Removes all listeners for the specified `eventName` or, if no `eventName` is provided, removes all listeners for all events registered on the `EventEmitter` instance.

-   **`emitter.eventNames()`**:
    Returns an array of strings that lists the event names for which listeners are registered on the emitter.

-   **`emitter.listenerCount(eventName)`**:
    Returns the number of listeners for a given `eventName`.

-   **`emitter.getMaxListeners()` / `emitter.setMaxListeners(n)`**:
    By default, `EventEmitter` instances will print a warning if more than 10 listeners are added for a particular event. This helps catch memory leaks. You can change this limit using `setMaxListeners()`.

## Error Events

The `error` event is special. If an `EventEmitter` instance emits an `'error'` event and there are no listeners registered for it, Node.js will, by default, throw the `Error` as an uncaught exception and exit the process. Therefore, it's crucial to always handle `error` events:

```javascript
myEmitter.on('error', (err) => {
  console.error('Whoops! There was an error:', err.message);
  // Do not let the process exit, log error, try to recover, etc.
});

myEmitter.emit('error', new Error('Something went wrong!')); // Output: Whoops! There was an error: Something went wrong!
```

## Extending `EventEmitter`

You can make your own custom classes event-driven by extending `EventEmitter`. This is a common pattern for building reusable components that can communicate with other parts of your application.

**Using ES6 Classes (Recommended):**

```javascript
class MyCustomLogger extends EventEmitter {
  constructor() {
    super(); // Call the parent EventEmitter constructor
  }

  log(message) {
    this.emit('message', message, Date.now());
  }

  error(err) {
    this.emit('error', err);
  }
}

const logger = new MyCustomLogger();

logger.on('message', (msg, timestamp) => {
  console.log(`[${new Date(timestamp).toLocaleTimeString()}] LOG: ${msg}`);
});

logger.on('error', (err) => {
  console.error('LOGGER ERROR:', err.message);
});

logger.log('User logged in.');
logger.error(new Error('Failed to connect to database.'));
```

**Using `util.inherits` (Legacy):**

```javascript
const util = require('util');
const EventEmitter = require('events');

function MyLegacyLogger() {
  EventEmitter.call(this); // Call the parent constructor
}
util.inherits(MyLegacyLogger, EventEmitter); // Inherit prototype methods

MyLegacyLogger.prototype.log = function(message) {
  this.emit('message', message);
};

// ... usage similar to ES6 class
```

## Practical Use Cases

-   **Custom Event Systems:** Build internal communication systems within your application.
-   **State Changes:** Emit events when an object's state changes, allowing other parts of the application to react.
-   **Stream Modules:** Streams (Readable, Writable, Duplex, Transform) are all instances of `EventEmitter`, emitting events like `data`, `end`, `error`, `finish`, `drain`.
-   **API Design:** Create cleaner, more decoupled APIs for your modules.

The `EventEmitter` is a powerful primitive that underpins much of Node.js's reactive nature, enabling the creation of highly decoupled and scalable applications.
