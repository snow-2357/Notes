# 5.1 Database Interaction

Databases are essential components of almost all modern web applications, providing persistent storage for application data. Node.js applications, with their asynchronous, non-blocking nature, are well-suited for interacting with databases, as database operations are inherently I/O-bound. This section explores how Node.js applications connect to and interact with various types of databases.

## Overview of Database Types

Databases are broadly categorized into two main types:

1.  **Relational Databases (SQL):**
    *   **Concept:** Store data in structured tables with predefined schemas. Data is organized into rows and columns, and relationships between tables are defined using keys. Adhere to ACID properties (Atomicity, Consistency, Isolation, Durability).
    *   **Examples:** PostgreSQL, MySQL, SQL Server, Oracle, SQLite.
    *   **Query Language:** Structured Query Language (SQL).

2.  **NoSQL Databases:**
    *   **Concept:** Provide a mechanism for storage and retrieval of data that is modeled in means other than the tabular relations used in relational databases. They are often schema-less, offer flexible data models, and are designed for horizontal scalability.
    *   **Examples:**
        *   **Document Databases:** MongoDB, Couchbase (store data in JSON-like documents).
        *   **Key-Value Stores:** Redis, Amazon DynamoDB (store data as a collection of key-value pairs).
        *   **Column-Family Stores:** Cassandra, HBase (store data in column families).
        *   **Graph Databases:** Neo4j (store data in nodes and edges).

## Interacting with Relational Databases (SQL)

Node.js applications can interact with SQL databases using direct drivers or Object-Relational Mappers (ORMs).

### Direct Drivers

-   **Concept:** Low-level libraries that provide direct programmatic access to database functionalities. You write SQL queries yourself.
-   **Examples:**
    *   `pg` for PostgreSQL (`npm install pg`)
    *   `mysql2` for MySQL (`npm install mysql2`)
    *   `sqlite3` for SQLite (`npm install sqlite3`)

```javascript
// Example: PostgreSQL with 'pg' driver
const { Client } = require('pg');

const client = new Client({
  user: 'dbuser',
  host: 'localhost',
  database: 'mydb',
  password: 'password',
  port: 5432,
});

async function getUsers() {
  await client.connect();
  try {
    const res = await client.query('SELECT * FROM users');
    console.log(res.rows); // Array of user objects
  } catch (err) {
    console.error('Error executing query', err.stack);
  } finally {
    await client.end();
  }
}
getUsers();
```

**Pros:**
-   Full control over SQL queries, allowing for highly optimized queries.
-   Typically offers the highest performance due to minimal abstraction.

**Cons:**
-   More boilerplate code.
-   Higher risk of SQL injection if queries are not properly parameterized.
-   Less abstraction means more verbose code for complex interactions.

### Object-Relational Mappers (ORMs)

-   **Concept:** ORMs provide an object-oriented abstraction layer over a relational database. They allow you to define database schemas using JavaScript/TypeScript classes and interact with the database using object methods, rather than writing raw SQL.
-   **Examples:**
    *   **Prisma:** A modern ORM that generates a type-safe client based on your database schema.
    *   **Sequelize:** A promise-based ORM for PostgreSQL, MySQL, MariaDB, SQLite, and Microsoft SQL Server.
    *   **TypeORM:** An ORM that can run in Node.js, Browser, React Native, etc., and supports both ActiveRecord and DataMapper patterns.
    *   **Knex.js:** A "SQL query builder" that's a step below a full ORM but provides a programmatic way to build SQL queries.

## Interacting with NoSQL Databases

Node.js interacts with NoSQL databases using direct drivers or Object-Document Mappers (ODMs).

### Direct Drivers

-   **Concept:** Libraries provided by the database vendor or community to interact directly with the NoSQL database's API.
-   **Examples:**
    *   `mongodb` for MongoDB (`npm install mongodb`)
    *   `node-redis` for Redis (`npm install redis`)

```javascript
// Example: MongoDB with 'mongodb' driver
const { MongoClient } = require('mongodb');
const uri = "mongodb://localhost:27017";
const client = new MongoClient(uri);

async function runMongoDB() {
  try {
    await client.connect();
    const database = client.db('testdb');
    const users = database.collection('users');

    await users.insertOne({ name: 'Alice', age: 30 });
    const docs = await users.find({ age: { $gt: 25 } }).toArray();
    console.log('MongoDB Users:', docs);

  } finally {
    await client.close();
  }
}
runMongoDB();
```

**Pros:**
-   Full control over database operations.
-   Often provides the best performance for raw interactions.

**Cons:**
-   More manual data validation and schema management.
-   More verbose for complex operations.

### Object-Document Mappers (ODMs)

-   **Concept:** ODMs provide an object-oriented abstraction layer over NoSQL document databases, similar to how ORMs work for relational databases. They help enforce schema-like structures on flexible NoSQL databases.

    *   **Mongoose:** The most popular ODM for MongoDB.

-   Can introduce some overhead.

## Connection Management Best Practices

-   **Connection Pooling:** Always use connection pooling for both SQL and NoSQL databases in production. Re-establishing a new database connection for every request is expensive. Pooling reuses existing connections, significantly improving performance.
-   **Environment Variables:** Store sensitive database credentials (host, user, password) in environment variables, not directly in code.
-   **Error Handling and Reconnection Logic:** Implement robust error handling and automatic reconnection logic to gracefully handle temporary database outages.
-   **Transactions:** For operations that require atomicity (all or nothing), use database transactions (supported in most SQL and some NoSQL databases like MongoDB).

Choosing the right database and interaction method depends heavily on your application's data model, scalability requirements, and team expertise. Node.js offers a wide array of tools to connect to virtually any database efficiently.
