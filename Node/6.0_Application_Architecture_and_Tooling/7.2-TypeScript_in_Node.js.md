# 7.2 TypeScript in Node.js

TypeScript has rapidly become a standard for building scalable and maintainable applications, both on the frontend and backend. As a superset of JavaScript, it adds optional static typing to the language, enabling developers to catch errors early, write more robust code, and enhance the development experience, especially in large Node.js projects.

## What is TypeScript?

TypeScript is an open-source programming language developed and maintained by Microsoft. It is a superset of JavaScript, meaning any valid JavaScript code is also valid TypeScript code. The key addition is **static typing**, allowing you to define the types of variables, function parameters, and return values. This type information is then used by the TypeScript compiler (`tsc`) to perform type-checking during compilation, and by IDEs for enhanced developer tooling.

## Why Use TypeScript with Node.js?

1.  **Type Safety:** Catches common programming errors (e.g., trying to call a method on an `undefined` variable, passing the wrong type of argument to a function) at compile time, before the code even runs. This drastically reduces runtime bugs.
2.  **Improved Code Quality and Robustness:** Static types act as a contract for your code, making it more predictable and less prone to unexpected behavior. This leads to more reliable applications.
3.  **Enhanced Developer Experience:**
    -   **Autocompletion & IntelliSense:** IDEs (like VS Code) can provide intelligent autocompletion, type suggestions, and inline error checking, boosting productivity.
    -   **Refactoring:** Confidently refactor code, knowing that type checking will flag inconsistencies.
    -   **Code Documentation:** Types serve as living documentation, making it easier for new developers to understand the codebase and for existing developers to remember the intended usage of functions and objects.
4.  **Scalability and Maintainability:**
    -   **Large Codebases:** Types help manage complexity in large applications by clearly defining data structures and API contracts.
    -   **Team Collaboration:** Facilitates smoother collaboration in large teams by establishing clear expectations for data types and function signatures.
5.  **Modern Framework Support:** Many modern Node.js frameworks, like NestJS, are built with TypeScript as a first-class citizen, leveraging its features extensively.

## Core Concepts of TypeScript (Brief Overview)

-   **Primitive Types:** `string`, `number`, `boolean`, `null`, `undefined`, `symbol`, `bigint`.
-   **`any`:** A type that can represent any JavaScript value. Avoid using it excessively as it defeats the purpose of type safety.
-   **`unknown`:** A type-safe alternative to `any`. You must perform type checking before you can operate on a value of type `unknown`.
-   **`void`:** Used for functions that do not return a value.
-   **`never`:** Represents the type of values that never occur (e.g., a function that always throws an error or never returns).
-   **Interfaces & Type Aliases:** Used to define custom types, especially the shape of objects.
    ```typescript
    interface User {
      id: number;
      name: string;
      email?: string; // Optional property
    }

    type UserProfile = User & {
      age: number;
      address: string;
    }
    ```
-   **Enums:** A way to define a set of named constants.
    ```typescript
    enum UserRole {
      Admin = 'ADMIN',
      Editor = 'EDITOR',
      Viewer = 'VIEWER',
    }
    ```
-   **Generics:** Allow you to write reusable code that works with a variety of types.
    ```typescript
    function identity<T>(arg: T): T {
      return arg;
    }
    let output = identity<string>("myString"); // type of output will be string
    ```
-   **Decorators:** Special kind of declaration that can be attached to classes, methods, accessors, properties, or parameters. (Used extensively in frameworks like NestJS).

## Setting Up TypeScript in a Node.js Project

1.  **Initialize Project:**
    ```bash
    mkdir my-ts-app
    cd my-ts-app
    npm init -y
    ```

2.  **Install TypeScript and Related Tools:**
    ```bash
    npm install --save-dev typescript @types/node
    # For development, ts-node allows running TypeScript files directly without pre-compilation
    npm install --save-dev ts-node
    # For testing, you might need @types/jest, etc.
    ```

3.  **Create `tsconfig.json`:**
    This file configures the TypeScript compiler. You can generate a basic one:
    ```bash
    npx tsc --init
    ```
    A typical `tsconfig.json` for Node.js might look like this:

    ```json
    {
      "compilerOptions": {
        "target": "es2020",                /* Specify ECMAScript target version */
        "module": "commonjs",             /* Specify module code generation: "commonjs", "es2015", "esnext", etc. */
        "outDir": "./dist",               /* Redirect output structure to the directory. */
        "rootDir": "./src",               /* Specify the root directory of source files. */
        "strict": true,                   /* Enable all strict type-checking options. */
        "esModuleInterop": true,          /* Enables emit interoperability between CommonJS and ES Modules via creation of namespace objects for all imports. Implies 'allowSyntheticDefaultImports'. */
        "skipLibCheck": true,             /* Skip type checking all .d.ts files. */
        "forceConsistentCasingInFileNames": true, /* Disallow inconsistently-cased file names. */
        "resolveJsonModule": true,        /* Allow importing .json files */
        "sourceMap": true,                /* Generates corresponding .map file. */
        "baseUrl": ".",                   /* Base directory to resolve non-absolute module names. */
        "paths": {
          "@/*": ["src/*"]                /* Example: alias for 'src' folder */
        }
      },
      "include": [
        "src/**/*.ts"                     /* Include all .ts files in the src directory */
      ],
      "exclude": [
        "node_modules",
        "**/*.spec.ts"                    /* Exclude test files from compilation */
      ]
    }
    ```

4.  **Write TypeScript Code:**
    Create a `src` directory and write your `.ts` files (e.g., `src/app.ts`).

5.  **Compilation:**
    To compile your TypeScript code into JavaScript, run:
    ```bash
    npx tsc
    ```
    This will output JavaScript files into the `dist` directory (as configured in `tsconfig.json`).

6.  **Running in Development:**
    Use `ts-node` to run TypeScript files directly without pre-compilation:
    ```bash
    npx ts-node src/app.ts
    ```
    For auto-reloading during development, you can use `nodemon` with `ts-node`:
    ```bash
    npm install --save-dev nodemon
    # Add a script to package.json
    "scripts": {
      "dev": "nodemon --exec ts-node src/app.ts"
    }
    ```

7.  **Running in Production:**
    Always compile your TypeScript code to JavaScript (`npx tsc`) and then run the compiled JavaScript:
    ```bash
    node dist/app.js
    ```

### ES Modules vs. CommonJS with TypeScript

Configuring `"module"` and `"target"` in `tsconfig.json` is crucial.
-   For **CommonJS** Node.js projects: `module: "commonjs"`
-   For **ES Modules** Node.js projects: `module: "esnext"` or `module: "node16"`, and set `"type": "module"` in your `package.json`. You might also need to use file extensions like `.js` in your `import` statements after compilation.

## Integrating with Node.js Frameworks

-   **Express.js:** To use TypeScript with Express, you'll need the type definitions: `npm install --save-dev @types/express @types/node`.
-   **NestJS:** Built from the ground up with TypeScript, so it's a seamless experience.
-   **Koa.js:** Similarly, install type definitions: `npm install --save-dev @types/koa @types/node`.

## Best Practices

-   **Enable Strict Mode:** Always set `"strict": true` in `tsconfig.json`. This enables a wide range of type-checking rules that lead to more robust code.
-   **Use `@types/*`:** For any third-party JavaScript library you use, install its corresponding type definition package (e.g., `@types/lodash`, `@types/jest`).
-   **Avoid `any` (Where Possible):** Limit the use of `any` to situations where type information is genuinely unknown or impractical to define. Use `unknown` for type-safe handling of unknown types.
-   **Consistent Formatting:** Combine TypeScript with linters (ESLint) and formatters (Prettier) to maintain consistent code style and prevent common issues.
-   **Clear Interfaces/Types:** Design clear and explicit interfaces or types for your data structures, function parameters, and return values.
-   **Migration Strategy:** When migrating an existing JavaScript project, introduce TypeScript incrementally. Start with new files, or convert critical modules first.

TypeScript significantly elevates the quality and maintainability of Node.js applications, making it an invaluable tool for modern backend development.
