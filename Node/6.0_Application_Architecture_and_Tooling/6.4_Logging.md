# 6.4 Logging

Logging is the process of recording events and information that occur during an application's execution. In Node.js applications, especially long-running server processes, effective logging is critical for debugging, monitoring, auditing, security analysis, and understanding application behavior in production environments. Relying solely on `console.log()` is insufficient for production-grade applications due to its limitations.

## Why Logging is Essential

-   **Debugging:** Pinpoint the source of errors and unexpected behavior in complex systems.
-   **Monitoring:** Track application health, performance, and resource utilization over time.
-   **Auditing:** Maintain a record of significant events for security compliance or business processes.
-   **Security:** Detect suspicious activities or intrusion attempts.
-   **Performance Analysis:** Identify bottlenecks or slow operations.
-   **Understanding Behavior:** Gain insights into how users interact with the application.

## Logging Levels

Log levels categorize messages by their severity, allowing you to filter and prioritize information based on the environment (e.g., development, staging, production) or the specific problem you're troubleshooting. Common logging levels (from least to most severe) include:

-   **`trace`:** Fine-grained informational events, usually only of interest to developers during debugging.
-   **`debug`:** Debugging information, typically used for local development.
-   **`info`:** Informational messages highlighting the progress of the application.
-   **`warn`:** Potentially harmful situations or unexpected events that are not errors (e.g., deprecated API usage, a recoverable issue).
-   **`error`:** Runtime errors or unexpected conditions that prevent some functionality from working correctly.
-   **`fatal`:** Very severe error events that will presumably lead the application to abort.

## Logging Libraries

While `console.log` is simple, production applications require more robust logging libraries that support levels, transports, and structured output.

### 1. Winston

Winston is a popular, highly flexible, and extensible logging library for Node.js. It allows you to define multiple "transports" (where logs are sent), format logs, and manage logging levels independently for different transports.

**Key Features:**
-   **Transports:** Console, file, HTTP, stream, daily rotate file, custom transports.
-   **Levels:** Supports standard syslog levels (error, warn, info, debug, verbose, silly) or custom levels.
-   **Formatting:** Customizable log formats (simple, JSON, printf, custom).
-   **Error Handling:** Robust error handling for transports.

```javascript
const winston = require('winston');

const logger = winston.createLogger({
  level: 'info', // Default logging level
  format: winston.format.json(), // JSON format for production
  transports: [
    new winston.transports.Console({
      format: winston.format.combine(
        winston.format.colorize(),
        winston.format.simple() // Simple format for console for readability
      )
    }),
    new winston.transports.File({ filename: 'error.log', level: 'error' }), // Only errors to error.log
    new winston.transports.File({ filename: 'combined.log' }) // All levels to combined.log
  ],
});

// If we're not in production then log to the `console` with the format:
// `${info.level}: ${info.message} JSON.stringify({ ...rest })`
if (process.env.NODE_ENV !== 'production') {
  logger.add(new winston.transports.Console({
    format: winston.format.simple(),
    level: 'debug' // Log debug and above in development console
  }));
}

logger.info('Application started successfully.', { service: 'auth-service' });
logger.warn('Deprecated API endpoint accessed.', { path: '/old/api' });
logger.error('Failed to connect to database.', { dbHost: 'localhost', port: 5432, stack: new Error().stack });
logger.debug('This is a debug message for dev environment.');
```

### 2. Pino

Pino is an extremely fast, low-overhead JSON logger for Node.js. It's optimized for production environments where performance is critical.

**Key Features:**
-   **Performance:** Very high throughput, designed to have minimal impact on application performance.
-   **Structured Logging (JSON):** Logs are always emitted as JSON objects, making them machine-readable and easy to parse by log management systems.
-   **Customization:** Supports custom log levels and serializers.
-   **`pino-pretty`:** A separate tool for pretty-printing JSON logs in development for human readability.

```javascript
const pino = require('pino');

// In production, logs go straight to stdout as JSON
const logger = pino({
  level: process.env.NODE_ENV === 'production' ? 'info' : 'debug',
  // timestamp: pino.stdTimeFunctions.isoTime, // Use ISO time format
});

// To use pino-pretty for development readability:
// pipe output to pino-pretty: node app.js | pino-pretty
// or configure it as a transport (less performant but convenient)
if (process.env.NODE_ENV !== 'production') {
    const pinoDev = pino({
        level: 'debug',
        transport: {
            target: 'pino-pretty',
            options: {
                colorize: true,
                translateTime: 'SYS:HH:MM:ss',
                ignore: 'pid,hostname',
            }
        }
    });
    // In dev, replace the logger with the pretty version
    module.exports = pinoDev;
} else {
    module.exports = logger;
}

logger.info({ service: 'user-service' }, 'User login initiated');
logger.error({ error: 'Auth failed', userId: 'user-xyz' }, 'Authentication failed for user');
logger.debug('Tracing some variable value', { variable: 'someValue' });
```

### 3. Bunyan

Bunyan is another popular JSON logging library that predates Pino. It offers similar features like structured logging and a CLI tool for pretty-printing.

## Structured Logging

-   **Concept:** Instead of simple text strings, logs are emitted as structured data (usually JSON). This allows you to include multiple key-value pairs with each log entry.
-   **Benefits:**
    -   **Machine Readability:** Easily parsed and indexed by log management systems.
    -   **Searchability:** Quickly search and filter logs based on any key (e.g., `reqId`, `userId`, `errorCode`).
    -   **Context:** Provides rich context for debugging, especially in distributed systems.
    -   **Analysis:** Facilitates aggregated analysis and dashboarding (e.g., count errors per service).

**Key Information to Include in Structured Logs:**
-   `timestamp`: When the event occurred.
-   `level`: Severity of the log message.
-   `message`: A human-readable description of the event.
-   `service` / `component`: Which part of the application emitted the log.
-   `reqId` / `traceId`: A unique identifier for a request, allowing tracing across services.
-   `userId`: Identifier for the user associated with the event.
-   `error`: Full error details, including stack trace.

## Contextual Logging with `AsyncLocalStorage`

In distributed systems, it's often useful to attach context (like a request ID or a user ID) to all log messages related to a single request, without explicitly passing the context through every function call. Node.js's `AsyncLocalStorage` (available since Node.js 13.0.0, stable in 14.x) enables this.

```javascript
const { AsyncLocalStorage } = require('async_hooks');
const asyncLocalStorage = new AsyncLocalStorage();

// Middleware to set request context
app.use((req, res, next) => {
  const requestId = generateUniqueId(); // Your function to generate a unique ID
  asyncLocalStorage.run(new Map([['requestId', requestId], ['userId', req.user?.id]]), () => {
    logger.info('Incoming request'); // This log will automatically include requestId and userId
    next();
  });
});

// Somewhere deep in your application logic
function someFunction() {
  const store = asyncLocalStorage.getStore();
  logger.debug('Inside some function', { customData: 'abc', requestId: store?.get('requestId') });
}
```

## Log Management Systems

For production environments, centralizing logs is crucial. Log management systems collect, store, index, and analyze logs from various sources.
-   **ELK Stack (Elasticsearch, Logstash, Kibana):** A popular open-source suite.
-   **Splunk:** A powerful commercial log management platform.
-   **Datadog, New Relic:** APM tools with integrated log management.
-   **Grafana Loki:** Log aggregation system designed for high performance and cost-efficiency.

## Best Practices for Logging

1.  **Don't Use `console.log` in Production:** It's synchronous and blocks the Event Loop, impacting performance. It also lacks features like log levels and structured output.
2.  **Choose the Right Library:** Use Winston for flexibility, Pino for performance.
3.  **Use Appropriate Log Levels:** Filter noisy messages from critical ones.
4.  **Prioritize Structured Logging:** Always emit JSON logs in production for easier parsing and analysis.
5.  **Include Contextual Information:** Attach `reqId`, `userId`, `traceId`, etc., to logs to enable effective tracing and debugging of distributed requests.
6.  **Log Errors with Stack Traces:** Always include the full stack trace for `error` and `fatal` level messages.
7.  **Asynchronous Logging:** Ensure your logging doesn't block the main thread. Most modern loggers handle this by default or through buffering.
8.  **Security:** Never log sensitive information (passwords, API keys, PII) directly. Sanitize data before logging.
9.  **Centralize Logs:** Aggregate logs from all your services into a single log management system.
10. **Monitor Log Volume:** Be aware of the volume of logs generated, as excessive logging can incur storage costs and impact performance.

Effective logging is an investment that pays off immensely when diagnosing issues, monitoring system health, and ensuring the smooth operation of your Node.js applications.
