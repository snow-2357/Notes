# 4.1 TypeScript: Intro and Setup

## Why TypeScript?

TypeScript is a **typed superset of JavaScript** that compiles to plain JavaScript. It was created by Microsoft to help build large-scale applications with fewer bugs.

Think of it as JavaScript with an extra layer of protection. This layer is **static typing**.

**Key Benefits:**

1.  **Catch Errors Early**: With static types, you can catch a whole class of errors during development (in your code editor) and at compile time, long before your code ever runs in a browser.
    ```typescript
    // JavaScript (error at runtime)
    const name = "Gemini";
    name.toUpperCase(); // Works
    // name.someNonExistentMethod(); // Crashes at runtime

    // TypeScript (error at compile time)
    const name: string = "Gemini";
    name.toUpperCase(); // Works
    // name.someNonExistentMethod(); // Error shown in your editor!
    ```

2.  **Improved Autocomplete & Readability**: Your code editor understands the shapes of your objects, providing better autocompletion and making the code easier for other developers to understand.

3.  **Safer Refactoring**: When you rename a property or change a function's signature, TypeScript can help you find all the places in your codebase that need to be updated.

4.  **Access to Modern JavaScript**: TypeScript allows you to use the latest JavaScript features and compiles them down to older versions of JavaScript that can run in a wider range of browsers.

## Setting Up a TypeScript Project

### 1. Install TypeScript
You can install the TypeScript compiler (`tsc`) globally using npm.

```bash
npm install -g typescript
```

This gives you access to the `tsc` command in your terminal.

### 2. The TypeScript Compiler (`tsc`)
Let's create a simple TypeScript file named `index.ts`. The `.ts` extension is used for TypeScript files.

**`index.ts`**
```typescript
const message: string = "Hello, TypeScript!";
console.log(message);
```

To compile this file, run the `tsc` command:
```bash
tsc index.ts
```

This will generate a new file, `index.js`, which contains the plain JavaScript version of your code.
**`index.js` (output)**
```javascript
var message = "Hello, TypeScript!";
console.log(message);
```
Notice that the type annotation (`: string`) is gone, and `const` was changed to `var` (this is configurable). You can then run this JavaScript file anywhere.

### 3. The `tsconfig.json` File
Managing a large project by compiling files one-by-one is not practical. The `tsconfig.json` file is the heart of a TypeScript project. It tells the compiler how to compile your project.

To create one, run:
```bash
tsc --init
```

This generates a `tsconfig.json` file with many options and helpful comments.

**Key `tsconfig.json` Options:**

-   `"target"`: Specifies which version of JavaScript the compiler should output (e.g., `"ES5"`, `"ES2016"`, `"ESNEXT"`).
    -   `"target": "ES5"` is a safe choice for broad browser compatibility.
-   `"module"`: Specifies the module system for the output code (e.g., `"CommonJS"`, `"ESNext"`).
-   `"rootDir"`: Specifies the root directory of your TypeScript files. Often `./src`.
-   `"outDir"`: Specifies the directory where the compiled JavaScript files should go. Often `./dist` or `./build`.
-   `"strict"`: A very important setting. When set to `true`, it enables a wide range of type-checking behaviors that result in more robust programs. **It's highly recommended to keep this on.**
-   `"noImplicitAny"`: When enabled (part of `strict` mode), it flags any variable that has an implicit `any` type. This forces you to be explicit about your types.

**Example `tsconfig.json`:**
```json
{
  "compilerOptions": {
    "target": "ES2016",
    "module": "CommonJS",
    "strict": true,
    "outDir": "./dist",
    "rootDir": "./src"
  },
  "include": ["src/**/*"] // Tells the compiler to only look in the src folder
}
```

With this `tsconfig.json` in place, you can now compile your entire project by simply running `tsc` in your project's root directory. The compiler will find all the `.ts` files in `./src`, compile them according to the rules, and place the `.js` output files in `./dist`.
