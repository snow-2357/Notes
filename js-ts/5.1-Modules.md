# 5.1 Module Systems

As applications grow, you need a way to split your code across multiple files to keep it organized and maintainable. This is where modules come in. A module is just a file that exports its code so it can be used by other files.

JavaScript has had two major module systems: **CommonJS** and **ES Modules (ESM)**.

## CommonJS (CJS)
This was the original module system used by **Node.js**. It's synchronous and designed for server-side development. You will see it in older Node.js projects and configuration files.

**Core Syntax:**
-   `require()`: A function used to import a module.
-   `module.exports`: An object that contains the values to be exported from the current module.

**Example:**

**`math.js`** (The module exporting code)
```javascript
function add(a, b) {
  return a + b;
}

function subtract(a, b) {
  return a - b;
}

// Export the functions
module.exports = {
  add,
  subtract
};
```

**`app.js`** (The module importing code)
```javascript
// Import the 'math' module
const math = require('./math.js');

const sum = math.add(10, 5);
console.log(`The sum is ${sum}`); // The sum is 15
```

## ES Modules (ESM)
This is the official, standardized module system for JavaScript, introduced in ES6. It's the modern standard and is supported by all modern browsers and recent versions of Node.js. It features an asynchronous, static syntax which allows for better optimization.

**Core Syntax:**
-   `export`: A keyword to export values from a module.
-   `import`: A keyword to import values into a module.

There are two types of exports: **named** and **default**.

### Named Exports
You can export multiple values from a single file. When importing, you must use the exact same name inside curly braces `{}`.

**Example:**

**`utils.ts`**
```typescript
export const PI = 3.14159;

export function log(message: string): void {
  console.log(message);
}
```

**`main.ts`**
```typescript
// Import the named exports
import { PI, log } from './utils.ts';

// You can also rename an import
import { PI as MyPI } from './utils.ts';

log(`The value of PI is ${PI}`);
log(`My aliased PI is ${MyPI}`);

// Or import everything as a single object
import * as utils from './utils.ts';
utils.log(`Accessing via wildcard: ${utils.PI}`);
```

### Default Export
A module can have only **one** default export. It's often used for the "main" value of a module, like a class or a primary function.

When importing a default export, you can give it any name you want.

**Example:**

**`MyClass.ts`**
```typescript
export default class MyClass {
  greet() {
    console.log("Hello from MyClass!");
  }
}
```

**`main.ts`**
```typescript
// The name `AnyNameIWant` is chosen by the importer.
import AnyNameIWant from './MyClass.ts';

const instance = new AnyNameIWant();
instance.greet();
```

## Which One to Use?

-   **ES Modules (ESM)** is the modern standard. Use it for all new browser-based and Node.js projects whenever possible. It's what TypeScript uses by default.
-   **CommonJS (CJS)** is still relevant for older Node.js codebases or for build scripts and configuration files that don't support ESM yet.

Your `tsconfig.json` file's `"module"` option controls what module system TypeScript compiles to.
-   `"module": "ESNext"` will output modern `import`/`export` syntax.
-   `"module": "CommonJS"` will convert your `import`/`export` statements into `require`/`module.exports` for compatibility with older Node.js environments.
