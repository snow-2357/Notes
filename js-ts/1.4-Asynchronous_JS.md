# 1.4 Asynchronous JavaScript

JavaScript is single-threaded, meaning it can only do one thing at a time. Asynchronous programming is a technique that allows your program to start a long-running task (like a network request or a timer) and continue to run other tasks in the meantime, rather than waiting for the long task to finish.

## The Problem: Blocking Code
Imagine requesting data from a server. If the code were synchronous (blocking), the entire program—including the user interface—would freeze until the server responded.

```javascript
// Synchronous (blocking) pseudo-code
const data = fetchDataFromServerSync(); // Program freezes here
console.log("This will only run after the data arrives.");
// The UI is unresponsive during the fetch.
```

## Basic: Callbacks (The Old Way)

The original solution to this problem was asynchronous callbacks. You pass a function (the callback) to another function, and that callback will be executed once the task is complete.

```javascript
function fetchData(callback) {
  // Simulate a network request
  setTimeout(() => {
    const data = { user: "Gemini" };
    callback(data); // Execute the callback with the data
  }, 2000);
}

console.log("Fetching data...");
fetchData(function(data) { // This is the callback function
  console.log("Data received:", data);
});
console.log("This logs immediately, without waiting!");
```

### The "Callback Hell" Problem
When you have multiple dependent asynchronous operations, you end up nesting callbacks inside callbacks, leading to code that is hard to read and maintain. This is often called "Callback Hell" or the "Pyramid of Doom".

```javascript
// Pyramid of Doom
asyncOp1(function(data1) {
  asyncOp2(data1, function(data2) {
    asyncOp3(data2, function(data3) {
      // ...and so on
    });
  });
});
```

## Intermediate: Promises (The Better Way)

ES6 introduced Promises to solve the issues of callback hell. A `Promise` is an object that represents the eventual completion (or failure) of an asynchronous operation.

A Promise can be in one of three states:
1.  **Pending**: The initial state; neither fulfilled nor rejected.
2.  **Fulfilled**: The operation completed successfully.
3.  **Rejected**: The operation failed.

You can chain `then()` and `catch()` methods to handle the results of a Promise, which flattens the pyramid of doom.

```javascript
function fetchDataWithPromise() {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      const success = true; // Simulate success or failure
      if (success) {
        const data = { user: "Gemini" };
        resolve(data); // Fulfill the promise
      } else {
        reject("Failed to fetch data!"); // Reject the promise
      }
    }, 2000);
  });
}

console.log("Fetching data...");
fetchDataWithPromise()
  .then(data => {
    // This runs if the promise is resolved
    console.log("Success:", data);
  })
  .catch(error => {
    // This runs if the promise is rejected
    console.error("Error:", error);
  })
  .finally(() => {
    // This runs regardless of success or failure
    console.log("Operation finished.");
  });
```

### Chaining Promises
You can chain multiple `.then()` blocks to handle a sequence of async operations gracefully.

```javascript
fetchUser()
  .then(user => fetchUserPosts(user.id))
  .then(posts => displayPosts(posts))
  .catch(error => console.error(error));
```

## Advanced: `async`/`await` (The Modern Way)

Introduced in ES2017, `async`/`await` is syntactic sugar built on top of Promises. It makes your asynchronous code look and behave more like synchronous code, making it much easier to read and write.

-   An `async` function always returns a Promise.
-   The `await` keyword can only be used inside an `async` function. It pauses the function execution and waits for a Promise to be resolved or rejected.

```javascript
function fetchDataWithPromise() {
  // Same function as before that returns a Promise
  return new Promise(resolve => {
    setTimeout(() => resolve({ user: "Gemini" }), 2000);
  });
}

async function displayUser() {
  try {
    console.log("Fetching data...");
    // Pause execution until the promise is resolved
    const data = await fetchDataWithPromise();
    // This line won't run for 2 seconds
    console.log("Data received:", data);
  } catch (error) {
    console.error("An error occurred:", error);
  }
}

displayUser();
console.log("This logs immediately!");
```

This `async/await` code is functionally equivalent to the `.then/.catch` example but is often considered more readable, especially for complex sequences of asynchronous steps.
