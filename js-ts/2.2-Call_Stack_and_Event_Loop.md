# 2.2 Call Stack, Memory Heap, and Event Loop

These three components are at the heart of how JavaScript executes code, manages memory, and handles asynchronous operations.

## The Core Components

### 1. The Memory Heap
This is an unstructured region of memory where the JavaScript engine stores all the objects and functions in your program. When you create a variable or an object (`const person = { name: 'G' }`), the memory required to store it is allocated on the heap.

### 2. The Call Stack
This is a data structure that keeps track of function calls in your program. It works on a **Last-In, First-Out (LIFO)** basis.
-   When you call a function, it gets added (pushed) to the top of the stack.
-   When a function finishes (returns), it gets removed (popped) from the top of the stack.
-   The code that is currently being executed is always the item at the top of the stack.

**Example:**
```javascript
function third() {
  console.log("Three");
}
function second() {
  third();
}
function first() {
  second();
}
first();
```
Execution order:
1.  `first()` is called and pushed onto the stack. `[first]`
2.  `first()` calls `second()`. `second()` is pushed onto the stack. `[first, second]`
3.  `second()` calls `third()`. `third()` is pushed onto the stack. `[first, second, third]`
4.  `third()` runs `console.log("Three")` and then returns. It's popped off the stack. `[first, second]`
5.  `second()` has nothing left to do and returns. It's popped off. `[first]`
6.  `first()` has nothing left to do and returns. It's popped off. `[]`
7.  The stack is now empty and the program is finished.

A **"Stack Overflow"** error happens when the call stack grows too large, usually due to infinite recursion.

## The Asynchronous Parts: The Event Loop Model

JavaScript is single-threaded, meaning it has only one Call Stack. How can it handle async operations without getting blocked? It uses a model involving the Call Stack, Web APIs, a Callback Queue, and the Event Loop.

### 3. Web APIs / C++ APIs
These are features provided by the runtime environment (like the browser or Node.js), not the JS engine itself. Examples include `setTimeout`, `fetch`, the DOM, and `fs` (in Node). When you call one of these async functions, the JS engine hands it off to the Web API and moves on.

### 4. The Callback Queue (or "Task Queue")
When a Web API finishes its task (e.g., a timer expires, or network data arrives), it doesn't just interrupt the JS engine. Instead, it places the **callback function** associated with that task into the Callback Queue. This is a **First-In, First-Out (FIFO)** queue.

### 5. The Event Loop
The Event Loop has one simple job: to monitor the Call Stack and the Callback Queue.
-   **If the Call Stack is empty**, the Event Loop takes the first item from the Callback Queue and pushes it onto the Call Stack for execution.
-   **If the Call Stack is not empty**, the Event Loop does nothing and just waits.

### Putting It All Together: An Example

```javascript
console.log("Start"); // 1

setTimeout(function timeoutCallback() { // 2
  console.log("Timeout Finished");
}, 2000);

console.log("End"); // 3
```

**Step-by-step execution:**
1.  `console.log("Start")` is pushed to the Call Stack, runs, and is popped off. **Output: "Start"**.
2.  `setTimeout(...)` is pushed to the Call Stack. The engine recognizes it as a Web API.
3.  The engine hands the `timeoutCallback` function and the `2000ms` delay over to the browser's Timer API. `setTimeout` is then popped off the Call Stack.
4.  `console.log("End")` is pushed to the Call Stack, runs, and is popped off. **Output: "End"**.
5.  The Call Stack is now empty. The program has finished its synchronous work.
6.  Meanwhile, the Timer API has been waiting for 2000ms. After 2 seconds, it takes `timeoutCallback` and places it in the **Callback Queue**.
7.  The **Event Loop** sees that the Call Stack is empty and there's something in the Callback Queue.
8.  The Event Loop pushes `timeoutCallback` from the queue onto the Call Stack.
9.  `timeoutCallback` runs, and `console.log("Timeout Finished")` is pushed to the stack, runs, and is popped. **Output: "Timeout Finished"**.
10. `timeoutCallback` finishes and is popped from the stack. The stack is empty again. The program is done.

### Microtasks vs. Macrotasks (Advanced)
The Callback Queue is sometimes called the "Macrotask Queue". There is another, higher-priority queue called the **"Microtask Queue"**.
-   **Microtasks**: Callbacks from Promises (`.then`, `.catch`, `.finally`) and `queueMicrotask()`.
-   **Macrotasks**: Callbacks from `setTimeout`, `setInterval`, I/O, etc.

**Rule**: The Event Loop will always process **all** tasks in the Microtask Queue completely before processing a **single** task from the Macrotask Queue.
