# 4.2 TypeScript: Types and Inference

The core feature of TypeScript is its static type system. You can explicitly annotate your code with types, and TypeScript will check them for you.

## Basic Types (Everyday Types)
These are the most common types you'll use.

-   **`string`**: `"hello"`
-   **`number`**: `42`, `3.14`
-   **`boolean`**: `true`, `false`
-   **`null`**: `null` (Represents intentional absence of a value)
-   **`undefined`**: `undefined` (Represents an uninitialized value)
-   **`any`**: A dynamic type that opts out of type checking. Use it as a last resort.
-   **`unknown`**: A safer alternative to `any`. You must perform a type check before you can use a variable of type `unknown`.
-   **`void`**: Used for functions that do not return a value.

```typescript
let myName: string = "Gemini";
let myAge: number = 1;
let isLearning: boolean = true;

let anything: any = 4;
anything = "now it's a string"; // No error

let unknownValue: unknown = 10;
// console.log(unknownValue.toFixed(2)); // Error: Object is of type 'unknown'.
if (typeof unknownValue === 'number') {
  console.log(unknownValue.toFixed(2)); // OK, we've checked the type
}
```

### Arrays
You can type arrays in two ways:
```typescript
let numbers: number[] = [1, 2, 3];
let names: Array<string> = ["Alice", "Bob"];
```

## Type Inference

In many cases, TypeScript is smart enough to **infer** the type of a variable on its own, so you don't always need to write explicit type annotations.

```typescript
// No need to write `: string`. TypeScript infers it from the value.
let greeting = "hello world";

// greeting = 123; // Error: Type 'number' is not assignable to type 'string'.
```
**Best Practice**: Use explicit type annotations when initializing a variable without a value, or for function return types and object shapes to be clear. Rely on inference for simple variable declarations.

## Creating Custom Types

As your application grows, you'll want to define your own types to represent the shape of your data. You can do this using `type` aliases or `interface`s.

### `type` Aliases
A type alias allows you to create a new name for a type. It's useful for referring to primitive types by a more descriptive name or for creating complex types like union types.

```typescript
// Alias for a primitive
type UserID = string;

// Alias for an object shape
type Point = {
  x: number;
  y: number;
};

function logPoint(p: Point) {
  console.log(`${p.x}, ${p.y}`);
}

const myPoint: Point = { x: 100, y: 200 };
logPoint(myPoint);
```

### `interface`
An interface is another way to define the shape of an object.

```typescript
interface User {
  id: number;
  name: string;
  // Optional property
  email?: string;
  // Read-only property
  readonly registrationDate: Date;
}

function printUser(user: User) {
  console.log(user.name);
  // user.registrationDate = new Date(); // Error: Cannot assign to 'registrationDate' because it is a read-only property.
}

const myUser: User = {
  id: 1,
  name: "Alex",
  registrationDate: new Date(),
};
printUser(myUser);
```

### `type` vs. `interface`

They are very similar, but have a few key differences:

| Feature                   | `interface`                                      | `type`                                     |
| ------------------------- | ------------------------------------------------ | ------------------------------------------ |
| **Purpose**               | Primarily to describe the shape of objects       | More general; can be any type              |
| **Extending**             | `extends` keyword                                | `&` (Intersection)                         |
| **Declaration Merging**   | Yes, interfaces with the same name are merged    | No, type aliases cannot be re-declared     |
| **Best for...**           | Defining the shape of objects or classes         | Union types, tuples, or utility types      |

**Declaration Merging (Interfaces Only):**
You can define an interface with the same name multiple times, and TypeScript will merge them into a single definition. This is useful for extending third-party types.

```typescript
interface Box {
  height: number;
  width: number;
}
interface Box {
  scale: number;
}
// `myBox` must have height, width, AND scale
const myBox: Box = { height: 10, width: 20, scale: 1 };
```

For most object-shaping, the choice between them is a matter of team preference. A common convention is to use `interface` for public-facing APIs and object shapes, and `type` for internal or more complex types (like unions).
