# 3.1 Prototypal Inheritance

Unlike most other object-oriented languages that use a class-based inheritance model (e.g., Java, C++), JavaScript uses a **prototypal inheritance** model. Understanding this is key to understanding how objects work in JavaScript.

## The Core Idea: Objects Inherit from Other Objects

In JavaScript, every object has a hidden internal property, `[[Prototype]]`, which is a reference (or link) to another object. That other object is called the object's **prototype**.

When you try to access a property on an object, the JavaScript engine first looks for the property on the object itself. If it doesn't find it, it then follows the `[[Prototype]]` link to the prototype object and looks for the property there. If it's still not found, it continues up the **prototype chain** until it finds the property or reaches the end of the chain.

The end of the chain is almost always the built-in `Object.prototype`, which has a `[[Prototype]]` of `null`.

## Constructor Functions (The "Old" Way of Creating Objects)

Before ES6 classes, constructor functions were the primary way to mimic classes and create objects with a shared prototype.

A constructor function is just a regular function, but it's invoked with the `new` keyword. By convention, their names start with a capital letter.

```javascript
// Define a constructor function
function Dog(name, breed) {
  // `this` refers to the new object being created
  this.name = name;
  this.breed = breed;
}

// Add a method to the Dog's prototype.
// This is efficient because all Dog instances will share this single function.
Dog.prototype.bark = function() {
  console.log(`Woof! My name is ${this.name}.`);
};

// Create instances using the `new` keyword
const dog1 = new Dog("Buddy", "Golden Retriever");
const dog2 = new Dog("Lucy", "Poodle");

dog1.bark(); // "Woof! My name is Buddy."
dog2.bark(); // "Woof! My name is Lucy."
```

### What `new` Does:
1.  **Creates a new, empty object** (`{}`).
2.  **Links the new object's `[[Prototype]]`** to the constructor function's `prototype` property (e.g., `dog1`'s prototype is linked to `Dog.prototype`).
3.  **Binds `this`** to the new object and executes the constructor function's code.
4.  **Returns the new object** implicitly (unless the constructor explicitly returns another object).

## The Prototype Chain in Action

Let's look at `dog1` from the example above.
1.  We call `dog1.bark()`.
2.  The engine checks if `dog1` has its own property called `bark`. It does not.
3.  The engine follows the `[[Prototype]]` link from `dog1` to `Dog.prototype`.
4.  The engine checks if `Dog.prototype` has a property called `bark`. It does!
5.  The engine calls the `bark` function with `this` set to `dog1`.

You can inspect the prototype chain using `Object.getPrototypeOf()`:
```javascript
console.log(Object.getPrototypeOf(dog1) === Dog.prototype); // true
console.log(Object.getPrototypeOf(Dog.prototype) === Object.prototype); // true
console.log(Object.getPrototypeOf(Object.prototype)); // null (end of the chain)
```

## Why Use Prototypes?

The main benefit is **memory efficiency**. Instead of creating a separate `bark` function for every single dog object we create, we define it just once on the `Dog.prototype`. All `Dog` instances then share that same function through the prototype chain. For thousands of objects, this saves a significant amount of memory.

While ES6 classes provide a much cleaner syntax, they are essentially "syntactic sugar" over this same prototypal inheritance mechanism. Understanding prototypes helps you understand what's happening under the hood.
