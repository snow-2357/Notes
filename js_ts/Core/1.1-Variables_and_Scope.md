# 1.1 Variables and Scope

Understanding how variables are declared and where they are accessible (scope) is a fundamental concept in JavaScript.

## The Three Declarations: `var`, `let`, and `const`

### Basic: `var` (The Old Way)
Before ES6 (2015), `var` was the only way to declare a variable. It is **function-scoped**.

```javascript
function myFunction() {
  var myName = "Hello";
  console.log(myName); // "Hello"
}
// console.log(myName); // ReferenceError: myName is not defined
```

**Pitfall**: `var` can be re-declared and updated, which can lead to bugs. It also "leaks" into the global scope if declared outside a function.

```javascript
var x = 10;
var x = 20; // No error, x is now 20.
console.log(x);
```

### Advanced: `let` and `const` (The Modern Way)
ES6 introduced `let` and `const`, which are **block-scoped**. A block is any code within curly braces `{}` (e.g., in an `if` statement, `for` loop, or just standalone braces).

- **`let`**: Can be updated, but not re-declared within the same scope.
- **`const`**: Cannot be updated or re-declared. It must be initialized at the time of declaration.

```javascript
let y = 10;
// let y = 20; // SyntaxError: 'y' has already been declared
y = 30; // This is fine
console.log(y); // 30

const z = 100;
// z = 200; // TypeError: Assignment to constant variable.
```

**Important Note on `const` with Objects/Arrays**: While you cannot re-assign a `const` variable, you can mutate the properties of an object or the elements of an array it holds.

```javascript
const user = { name: "Alex" };
user.name = "Sam"; // This is allowed
console.log(user.name); // "Sam"

// user = { name: "John" }; // TypeError: Assignment to constant variable.
```

## Scope: Where Variables Live

Scope determines the accessibility of variables.

1.  **Global Scope**: Variables declared outside any function or block. They are accessible from anywhere in your code. It's best practice to minimize global variables.
2.  **Function Scope**: Variables declared with `var` are accessible only within the function they are created in.
3.  **Block Scope**: Variables declared with `let` and `const` are accessible only within the block (`{...}`) they are created in.

```javascript
var globalVar = "I am global";

function scopeTest() {
  var functionVar = "I am in a function";
  if (true) {
    let blockVar = "I am in a block";
    console.log(blockVar);     // "I am in a block"
    console.log(functionVar); // "I am in a function"
  }
  // console.log(blockVar); // ReferenceError: blockVar is not defined
}
scopeTest();
console.log(globalVar); // "I am global"
```

## Hoisting: "Lifting" Declarations

Hoisting is JavaScript's default behavior of moving declarations to the top of their current scope before code execution.

### `var` Hoisting
- `var` declarations are hoisted and initialized with `undefined`.

```javascript
console.log(myVar); // undefined (No error!)
var myVar = 5;
console.log(myVar); // 5
```
Behind the scenes, the engine processes this as:
```javascript
var myVar; // Declaration hoisted and initialized to undefined
console.log(myVar);
myVar = 5; // Assignment happens here
console.log(myVar);
```

### `let` and `const` Hoisting (The Temporal Dead Zone)
- `let` and `const` declarations are also hoisted, but they are **not** initialized.
- Accessing them before the line where they are declared results in a `ReferenceError`.
- The period from the start of the block until the declaration is encountered is called the **Temporal Dead Zone (TDZ)**.

```javascript
// Start of TDZ for myLet
// console.log(myLet); // ReferenceError: Cannot access 'myLet' before initialization

let myLet = 10; // End of TDZ for myLet
console.log(myLet); // 10
```

This behavior encourages better coding practices by forcing you to declare variables before you use them.
